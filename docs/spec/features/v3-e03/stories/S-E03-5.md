## 2. Décisions tranchées (→ `ADR-075`)

`ADR-075` est **justifié et obligatoire** : deux vraies décisions sont prises ici. Le numéro a été vérifié —
`docs/adr/` s'arrête à `ADR-074`, et aucune PR ouverte (six, toutes `dependabot/*`, mesuré le 2026-08-26 via
`gh pr list --state open`) n'en réclame un.

### D1 — AC-2 : c'est **(b)**, un endpoint dédié qui rend des lignes `Guardianship`

**Rejeté : (a) aplatir `guardianships[]`.** Ce n'est pas un arbitrage de coût, c'est un constat de mesure :
**(a) ne peut pas satisfaire `G-TRUTH`**, qui est la porte que cette tranche déclenche.

1. `GET /guardians` filtre déjà la relation par `guardianshipOnTheBooksWhere()`
   (`guardians.controller.ts:126`, `= { status: { in: ['pending','active'] } }`, posé par `S-E03-3c`). Les
   liens **révoqués sont exclus par le serveur**. L'onglet « Rejetées » resterait donc **structurellement
   vide après le fix** — on aurait déplacé `DNC-06` d'un onglet sur cinq au lieu de le retirer. C'est
   exactement la forme que `PF-372` enregistre déjà pour la tuile « Rattachements révoqués » de
   `admin/guardians`.
2. Le plafond de 200 **guardians** ne borne pas le nombre de demandes, et le comptage resterait client. Le
   KPI (un `count` serveur) et la file (un `.length` d'une page tronquée) **ne peuvent pas s'accorder par
   construction** — or `G-TRUTH` exige que le même fixture donne la MÊME valeur des deux côtés.
3. `page.tsx:145`/`:249` lisent `r.student.enrollments?.[0]?.classSection.name` ; l'`include` de la relation
   (`:127`) ne sélectionne que `{ id, firstName, lastName }`. La colonne « Classe souhaitée » resterait `—`.

**Retenu : (b).** Un endpoint dédié `GET /api/v1/guardians/guardianships/pending-requests` rend des lignes
`Guardianship` **et les totaux par onglet calculés côté serveur**. Le changement de forme de réponse est
assumé, et c'est le prix de la seule voie qui rend `G-TRUTH` démontrable.

### D2 — AC-5 : la portée est **l'ÉCOLE**, via `student.schoolId`

Le KPI et la file sont scopés `{ tenantId, student: { schoolId } }`, **la même portée des deux côtés**.

*Pourquoi école plutôt que tenant :* `adminDashboard({ tenantId, schoolId })` est un tableau de bord **par
école** ; ses six autres KPI le sont ; un admin dont le contexte est l'école A ne doit pas se voir annoncer
les demandes de l'école B, puis atterrir sur une file qui ne les contient pas — ce serait le défaut de
`PF-20` **reconstruit par le fix**.

*Pourquoi `student.schoolId` plutôt que `guardian.schoolId` :* les deux existent
(`schema.prisma:491` / `:543`), et il fallait trancher. La décision d'accepter un rattachement appartient à
l'école **où l'enfant est scolarisé** ; `Student.schoolId` est aussi l'axe que tous les autres KPI admin
emploient (`student.count({ tenantId, schoolId, … })`, `:2466`). `Guardian.schoolId` est posé depuis le
contexte de l'admin créateur (`guardians.controller.ts:162`) et peut donc diverger pour un parent dont les
enfants relèvent de deux écoles. **L'axe élève est l'invariant ; l'axe parent est un artefact de saisie.**

*Conséquence assumée et à écrire dans l'ADR :* le KPI « Demandes en attente » **change de valeur** pour tout
tenant multi-écoles. Il devient plus petit et **plus vrai**. C'est le sens même de la tranche.

## 3. Critères d'acceptation

### AC-1 — LE CŒUR : une seule dérivation déclarée, dans le module existant

Dans **`packages/contracts/src/guardianship/link-liveness.ts`** (le fichier existant — **ne pas créer un
cinquième module frère**, cf. `PF-365`/`PF-370`), ajouter une **troisième portée nommée**, en suivant
exactement les conventions du fichier (`§2.1`…`§2.6`) :

```ts
/* §2.7 — EN ATTENTE D'UNE DÉCISION ADMIN */

/** Liste POSITIVE, comme `LIVE` : un état ajouté plus tard ne doit pas
 *  entrer dans une file de décision par le seul fait d'exister. */
export const GUARDIANSHIP_AWAITING_DECISION_STATUSES:
  readonly GuardianshipLinkStatus[] = ['pending'] as const;

/** Le pendant `where` — structurel, sans dépendance Prisma (GUARDRAILS §2). */
export function guardianshipAwaitingDecisionWhere(): GuardianshipStatusFilter;

/** Le pendant EN MÉMOIRE — §2.5 : « un where corrigé côté base doit l'être
 *  aussi en mémoire ». */
export function isGuardianshipAwaitingDecision(row: GuardianshipLivenessRow): boolean;

/** LA portée complète d'UNE demande de rattachement en attente : tenant +
 *  école + statut, en UN SEUL appel, pour qu'aucun site ne puisse en épeler
 *  la moitié. C'est ce qui rend AC-5 mécanique plutôt que déclaratif. */
export interface GuardianshipPendingRequestScope {
  readonly tenantId: string;
  readonly schoolId: string;

export function guardianshipPendingRequestWhere(
  scope: GuardianshipPendingRequestScope,
): {
  readonly tenantId: string;
  readonly student: { schoolId: string };
  readonly status: { in: GuardianshipLinkStatus[] };

/** L'étiquette de portée, à côté des trois existantes (§2.6). */
GUARDIANSHIP_SCOPE_LABEL.awaitingDecision =
  'Demandes de rattachement en attente de décision (école)';
```

**Contraintes de forme, non négociables :**
- `tenantId` et `schoolId` sont **requis** dans `GuardianshipPendingRequestScope`. **Jamais**
  `...(schoolId ? { … } : {})` — `ADR-065 §D5` : Prisma laisse tomber une clé `undefined` et la requête
  **s'élargit** silencieusement. Un `schoolId` manquant doit être un `TS2345`, pas une fuite.
- Les constructeurs **copient** (`[...CONST]`) : les constantes restent `readonly`, le `where` rendu est
  frais et mutable (raison exposée au `§2.4` du fichier — `EnumGuardianshipStatusFilter.in` est mutable).
- Aucun `import '@prisma/client'` (un test du cliquet existant l'assied déjà).
- Le docblock du fichier gagne une section expliquant que `awaitingDecision` **n'est pas** un sous-cas de
  `live` ni de `onTheBooks` : c'est la question *« qu'est-ce qui attend un humain ? »*, la troisième
  question posée à la même colonne. Citer `PF-373` et sa direction de correction.

**Backend.** Nouvelle route dans `apps/api/src/modules/guardians/guardians.controller.ts`, à côté des routes

- `select` : `{ id, status, relationship, notes, createdAt, guardian: { id, firstName, lastName, email, phone },

- Pagination **serveur** : `?page` / `?pageSize` (défaut 10, plafond 100), plus **`total`** — un `count`
  serveur sur le **même `where`**, pas un `data.length`.
- La réponse porte `guardianshipScope: GUARDIANSHIP_SCOPE_LABEL.awaitingDecision` (convention `ADR-074 §2.6` :

**Frontend.** `apps/web/src/app/admin/enrollments/page.tsx` consomme cette route.

## 3. Les décisions, tranchées ici — `ADR-090` les argumente

### D1 — Le champ nouveau s'appelle `activeAcademicYear`, et l'ancien SURVIT

`activeAcademicYearId` **n'est pas remplacé**. Deux raisons, et la seconde est la plus forte :

1. 45 sites le lisent comme filtre et 3 pages web le typent. Le remplacer ferait de cette tranche un diff
   transverse de 48 sites, donc Tier A, donc non prouvable en un run.
2. **La révertibilité.** Un diff purement additif se révoque en une commande (`git revert`) sans laisser
   d'appelant orphelin. C'est ce qui autorise Tier B.

Le nom `activeAcademicYear` (sans suffixe) est délibéré : il se lit comme « l'année », l'autre comme « l'id de
l'année ». Aucun des deux ne peut être pris pour l'autre à la relecture.

### D2 — La forme transportée est un **DTO de fil**, pas le type domaine

`ResolvedAcademicYear` porte `startDate: Date` / `endDate: Date`. Sérialisé par Nest, un `Date` devient une
**chaîne ISO**. Rendre `ResolvedAcademicYear` tel quel donnerait un type TypeScript qui **ment sur le fil** —
`DNC-06` posé de nos propres mains.

On introduit donc, dans `packages/contracts/src/academic-year/academic-year-scope.ts` :

```ts
/** La PORTÉE d'année telle qu'elle voyage sur le fil : dates en ISO 8601, jamais en `Date`. */
export interface AcademicYearScope {
  id: string;
  name: string;
  /** ISO 8601 — `Date.prototype.toISOString()`. Le type est EXACTEMENT ce que JSON produit. */
  startDate: string;
  endDate: string;
  status: string;
  viaFallback: boolean;
  containsReferenceDate: boolean;
  isStale: boolean;
  staleByDays: number;
  activeCount: number;
}

/** Mapper PUR. Aucune horloge : `referenceDate` a déjà été appliquée par le résolveur. */
export function toAcademicYearScope(resolved: ResolvedAcademicYear): AcademicYearScope { … }
```

⚠ **`hermetic-spec-writers-gate` s'applique à ce dossier** : **aucun** `new Date(`, **aucun** `Date.now(` dans
`packages/contracts/src/academic-year/`. `toISOString()` est autorisé et suffit. Attention aussi au piège du run
80 : une assertion `not.toContain('new Date(')` sur la source brute matche **le commentaire qui promet qu'il n'y
a pas d'horloge**. Ne pas réécrire cette assertion-là.

`schoolId` n'est **pas** transporté : la réponse le porte déjà ailleurs, et le dupliquer créerait deux endroits où
lire la même chose — le défaut même que V3-E03 démonte.

### D3 — Le mapping se fait **UNE fois**, dans `SchoolContextService`, pas dans les cinq contrôleurs

`forTenant` / `forUser` rendent directement `activeAcademicYear: AcademicYearScope | null`. Les cinq contrôleurs
font un **passe-plat** (`activeAcademicYear,` en abrégé d'objet) et rien d'autre.

Si le mapping vivait dans les contrôleurs, le cliquet devrait vérifier un *appel de fonction* au lieu d'une
*présence de clé* — et `PF-483` (run 105) établit précisément qu'un `where`/argument derrière un appel devient
invisible au marcheur. Une règle de FORME sur une clé est robuste ; une règle sur un appel ne l'est pas.

### D4 — `packages/ui` **ne gagne aucune dépendance**

`packages/ui/package.json` ne dépend pas de `@pilotage/contracts` et **ne doit pas commencer** (ce serait une
décision d'architecture nouvelle, donc un ADR séparé, donc hors tranche). Le badge déclare donc sa **propre
interface de props structurelle**, compatible par structure avec `AcademicYearScope` — exactement le patron déjà
en place pour `EnrollmentStatusBadge` (`EnrollmentActivityState` y est déclaré localement). Le compilateur vérifie
la compatibilité au site d'appel dans `apps/web`, qui, lui, dépend des deux paquets.

### D5 — ⛔ **INTERDICTION ABSOLUE : ne jamais SÉLECTIONNER sur `containsReferenceDate` ni sur `isStale`**

Sur les données mesurées en `§1.2`, **0 des 2 années actives ne contient aujourd'hui**. Un filtre, un tri, un
`?? fallback` ou un `if (!isStale)` quelque part sur ce chemin **viderait les quatre portails**. Ce n'est pas une
précaution : c'est le résultat mesuré au run 80, re-mesuré au run 101, re-mesuré aujourd'hui.

`ADR-070` porte déjà la règle ; `ADR-090` la ré-affirme comme **règle de PRODUIT** : *le containment est une
propriété RAPPORTÉE. Il ne devient un critère de sélection que le jour où quelqu'un tranche ce que « active »
signifie pour une année terminée — c'est `PF-484`, et ce n'est pas une tranche de vérité.*

### D6 — Aucun `WARN` par requête dans `SchoolContextService`

Ce service tourne sur quasiment chaque requête authentifiée. Le commentaire actuel du service le dit déjà et il a
raison : un `logger.warn` par requête serait du bruit qui noierait les deux signaux basse fréquence existants. Le
signal humain, dans cette tranche, est **le badge**, pas un journal de plus.

### D7 — `G-MIGRATION` non déclenché, et c'est le cœur du design

Aucune modification de `schema.prisma`, aucune migration, aucun SQL. C'est ce qui rend la tranche révertible en
une commande et ce qui la maintient en Tier B. Toute pulsion d'ajouter une contrainte de containment est
`PF-484` et doit être **écrite au registre, pas codée**.

## 7. `AC-4` — le cliquet : `apps/api/src/shared/quality/academic-year-scope-emission-gate.spec.ts`

### 7.1 Le corpus, DÉRIVÉ

Marcher `apps/api/src` et retenir **tout fichier dont le nom se termine par `.controller.ts`** — dérivé du nom,
pas d'une liste. Mesuré le 2026-08-30 : **41** fichiers. Exclure `.spec.ts`, `.d.ts`, `node_modules`, `dist`,
`.next` et `__fixtures__` (les fixtures portent des sources délibérément contrevenantes ; les juger produirait un
auto-rouge qu'on « corrigerait » par une exclusion, donc une allowlist déguisée).

**Plancher de MARCHE** (« la marche a bien regardé l'arbre »), et **jamais** un plancher de contravention :
`MIN_CONTROLLER_FILES = 30`. Il ne suit aucune classe que la feuille de route fait rétrécir.

### 7.2 Pourquoi le corpus est **les contrôleurs**, et pas tout `apps/`

`packages/imports-core/src/caches.ts:174` place lui aussi `activeAcademicYearId` dans un objet retourné. Ce n'est
**pas** une réponse HTTP : c'est le cache du chemin d'**ÉCRITURE** de l'import, où la valeur est persistée dans
les `class_section` / `enrollment` créés (`imports.processor.ts:202`). Lui exiger un objet de portée serait
absurde et produirait un faux rouge qu'on « corrigerait » par une exception.

La discrimination est donc **structurelle et dérivée** — suffixe de fichier **+ décorateur de méthode** — jamais
une allowlist. Elle est enregistrée en `PF-486`.

### 7.3 Le classifieur — tous les noms INJECTÉS

Parser avec `typescript` (`require('typescript')`, non gardé, exprès — `DNC-08` : si l'outil s'évapore, la suite
doit mourir au CHARGEMENT plutôt que dégénérer en « rien à vérifier »).

```ts
const NAMES = {
  idField: 'activeAcademicYearId',
  scopeField: 'activeAcademicYear',
} as const;

const HTTP_DECORATORS = new Set(['Get','Post','Put','Patch','Delete','Head','Options','All']);
```

Pour chaque fichier du corpus :

1. Trouver les **méthodes de classe** portant au moins un décorateur dont le nom est dans `HTTP_DECORATORS`.
2. Dans le corps de chaque méthode, visiter tous les `ReturnStatement`.
3. Pour chaque `return`, calculer l'ensemble des **clés de premier niveau** de l'objet rendu, en **SUIVANT** :
   - les `ObjectLiteralExpression` (propriétés nommées **et** abrégées),
   - les `SpreadAssignment` **dont l'expression est elle-même un littéral d'objet** (un spread d'identifiant
     comme `...cycle` apporte des clés inconnues : on ne les invente pas, on les ignore),
   - les `ConditionalExpression` (les **deux** branches),
   - les `ParenthesizedExpression`,
   - profondeur bornée à 6.
4. **Violation** ⇔ l'ensemble contient `idField` **et pas** `scopeField`.

⚠ Le suivi des spreads et des ternaires n'est pas cosmétique : le site 3
(`return { ...cycle, activeAcademicYearId };`) est **littéralement un spread**, et `S-E03-13` a déjà été trompé
par un spread conditionnel. Un classifieur qui ne lirait que les propriétés écrites en clair passerait à côté du
site que ce cliquet existe pour attraper — **et sortirait vert**.

### 7.4 La règle : **TOLÉRANCE ZÉRO**

L'ensemble des violations doit être **VIDE**. Pas de plafond décroissant : contrairement au cas `R2` de
`assignment-year-axis-derivation-gate`, aucun site ici n'est un mur d'autorisation, aucun ne demande de décision
sémantique. Les cinq se convertissent en une ligne chacun. Un plafond serait un confort, pas une prudence.

Le message d'échec **NOMME chaque site** (`fichier:ligne — méthode`) et rappelle le remède en une phrase.

### 7.5 Anti-vacuité — par FIXTURES, jamais par comptage

Sous `apps/api/src/shared/quality/__fixtures__/academic-year-scope-emission/` :

| fixture | ce que le classifieur doit dire | ce que ça prouve |
|---|---|---|
| `offending.controller.ts.txt` — méthode `@Get()` rendant `{ activeAcademicYearId }` | **VIOLATION** | le classifieur voit encore une contravention en clair |
| `offending-spread.controller.ts.txt` — `@Get()` rendant `{ ...base, activeAcademicYearId }` | **VIOLATION** | le suivi de spread est vivant (c'est la forme du site 3) |
| `offending-ternary.controller.ts.txt` — `@Get()` rendant `cond ? { activeAcademicYearId } : { other: 1 }` | **VIOLATION** | les deux branches sont visitées |
| `compliant.controller.ts.txt` — `@Get()` rendant `{ activeAcademicYearId, activeAcademicYear }` | **conforme** | le cliquet n'est pas un refus universel |
| `non-http.controller.ts.txt` — méthode **sans** décorateur HTTP rendant `{ activeAcademicYearId }` | **conforme** | la discrimination par décorateur fonctionne (c'est ce qui protège `imports-core`) |

Ces fixtures sont passées **directement au classifieur** (appel de fonction), pas via la marche de production —
la marche les exclut, et c'est délibéré. Extension `.txt` pour qu'aucun runner ni aucun typecheck ne les compile.

### 7.6 Ce que ce cliquet NE prouve PAS

Il prouve une **FORME dans les sources** : « aucune réponse HTTP n'émet l'id sans la portée ». Il ne prouve pas
que la valeur **arrive** au navigateur — c'est `AC-6`, la sonde live. Il ne prouve pas non plus que le badge est
**rendu** — c'est `AC-3`, la revue de diff. **Trois affirmations, trois mécanismes ; les confondre serait
`DNC-06`.**

## 10. Ce qui ferait échouer cette tranche

1. **Recopier « quatre » ou « cinq »** au lieu de lire la liste imprimée par le cliquet. C'est l'échec exact que

5. **Ajouter `@pilotage/contracts` aux dépendances de `packages/ui`.** Décision d'architecture ⇒ ADR séparé

   `api` sans `migrator` est un piège (`PF-479`).

8. **Toucher `schema.prisma`, une migration, ou un gate.** Le premier casse `D7`, le second est l'interdit

9. **Faire recalculer la vétusté au badge** en lui passant `endDate`. Le calcul migrerait dans `packages/ui`,
   hors des racines de marche du cliquet — pire que le bug d'origine.
10. **Prétendre `G-PORTAL` 4/4.** C'est 2/4, et le dire est une exigence, pas une excuse.

## 2. The design, and the four constraints it is shaped by

### 2.1 The fix is **not** to reorder the substring cascade — Constraint (i)

Keycloak genuinely **cannot** distinguish a wrong password from a wrong or missing TOTP in the ROPC grant: both answer `Invalid user credentials`. Reordering the four `includes()` tests would move the lie, not remove it.

Therefore that case must classify as **rejected-and-ambiguous**, and the UI must not assert MFA. **The ambiguity is encoded in the union member's own name** so that no later reader mistakes it for certainty:

```ts
'credentials-or-otp-rejected'
```

Not `'invalid_credentials'` (asserts the password was wrong). Not `'otp_required'` (asserts an MFA fact). The name carries the epistemics.

### 2.2 One declaration, in the module that already owns this shape

`packages/contracts/src/security/` already holds `csp.ts`, `csv-injection.ts` and `branding-css.ts` — pure, import-free, security-relevant, shared across all three runtimes, unit-tested from `apps/api`. `csv-injection.ts:23-31` states the address rule explicitly and it applies verbatim here.

Two new files, one concern each (the one-concern-per-file precedent of that directory):

- `packages/contracts/src/security/direct-grant-failure.ts`
- `packages/contracts/src/security/mfa-enrolment-policy.ts`

Both must import **nothing** — not zod, not `node:*`, not another contracts module. They run in a browser bundle (`apps/web/src/auth.ts` reaches the edge/server boundary), in a Node API process, and inside a `require()`-based gate. Both must declare **no class and no `instanceof`**: `packages/contracts` ships CJS (`main → dist/index.js`, `dist/` git-ignored), so a spec resolving `src/` and a runtime resolving `dist/` hold two different module objects. Plain functions returning plain object literals cannot disagree with themselves across that seam; a class would.

### 2.3 The export surface must reach `dist` — Constraint (iii)

`packages/contracts/package.json` resolves `types → ./src/index.ts` but `default → ./dist/index.js`. `apps/web` imports contract **values**. ## 3. The premise this slice ships on, stated as a premise — **P-1**

> **P-1.** In the Keycloak ROPC (direct access) grant, `error_description: 'Account is not fully set up'` is returned **only after the supplied password has been validated**. A caller who has *not* proven the credential receives `'Invalid user credentials'` instead.

**Why it is believed.** `register.controller.ts:241` is an in-repo comment asserting exactly this ordering, written by an author who was working against a running realm, and the registration flow's design (`requiredActions: []` at `register.controller.ts:255`, chosen *because* pending actions break ROPC) already **depends** on it.

**Why it matters.** P-1 is the whole information-disclosure argument for §4.4's `account-setup-pending` copy. If P-1 is true, the new message is disclosed only to someone who already holds the correct password — a materially different bar from an unauthenticated oracle. If P-1 is **false**, `account-setup-pending` becomes an account-existence oracle.

**P-1 is UNVERIFIED and is recorded as `PF-444`.** Its discharge is the probe step of §4.7, which ships not-executed. **Contingency, pre-decided so nobody has to re-litigate it under pressure:** if the probe falsifies P-1, the remedy is **one line in `PortalLoginForm.tsx`** — render `account-setup-pending` with the same copy as `credentials-or-otp-rejected`. The classifier keeps the distinction (it is still the right thing for a server-side log); only the *rendered* string collapses. Nothing about the union, the contract, the ratchet or `/me` changes.

This is an **autonomous decision, documented rather than escalated** (`feedback_autonomous_decisions`): ship the fix with a named premise and a one-line rollback, rather than block a `BROKEN_RUNTIME` L0 finding behind a container that has refused to start seven runs running.

## 4. Functional requirements

### 4.1 `packages/contracts/src/security/direct-grant-failure.ts` (new)

Input is the **observable response**, nothing else. Output is a **closed union**.

```ts
export type DirectGrantFailureCode =
  | 'credentials-or-otp-rejected'
  | 'account-setup-pending'
  | 'unclassified';

export const DIRECT_GRANT_FAILURE_CODES: readonly DirectGrantFailureCode[] = [
  'credentials-or-otp-rejected',
  'account-setup-pending',
  'unclassified',
];

export interface DirectGrantFailureInput {
  status: number;
  error?: string | null;
  errorDescription?: string | null;
}

export function classifyDirectGrantFailure(
  input: DirectGrantFailureInput,
): DirectGrantFailureCode;
```

Rules, in this order, and **each anchored on a measured string, never on a needle**:

1. `errorDescription` normalised (trim + lowercase) **equals or contains** `account is not fully set up` → `'account-setup-pending'`.
2. `status === 401` **or** `error === 'invalid_grant'` → `'credentials-or-otp-rejected'`.
3. otherwise → `'unclassified'`.

Rule 1 must be an **exact anchored phrase**, not a needle set. The whole defect being closed is what happens when a classifier matches on a fragment (`credential`) that a *different* message legitimately contains. A single full phrase measured from Keycloak cannot collide the way four four-to-twelve-character fragments did.

Carry the fixture strings in the module with a **provenance comment naming where each was measured**:

```ts
/**
 * MEASURED STRINGS — provenance, not folklore.
 *
 * 'Invalid user credentials'
 *   MEASURED 2026-08-15 (run 63) against a Keycloak 26.0 container importing
 *   infra/keycloak/realm-export.json. Recorded verbatim at
 *   docs/daily-improvement-v3/traceability/CLOSED-L0.md:123, candidate A.
 *
 * 'Account is not fully set up'
 *   NOT independently measured by this routine. Sourced from
 *   apps/api/src/modules/identity/register.controller.ts:241, an in-repo
 *   comment that the registration flow's own design depends on. Its live
 *   read-back is STEP 6 of scripts/keycloak-live-probe.js, which ships
 *   NOT EXECUTED (Docker down, 7th consecutive run). See S-E05-8 §3 / PF-444.

```

**The docblock must not promise more than the runtime delivers (G-DNC / DNC-06).** It must say, in words: *this function cannot tell a wrong password from a wrong OTP, because Keycloak does not tell it.*

### 4.9 Unit spec — `apps/api/src/shared/quality/direct-grant-failure.spec.ts` (new)

Beside its gate, following the `calendar-window.spec.ts` / `calendar-window-derivation-gate.spec.ts` pairing precedent. Drives `classifyDirectGrantFailure` and `mfaRequiredByInvitePolicy` from `@pilotage/contracts` (jest maps to source, so no build is needed for this file).

Cases, at minimum:

1. `{status: 401, error: 'invalid_grant', errorDescription: 'Invalid user credentials'}` → `credentials-or-otp-rejected`. **This is the regression case for (a)(1)** and must carry a comment saying so.
2. Same, upper/mixed case and with surrounding whitespace → same code. (The classifier normalises; it does not depend on Keycloak's casing.)
3. `{status: 400, error: 'invalid_grant', errorDescription: 'Account is not fully set up'}` → `account-setup-pending`. **Regression case for (a)(2).**
4. The same description at `status: 401` → still `account-setup-pending` (rule 1 precedes rule 2 deliberately, and *that* ordering is safe because rule 1 is a full anchored phrase).
5. `{status: 503, error: undefined, errorDescription: undefined}` → `unclassified`. A gateway failure is not a credential verdict.
6. `{status: 400, error: 'invalid_client'}` → `unclassified`. A misconfigured client secret must never be shown to a user as « mot de passe incorrect ».
7. `errorDescription: null` and `errorDescription: ''` at `401` → `credentials-or-otp-rejected` (never a crash, never `unclassified`).
8. **The anti-regression case that names the defect:** a description containing the bare word `credential` but *not* the anchored phrase, at `status: 200`-shaped input, must **not** yield an MFA-flavoured code — there is no MFA-flavoured code to yield. Assert `DIRECT_GRANT_FAILURE_CODES` contains no member whose name asserts MFA.
9. `mfaRequiredByInvitePolicy`: `['school_admin']` → true; `['teacher']` → true; `['parent']` → false; `['student']` → false; `[]` → false; `['parent','teacher']` → true; unknown role → false.
10. **Purity:** both modules' source text contains no `import` statement, no `require(`, no `process.env`, no `node:` specifier — the `portal-landing-gate.spec.ts:287-290` assertion shape.

## 1. Why — the defect, reproduced

### 1.1 The sequence

`apps/web/src/components/PortalLoginForm.tsx:76`

```ts
const callbackUrl = params.get('callbackUrl') ?? DEFAULT_LANDING[accent];
```

read straight off the query string, with **no same-origin validation**, and `:125`

```ts
// Success — NextAuth set the session cookie. Navigate.
router.push(callbackUrl);
```

Next's App Router performs a hard `window.location` navigation when the href is cross-origin. So
`/parent/login?callbackUrl=https://evil.example/`:

1. serves the **genuine** login page, on the genuine origin, with the genuine TLS certificate;
2. authenticates the parent **for real** — the next-auth session cookie **is** set, so nothing looks wrong;
3. then lands them on `https://evil.example/`, which is free to render a pixel-perfect "session expired, sign in
   again" page.

That is the maximally convincing phishing sequence, and this platform's users are **parents of minors**. `L0`,
`BROKEN_SECURITY`, `P1`.

### 1.2 Scope, measured — the SSO branch is NOT affected, and must not be "fixed"

Only the **credentials** branch is defective.

* The SSO branch (`:136`, `signIn(\`keycloak-${accent}\`, { callbackUrl }, { prompt: 'login' })`) is covered by
  next-auth's **default** same-origin redirect guard. Verified, not assumed:
  `grep -n "async redirect" apps/web/src/auth.ts` → **no match**; `auth.ts:292` declares
  `callbacks: { jwt, session, … }` with no `redirect` override.
* **Do not add a `redirect` callback to `auth.ts`.** Overriding it is how that default guard gets weakened. The SSO
  branch is left alone; it merely benefits, because after this slice the `callbackUrl` it receives is already
  path-only.

### 1.3 The emission side is already safe

`apps/web/src/middleware.ts:158`

```ts
url.searchParams.set('callbackUrl', pathname);
```

`pathname` is `req.nextUrl.pathname` — server-derived, never a request query parameter. The defect is **entirely on
the consumption side**. `apps/api/src/shared/quality/portal-landing-gate.spec.ts:362-371` already pins the
middleware's *authed bounce target*; what it does **not** pin — and what `PF-102` is — is what the login form does
with the parameter the middleware emitted. AC-5(e) closes that asymmetry.

### 1.4 One component, four portals (G-PORTAL)

`PortalLoginForm` is shared. Verified:

```
grep -l "PortalLoginForm" apps/web/src/app/*/login/page.tsx
  apps/web/src/app/admin/login/page.tsx
  apps/web/src/app/parent/login/page.tsx
  apps/web/src/app/student/login/page.tsx
  apps/web/src/app/teacher/login/page.tsx
```

Four routes, one component, one defect, one fix. G-PORTAL is satisfied **by construction** — but it must be
*asserted*, because "one shared component" is a claim about the tree that a fifth login page could falsify next week.

## 3. The validator — design decisions, stated and justified

### 3.1 Decision D1 — allow-list, and **no normalisation at all**

AC-2 asks the implementer to "decide deliberately whether to trim-then-check or reject-if-not-exactly-`/`-first and
SAY WHY in a comment". **The decision is: reject-if-not-exactly-`/`-first. Never trim, never lowercase, never
decode, never `new URL()`.**

Why, and it is not a style preference:

* Trimming means **reimplementing the browser's stripping rules**, and getting them exactly right, forever. The
  WHATWG URL parser removes leading *and* trailing C0-control-or-space, and additionally removes ASCII tab, LF and CR
  from **anywhere** in the string. It does **not** strip U+00A0, U+2028, or U+FEFF. Any divergence between our trim
  set and the browser's is, by definition, an exploit: we validate one string and the browser navigates to a
  different one.
* Decoding (`decodeURIComponent`) would turn `%2F%2Fevil.example` — which resolves same-origin, measured — into
  `//evil.example`, which does not. Decoding creates the vulnerability it looks like it prevents.
* `new URL(raw, base)` requires choosing a `base`, and on the client the only honest base is `window.location`, which
  makes the validator un-unit-testable and non-edge-safe. The whole point of a pure module is that a spec can drive
  it with no DOM.

So: the raw string is judged **exactly as received**, and anything not unambiguously path-only is refused.

### 3.2 Decision D2 — **the rule as briefed is exploitable; this is the correction** ⚠️

> **This is a corrected premise, and a corrected premise is a RESULT, not a failure.** It was found by executing the
> briefed rule against the real URL parser rather than reading it.

AC-2 and `audit-findings-index.md:149` both propose:

```ts
raw.startsWith('/') && raw[1] !== '/' && raw[1] !== '\\'
```

**That rule accepts three inputs that navigate off-origin.** Executed against Node's WHATWG `URL` with base
`https://pilotage.example/parent/login`:

| input | resolves to | briefed rule | verdict |
|---|---|---|---|
| `"/\t/evil.example"` | `https://evil.example/` | **ACCEPT** | **exploitable** |
| `"/\n/evil.example"` | `https://evil.example/` | **ACCEPT** | **exploitable** |
| `"/\r/evil.example"` | `https://evil.example/` | **ACCEPT** | **exploitable** |

The cause is exactly the one D1 names: the URL parser removes tab/LF/CR from anywhere in the string *before*
parsing, so `/<TAB>/evil.example` becomes `//evil.example` — scheme-relative — after our check has already passed it.
`raw[1]` is a tab, which is neither `/` nor `\`.

**The rule this slice ships is therefore the briefed allow-list PLUS one more clause:**

```
ACCEPT  ⟺  typeof raw === 'string'
        AND raw[0] === '/'
        AND raw[1] !== '/'
        AND raw[1] !== '\'
        AND raw contains NO C0 control character (U+0000–U+001F) and no U+007F, at ANY position
```

Executed over the 25-case probe in §5: briefed-rule holes = **3**, corrected-rule holes = **0**.

The C0 clause is stated as *"anywhere"*, not *"at position 1"*, on purpose: `"/x/\t/y"` also contains a removable
byte, and while it happens to resolve same-origin today, a rule whose safety depends on **where** the byte sits is a
rule that breaks the next time the parser's normalisation order changes. Reject the whole class.

`raw[1]` on a one-character string `"/"` is `undefined`, which is neither `'/'` nor `'\'` — so `"/"` is accepted, as
AC-2 requires. Do not "fix" this with a length check.

### 3.3 Decision D3 — the `fallback` is trusted, and that is enforced at the call site, not inside

`safeCallbackUrl(raw, fallback)` does **not** validate `fallback`. Validating it would need a fallback for the
fallback — infinite regress, and the honest place to stop. Instead the guard spec asserts that the **only** call site
in the tree passes a compile-time constant (`PORTAL_LANDING[accent]`), so an untrusted fallback cannot be introduced
without turning the gate red. State this in the module header.

### 3.4 Decision D4 — validate **once, at the read site** (AC-3)

```ts
const callbackUrl = safeCallbackUrl(params.get('callbackUrl'), PORTAL_LANDING[accent]);
```

Not at the two use sites. A per-use-site guard is a rule that a third use site can forget; a per-read-site guard
makes the local binding safe **by construction**, so `callbackUrl` is a safe value everywhere in the component
including the SSO branch (which is strictly safer than before, and is not a change to next-auth's own guard).

**NEW FILE** `apps/web/src/lib/safe-callback-url.ts` exports


## 6. The guard spec contract — `apps/api/src/shared/quality/open-redirect-gate.spec.ts`

### 6.0 Floor first (the run-10 rule)

Before any negative assertion: assert the tree really was walked
(`WEB_SRC_FILES.length >= 300`, matching `portal-landing-gate.spec.ts:169`), that the stripper really strips and
really preserves length, and that `safe-callback-url.ts` exists. Every `not.toContain` below is satisfied forever by
a walk that found nothing.

### 6.1 AC-5(a) — EXECUTE the helper, do not read it

Transpile the real module with the `typescript` package and evaluate it, copying the `loadRegister` idiom at
`web-observability-gate.spec.ts:380-398`:

```ts
const source = readFileSync(SAFE_CALLBACK_PATH, 'utf8');
const { outputText } = ts.transpileModule(source, {
  compilerOptions: { module: ts.ModuleKind.CommonJS, target: ts.ScriptTarget.ES2022 },
});
const container = { exports: {} as Record<string, unknown> };
const factory = new Function('module', 'exports', 'require', outputText) as (…) => void;
factory(container, container.exports, (specifier: string) => {
  // AC-1 proven by EXECUTION, not by grep: an import-free module never calls this.
  throw new Error(`safe-callback-url.ts must import nothing — it tried to load ${specifier}`);
});
```

The throwing `require` is the AC-1 edge-safety proof: a module that imports anything fails at load. Keep the
grep-level assertions (`not.toMatch(/^\s*import\s/m)`, `not.toContain('server-only')`,
`not.toContain('process.env')`) **as well** — they name the intent where a reader will look.

### 6.2 The matrix, driven twice

For every one of the 37 rows:

1. **Expectation** — `safeCallbackUrl(input, FALLBACK)` equals `FALLBACK` (reject rows) or the input verbatim
   (accept rows).
2. **Differential oracle** — `new URL(safeCallbackUrl(input, FALLBACK), BASE).origin === 'https://pilotage.example'`.

The oracle is the load-bearing one: it is the property that actually matters, and unlike a hand-written expectation
column it cannot silently drift. Also assert, per accept row, that the raw input's own origin is same-origin — that
is what makes the accept list *defensible* rather than merely *asserted*.

### 6.3 AC-5(b) — proven in the NEGATIVE, in two directions

**(i) The old expression.** A fixture string reproducing `PortalLoginForm.tsx:76`+`:125` as they were —

```ts
const OLD_SHAPE = [
  "const callbackUrl = params.get('callbackUrl') ?? DEFAULT_LANDING[accent];",

```

— must be **reported as an offender** by the same scan function that walks the tree (§6.4), and the current

**(ii) The briefed-but-insufficient rule.** Re-implement §3.2's briefed rule as a local fixture function and run the

### 6.4 AC-5(c) — the structural scan, over comment-stripped executable content

Scan **the whole of `apps/web/src`**, not the one file — no escape by omission, the rule both `lint-ratchet.js` and
`production-artefact-check.js` encode.

Read every `.ts`/`.tsx` under `apps/web/src` through `stripCommentsPreservingLines` from
`scripts/link-integrity-check.js` (`require` it unguarded, exactly as `portal-landing-gate.spec.ts:90-96` does — if
the script stops exporting it, this suite must **fail at load**, never degrade to "nothing to check"). This is
`PF-83`'s lesson: a guard that a reworded comment can turn red is a false red waiting to happen, and `R-30` says a
red assertion may be the author's error rather than the code's.

**The rule, stated precisely so it is implementable and so its limits are honest:**

* **Tainted binding** — a `const`/`let` declaration in the file whose initialiser text contains a search-parameter
  read: `searchParams.get(`, `params.get(`, or `useSearchParams()`. A binding whose initialiser also contains
  `safeCallbackUrl(` is **not** tainted (that is the fix).
* **Sink** — the first argument of `router.push(`, `router.replace(`, `redirect(`,
  `window.location.assign(`, `window.location.replace(`, or the right-hand side of `window.location.href =`.
* **FAIL** when a sink's argument *is* a tainted identifier, or begins with one (`tainted`, `tainted as string`,
  `tainted!`).

**Measured false-positive surface — every current sink in the tree, and why the rule is silent on it.** This list was
produced by grep before the rule was written; it is the evidence that the rule will not go red on a correct tree:

| site | pushed value | in scope? |
|---|---|---|
| `apps/web/src/components/PortalLoginForm.tsx:125` | `callbackUrl` | **yes — the target.** Green only after AC-3 |
| `apps/web/src/app/admin/analytics/PerformanceDrilldown.tsx:118` | `hrefFor(patch)` → returns `` `${pathname}?${qs}` `` | no — a local call, and pathname-anchored by construction |
| `apps/web/src/components/notifications/NotificationListItem.tsx:56,59` | `link` (a prop, from a `Notification` row) | no — server data, not `searchParams`. See §7.3 |
| `apps/web/src/app/{admin,teacher,parent,student}/page.tsx` | `PORTAL_LANDING.<portal>` | no — literal-key constant lookup |
| `apps/web/src/middleware.ts:150,159,166` | `new URL(…, req.nextUrl.origin)` | no — origin-anchored `NextResponse.redirect` |
| every `*Filters.tsx` / `*Tabs*.tsx` under `app/**` | `` `${pathname}?${params}` `` | no — pathname-anchored |

**What this scan does NOT claim, and must say so in its own header (DNC-08 honesty):** it is lexical and
single-file. It does not perform cross-file dataflow, and it will not catch a tainted value laundered through an
intermediate helper or passed as a prop between files. It closes the shape `PF-102` actually is, and it says so
rather than implying more.

## 7. Implementation notes

### 7.1 The module, in outline

```ts
/**
 * Same-origin-only post-authentication redirect target (S-E05-12, PF-102).
 *
 * WHY THIS MODULE EXISTS …            ← the §1.1 sequence, in prose
 * WHY IT IS IMPORT-FREE …             ← the portals.ts reason, verbatim in spirit
 * WHY NOTHING IS TRIMMED OR DECODED … ← §3.1 / D1
 * WHY C0 CONTROLS ARE REFUSED ANYWHERE … ← §3.2 / D2, with the three measured inputs named
 * WHY `fallback` IS NOT VALIDATED …   ← §3.3 / D3
 */
/** C0 controls + DEL. Written as \u escapes on purpose: a literal tab inside
 *  a character class is invisible in a diff, and this class is load-bearing. */
const CONTROL_CHARACTERS = /[\u0000-\u001F\u007F]/;

export function safeCallbackUrl(raw: string | null | undefined, fallback: string): string {
  if (typeof raw !== 'string') return fallback;
  if (raw[0] !== '/') return fallback;
  if (raw[1] === '/' || raw[1] === '\\') return fallback;
  if (CONTROL_CHARACTERS.test(raw)) return fallback;
  return raw;
}
```

No `startsWith` — `raw[0] !== '/'` handles the empty string in the same branch, with no second check to forget.

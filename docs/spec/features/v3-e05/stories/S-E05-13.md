## 0. What this story is, in one sentence

`PATCH /api/v1/cycles/grade-levels/:levelId` takes an **entirely unvalidated** request body and hands it
straight to `prisma.gradeLevel.update({ data: body })`, so a `school_admin` can PATCH
`{"tenantId":"<another-tenant-uuid>"}` and **move the row out of their own tenant into a foreign one**; this
story replaces both `Partial<T>` bodies in `apps/api` with real DTO classes, replaces the mass-assignment with
an explicit field pick, adds `ParseUUIDPipe` to the four affected path params, and lands a **derived** ratchet
so no `@Body()` in this API can silently erase to `Object` again.

epic carries”**, and additionally carries the long-standing `S-E05-2b` pointer. Neither is an instruction to

### 1.1 The mechanism, read off the SHIPPED BUILD ARTEFACT (not inferred)

`apps/api/dist/modules/school-structure/cycles.controller.js` — emitted decorator metadata, verbatim:

```js

// line 263 — updateGradeLevel
__metadata("design:paramtypes", [String, Object,        Object]),
// line 234 — update (cycle) — the CONTROL: a real class survives erasure
__metadata("design:paramtypes", [String, UpdateCycleDto, Object]),
```

The chain, each link measured:

1. `packages/tsconfig/node.json:10` sets `"emitDecoratorMetadata": true`.
2. `Partial<T>` is a **mapped type**, not a class. TypeScript has no runtime value to emit for it, so it
   emits `Object`.
3. Nest's `ValidationPipe.toValidate()` returns `false` when the metatype is `Object` (it is in the pipe's
   own `[String, Boolean, Number, Array, Object]` skip list).
4. Therefore the pipe **skips validation entirely and returns the body RAW**. The global
   `new ValidationPipe({ transform: true, whitelist: true, forbidNonWhitelisted: true })` at
   `apps/api/src/main.ts:140-145` is **bypassed, not applied**.

The trailing `Object` in every triple is the `@CurrentJwt()` payload (`KeycloakJwtPayload` is a
`type`, imported with `import { type … }`), and the `[String, Object]` on `remove`/`deleteGradeLevel` is
`(id, jwt)`. **This is why the ratchet must key on `@Body()` specifically and not on “any `Object` metatype”** —
see §5.

### 1.3 SITE 1 — SEVERE — `cycles.controller.ts:165-174` `updateGradeLevel`

```ts
  @Patch('grade-levels/:levelId')
  @RequiresPermission('grade_levels.write')
  async updateGradeLevel(
    @Param('levelId') levelId: string,
    @Body() body: Partial<GradeLevelDto>,
    @CurrentJwt() jwt: KeycloakJwtPayload,
  ) {
    const me = await this.users.ensureUser(jwt);
    const level = await this.prisma.gradeLevel.findUnique({ where: { id: levelId } });
    if (!level || level.tenantId !== me.tenantId) throw new NotFoundException();
    return this.prisma.gradeLevel.update({ where: { id: levelId }, data: body });
  }
```

`data: body` is **full mass-assignment**. `apps/api/prisma/schema.prisma` `model GradeLevel` (read, never
edited) carries these **writable scalars**:

```prisma
model GradeLevel {
  id         String   @id @default(uuid()) @db.Uuid
  tenantId   String   @map("tenant_id") @db.Uuid   // ← writable
  schoolId   String   @map("school_id")  @db.Uuid  // ← writable
  cycleId    String   @map("cycle_id")   @db.Uuid  // ← writable
  code       String
  name       String
  orderIndex Int      @map("order_index")
  …
}
```

Prisma's `GradeLevelUncheckedUpdateInput` accepts those raw scalar FKs. So
`PATCH {"tenantId":"<foreign-uuid>"}` **pushes the row out of the caller's tenant into a foreign one**. The
`findUnique` guard above it only inspects the row's **current** `tenantId`; it is structurally blind to the
incoming body. `schoolId` and `cycleId` are the same class of escape one level down (re-parenting a level
under a foreign school / an unrelated cycle).

**This is a cross-tenant WRITE. It triggers `G-TENANT` and it is the reason this story is P1.**

### 1.4 SITE 2 — LESSER — `academic-years.controller.ts:244-262` `updateTerm`

```ts
  @Patch('terms/:termId')
  @RequiresPermission('terms.write')
  async updateTerm(
    @Param('termId') termId: string,
    @Body() body: Partial<TermDto>,
    @CurrentJwt() jwt: KeycloakJwtPayload,
  ) {
    const me = await this.users.ensureUser(jwt);
    const term = await this.prisma.term.findUnique({ where: { id: termId } });
    if (!term || term.tenantId !== me.tenantId) throw new NotFoundException('Trimestre introuvable');
    if (body.startDate && body.endDate) this.assertDateOrder(body.startDate, body.endDate);
    return this.prisma.term.update({
      where: { id: termId },
      data: {
        name: body.name ?? undefined,
        orderIndex: body.orderIndex ?? undefined,
        startDate: body.startDate ? new Date(body.startDate) : undefined,
        endDate: body.endDate ? new Date(body.endDate) : undefined,
      },
    });
  }
```

**Say this precisely, and do not overstate it.** This handler is **also unvalidated** — same `Object`
erasure, same skipped pipe. But it **already field-picks** (`name`, `orderIndex`, `startDate`, `endDate`)
instead of spreading, so **there is NO tenancy escape here**. Writing that site 2 had a mass-assignment hole
would be **false** and must not appear in the diff, the docblock, the ADR or the PR body.

What *is* real at site 2:

- **No type or length validation at all.** `body.name` may be a 10 MB string, an array, or an object; it
  reaches a `String` column unchecked. `body.orderIndex` may be `"three"` and reaches an `Int` column.
- **`new Date(body.startDate)` on an arbitrary string yields `Invalid Date`**, Prisma rejects it, and the
  caller gets a **500** where a **400** was owed.

## 3. The fix — TWO INDEPENDENT DEFENCES on site 1, and one on site 2

### 3.1 Defence 1 — real DTO classes (restores the global pipe)

Replace both `Partial<T>` annotations with **declared classes**, every field `@IsOptional()` plus the same
validators the create DTOs already use. Place each next to its existing sibling DTO in the same file
(`cycles.controller.ts` and `academic-years.controller.ts` both already declare their DTOs inline — follow
the house style, do not invent a `*.dto.ts` for two classes; `branding.dto.ts` exists but is a service-backed
module, a different shape).

```ts
// cycles.controller.ts — next to GradeLevelDto
class UpdateGradeLevelDto {
  @IsOptional() @IsString() @MinLength(1) @MaxLength(20) code?: string;
  @IsOptional() @IsString() @MinLength(1) @MaxLength(40) name?: string;
  @IsOptional() @IsInt() @Min(0) orderIndex?: number;
}

// academic-years.controller.ts — next to TermDto
class UpdateTermDto {
  @IsOptional() @IsString() @MinLength(1) @MaxLength(40) name?: string;
  @IsOptional() @IsInt() orderIndex?: number;
  @IsOptional() @IsDateString() startDate?: string;
  @IsOptional() @IsDateString() endDate?: string;
}
```

The bounds are **copied from the create DTOs already in those files** (`GradeLevelDto`:
`code` 1..20, `name` 1..40, `orderIndex` `@IsInt @Min(0)`; `TermDto`: `name` 1..40, `orderIndex` `@IsInt`
with **no** `@Min`, `startDate`/`endDate` `@IsDateString`). Do **not** silently tighten or loosen them —
a PATCH that rejects a value the POST accepts is a new inconsistency, and `@Min(0)` on `TermDto.orderIndex`
would be exactly that.

Because the metatype is now a real class, `ValidationPipe.toValidate()` returns `true` and the global
`whitelist: true, forbidNonWhitelisted: true` **applies**: an unknown key such as `tenantId`, `schoolId` or
`cycleId` now yields **400**.

### 3.2 Defence 2 — explicit field pick (holds even if defence 1 regresses)

**Independently**, replace `data: body` in `updateGradeLevel` with the same explicit shape `updateTerm`
already uses:

```ts
    return this.prisma.gradeLevel.update({
      where: { id: levelId },
      data: {
        code: body.code ?? undefined,
        name: body.name ?? undefined,
        orderIndex: body.orderIndex ?? undefined,
      },
    });
```

**Both defences ship in the same commit, and the docblock must say why.** Defence 1 is a *decorator
contract*: it survives only as long as nobody re-annotates the parameter with a type-level construct — which
is precisely the mistake this story is repairing. Defence 2 is a *dataflow fact* at the call site: even with
the pipe fully bypassed, `tenantId` has no route into the `data` object. Neither is redundant with the other,
and a reviewer who deletes one as "already covered" has removed a layer. Write that in the docblock, in those
terms.

### 3.3 The path params

Add `ParseUUIDPipe` to the five parameters in §1.5, `@Param('levelId', ParseUUIDPipe)` style (the
`enrollments.controller.ts:778` form — the bare class, not `new ParseUUIDPipe()`; both idioms exist in the
repo, prefer the one the predecessor slice used). Import it from `@nestjs/common` alongside the existing
`Param` import in each file.

### 3.4 Explicitly NOT fixed here

`assertDateOrder` at `academic-years.controller.ts:270` runs **only when both `startDate` and `endDate` are
present** (`if (body.startDate && body.endDate)`), so a one-sided PATCH — `{"endDate":"2020-01-01"}` on a term
starting in 2026 — **inverts the term's date order** and is accepted. Allocated **`PF-284`** (P2
`[correctness]`) and **left open**. It is a *semantic* invariant needing the persisted row as the other
operand (`term.startDate` from the `findUnique` already in hand), not a DTO annotation, so it does not fall
out of this work for free. If the dev finds it *does* fall out for free, they may take it — but only with its
own test and its own ledger row moving to closed.

## 5. The ratchet — DERIVED, never a hand-maintained twin list

New spec: **`apps/api/src/shared/quality/body-metatype-gate.spec.ts`** (the `shared/quality/` folder is where
every cross-cutting gate in this repo lives — 31 siblings; `apps/web` has no unit runner, so this is the only
correct home).

**It asserts: no `@Body()` parameter in this API reflects a metatype of `Object`.**

**Why it must be derived.** A spec that hard-codes "the two known sites are fixed" is exactly the
paired-hand-maintained-list failure this repo has already been burned by (`academic_year.SELECT`, run 59:
the required closure and the probe's hard-coded `VALUES` drifted apart and four portals 503'd). A third
`Partial<T>` added next month must **fail this gate on its first commit**, without anyone editing the gate.

**Two layers, and the spec must say which one proves what:**

- **Layer A — source census over the whole tree (the drift-proof half).**
  Walk `apps/api/src/**/*.controller.ts` (use the shared `scripts/lib/walk-read.js` seam — `TOOL-17` exists
  precisely so gates stop hand-rolling `walk()` + module-level `readFileSync`, which races under parallel
  jest). For every `@Body()` parameter, extract its type annotation and require it to be a **bare
  identifier that resolves to a `class` declaration** reachable from that file. Anything else fails:
  `Partial<`, `Pick<`, `Omit<`, `Record<`, `Partial<T> | U`, an inline object literal, `any`, `unknown`, or a
  bare identifier that resolves to a `type`/`interface` rather than a `class` — **every one of those erases
  to `Object`**, and enumerating only `Partial<` would leave the door open one keyword over.
- **Layer B — runtime truth on the two repaired controllers.**
  `import { CyclesController } from '…/cycles.controller'` and likewise `AcademicYearsController`, then
  `Reflect.getMetadata('design:paramtypes', Ctrl.prototype, 'updateGradeLevel')` and assert
  `[1] === UpdateGradeLevelDto` (not `Object`). Pair it with `Reflect.getMetadata('__routeArguments__', Ctrl,
  'updateGradeLevel')` to confirm index `1` is the `@Body()` slot — **this is the step that stops the gate
  from mistaking the trailing `@CurrentJwt()` `Object` (see §1.1) for a defect.** The `__routeArguments__`
  reflection idiom is already in the repo at
  `enrollments-roster-abac.spec.ts:678-686`; reuse it, including its
  `const ROUTE_ARGS_METADATA_KEY = '__routeArguments__'` constant and the `import 'reflect-metadata'` first
  line.

**Do NOT import all 41 controllers.** `boot-gate.spec.ts:26-33` records the measured reason: importing broadly
under ts-jest pulls `AuthModule → JwtStrategy → jwks-rsa → jose`, and `jose@6` is ESM-only — the CommonJS
runtime fails to parse it and the suite dies before its first assertion. Layer A (text, zero imports) is what
gives whole-tree coverage; Layer B is depth on the two sites this story touches. The spec's docblock must
state this division of labour so nobody "simplifies" Layer A into an import loop.

**FAILS-BEFORE / PASSES-AFTER.** The gate must be red on the pre-fix tree. Prove it the way
`walk-read-gate.spec.ts` and `audit-provenance-gate.spec.ts` do — a scratch fixture under
`mkdtempSync(tmpdir())` containing a `@Body() b: Partial<Foo>` controller, driven through the same extractor —
**not** by `git show HEAD:` (which inverts the moment the slice is committed, and CI checks out at depth 1)
and **never** by planting a probe file into the real checkout (`TOOL-17`: that is the parallel-jest race
itself).

**The allowlist.** If a legitimate exception ever exists it must be an explicit, named entry
(`{ file, method, param, reason }`) — never a wildcard, never a regex over paths. **It ships EMPTY.** A
non-empty allowlist at land is a review-blocking finding.

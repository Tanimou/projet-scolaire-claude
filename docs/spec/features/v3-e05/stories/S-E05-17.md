## Why this slice

`PF-51` (a ROADMAP finding) has three clauses. Clause 1 (PATCH body / mass-assign) closed run 74. Clause 2
(query params) closed run 75. This slice closes clause 3 — *"several query params bypass validation; notification
`kind` accepts arbitrary strings"* — so the row can finally flip.

The flip is earned by the **ratchet**, not by the three pipes. Three pipes close three sites; only a derived,
repo-wide gate closes a class. `OPEN.md`'s standing instruction — *"Do NOT flip this row on the strength of one
parameter"* — is discharged by `AC-6`, and by nothing else.

## The three sites (measured live, 2026-08-23, not derived from source)

```
PATCH /api/v1/notifications/preferences/not_a_kind     -> 500
PATCH /api/v1/notifications/preferences/remediation    -> 200  writes a row GET /preferences NEVER returns
GET   /api/v1/calendar/events?type=not_a_type          -> 500
GET   /api/v1/calendar/events?type=                    -> 200  (empty string is falsy today)
GET   /api/v1/alerts/instances?status=not_a_status     -> 200  FULL UNFILTERED LIST
```

| # | Site | Mechanism |
|---|---|---|
| 1 | `notifications/preferences.controller.ts` | `@Param('kind') kind: string` → metatype `String` → `ValidationPipe.toValidate()` false → the global pipe is **SKIPPED**, and `kind as NotificationKind` carries a raw string into a compound-key `findUnique`/`upsert` → `PrismaClientValidationError` → bare 500 |
| 2 | `calendar/calendar.controller.ts` | `@Query('type') type?: CalendarEventType` — the TS type is **erased at runtime**; there was no validator at all |
| 3 | `alerts/alerts.controller.ts` | a hand-written four-value literal duplicating `ALERT_STATUS`; an invalid value fell through to `undefined`, i.e. **no filter** — a truth defect, not just a validation gap |

## Acceptance criteria

- **AC-1** `:kind` is refused with **400** in the PIPE phase — before the handler body and before `ensureUser`
  (**not** "before any database read": guards run before pipes, and `PermissionsGuard` reads). Proven by
  executing the route-registered pipe instance and asserting zero calls on counting fakes, with a positive
  control proving the fakes record.
- **AC-2** The accepted set is the **EXPOSED** 8, not the 9-value Prisma enum. `remediation` → 400 (`PF-314`).
- **AC-3** The allowlist exists exactly once: `NOTIFICATION_KIND` in contracts; `NOTIFICATION_KINDS` is that
  same array (referential identity asserted), bound through `ReadonlyArray<NotificationKind>`; the ordered
  8-tuple is pinned; `WITHHELD_NOTIFICATION_KINDS` is derived and pinned to `['remediation']`.
- **AC-4** `?type` unknown → 400; **absent → 200** (the only shape any real caller uses); all 7 valid → 200;
  `?type=` → 400, declared in `ADR-067 §D2`, with no normalisation helper in the diff.
- **AC-5** `?status` unknown → 400 instead of the unfiltered list; the four valid statuses return the **same
  rows** before and after over the same fixture (G-TRUTH on the valid path); `ALERT_STATUS` comes from contracts
  and is bound through `ReadonlyArray<AlertStatus>`.
- **AC-6** A one-way ratchet under `apps/api/src/shared/quality/`, **annotation-first and cast-second**, with a
  derived enum inventory, an empty `MANUAL_ALLOWLIST`, red-before/green-after fixtures **and** a negative
  control shaped like the two already-correct siblings.
- **AC-7** `scripts/enum-route-input-probe.js` — credentials from env with no defaults, loopback enforced on
  **both** `KEYCLOAK_URL` and `API_URL`, value-preserving control PATCH, no secret printed, non-zero exit on any
  mismatch. Wired into no gate stage. **Run before the image rebuild it exits non-zero with the pre-change
  matrix — that run is its own negative control and is never presented as green evidence.**
- **AC-8** `ADR-067` records §D0 source selection, §D1 exposed-set, §D2 the empty-string 400, §D3
  400-not-widening, §D4 the French message, §D5 landing prerequisites, §D6 the ratchet, §D7 the non-goals.
- **AC-9** Ledger: `PF-314`/`PF-315` closed, `PF-316` record-only, `PF-291` advanced not closed, `PF-51`
  `closed`, `PF-317`/`PF-318`/`R-1` recorded.
- **AC-10** G-PORTAL reported with the REAL numbers: preferences **3/4**, calendar **3/4** (the planning
  premise "calendar is on all four" is stale — no student calendar route exists), alerts admin-only.
- **AC-11** G-TENANT holds; the un-tenant-keyed `userProfileId_kind` `where` is pre-existing, unchanged, and
  explicitly out of scope.

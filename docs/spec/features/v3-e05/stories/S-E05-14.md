## 1. The measurement, re-taken against `HEAD` before a line was written

### 1.1 The handler, verbatim (`apps/api/src/modules/enrollments/enrollments.controller.ts:530-548`)

```ts
  /** Roster — list active enrollments per class section, useful for the teacher portal. */
  @Get('roster/:classSectionId')
  @RequiresPermission('enrollments.read')
  async roster(@Param('classSectionId') classSectionId: string, @CurrentJwt() jwt: KeycloakJwtPayload) {
    const me = await this.users.ensureUser(jwt);
    const cls = await this.prisma.classSection.findUnique({ where: { id: classSectionId } });
    if (!cls || cls.tenantId !== me.tenantId) throw new NotFoundException();

    const enrollments = await this.prisma.enrollment.findMany({
      where: { classSectionId, status: 'active', tenantId: me.tenantId },
      include: { student: true },
      orderBy: { student: { lastName: 'asc' } satisfies Prisma.StudentOrderByWithRelationInput },
    });
    return {
      classSection: cls,
      enrollments,
      capacity: { current: enrollments.length, max: cls.maxStudents },
    };
  }
```

Three things happen: `ensureUser`, a tenant comparison that yields 404, and one `findMany`. **There is no
ABAC and no ownership check of any kind.**

### 1.2 Who holds the key (`apps/api/src/shared/auth/permissions.constants.ts`)

### 1.3 What comes back (`apps/api/prisma/schema.prisma:488-513`)

`medicalNotes` is special-category data about a minor. `GUARDRAILS.md` §1 makes minimal access

### 3.2 The decision layer — pure, exported, no escape hatch

```ts
/** Le contexte d'autorisation de l'appelant, résolu DEHORS, comparé PUREMENT. */
export interface EnrollmentRosterReadContext {
  /** `super_admin` / `school_admin` : la propriété n'est pas exigée d'eux. */
  readonly isPrivileged: boolean;
  /** `null` = l'appelant n'a AUCUN profil professeur (donc aucune affectation). */
  readonly teacherProfileId: string | null;
  /** Une `TeachingAssignment` de cet appelant porte-t-elle sur CETTE classe ? */
  readonly teachesSection: boolean;
}

export function isPrivilegedEnrollmentsCaller(roles: readonly string[]): boolean {
  return roles.includes('super_admin') || roles.includes('school_admin');
}

export function assertClassRosterReadable(context: EnrollmentRosterReadContext): void {
  if (context.isPrivileged) return;
  if (context.teacherProfileId === null || !context.teachesSection) {
    throw new ForbiddenException('Vous ne pouvez consulter que la liste des élèves de vos classes.');
  }
}
```

Three properties are load-bearing and each is tested:

- **Fail-closed on `null`.** A caller with no `TeacherProfile` is refused **even if `teachesSection` were
  somehow true** — the `null` branch is checked first and independently, so a fake context cannot walk
  past it. Treating `null` as “let through” is exactly the fail-open `G-AUTHZ` refuses.
- **The message is READ-shaped**, French, and names no tenant, table, id or Prisma code (`ADR-048 §D9`).
  It is deliberately **not** `assertSessionReadable`'s message (“vos affectations” / séances): that copy is
  about opening a *session*, and this refusal is about a *class list*.
- **No bypass.** No `bypass` / `allow` / `skip` parameter, no options bag, no `NODE_ENV` /
  `SKIP_*` / `ALLOW_*` env read. A control you can switch off is not a control (`DNC-10`).

`isPrivilegedEnrollmentsCaller`'s docblock must carry the **same `PF-268` honesty** as its attendance twin —
copy the limitation, not just the code: *this is a test on the **name** of a realm role, while
`PermissionsGuard` also resolves **custom** roles via `UserSyncService.effectivePermissions` (`ADR-013`,
`ADR-047` — custom roles are global). A “vie scolaire” custom role holding `enrollments.read` would pass
the guard and be refused here. The honest remedy is a dedicated permission code, which §6 puts out of
scope. Measured on the local stack 2026-08-23: `select count(*) from role` → **0**, so zero live callers
are affected today.*

### 3.3 The handler — the two-step shape, in this order

```ts
  @Get('roster/:classSectionId')
  @RequiresPermission('enrollments.read')
  async roster(
    @Param('classSectionId', ParseUUIDPipe) classSectionId: string,
    @CurrentJwt() jwt: KeycloakJwtPayload,
  ) {
    const me = await this.users.ensureUser(jwt);

    // 1) LECTURE DE GARDE, `select` seul : elle rend le 404 ET les trois champs
    //    de la réponse. Aucune donnée d'élève n'est matérialisée avant le verdict.
    const cls = await this.prisma.classSection.findUnique({
      where: { id: classSectionId },
      select: { id: true, tenantId: true, name: true, maxStudents: true },
    });
    if (!cls || cls.tenantId !== me.tenantId) throw new NotFoundException();

    // 2) VERDICT DE PROPRIÉTÉ (403), toujours APRÈS le 404.
    await this.assertRosterOwnership(classSectionId, me, jwt);

    // 3) CHARGE UTILE, une fois le verdict rendu seulement.
    const enrollments = await this.prisma.enrollment.findMany({
      where: { classSectionId, status: 'active', tenantId: me.tenantId },
      include: { student: { select: ENROLLMENT_ROSTER_STUDENT_SELECT } },
      orderBy: { student: { lastName: 'asc' } satisfies Prisma.StudentOrderByWithRelationInput },
    });
    return {
      classSection: { id: cls.id, name: cls.name, maxStudents: cls.maxStudents },
      enrollments,
      capacity: { current: enrollments.length, max: cls.maxStudents },
    };
  }
```

**Why `ensureUser` comes first here, unlike `attendance/overview`.** `overview` refuses **before**
`ensureUser` because its decision depends on the token alone. This decision does **not**: it needs
`me.tenantId` for the 404 comparison and for the tenant-keyed assignment lookup. So `ensureUser` stays
first, and that is a measured difference, not an oversight. Say so in the docblock.

**Resolution helper** (private, mirrors `assertSessionOwnership:816`):

```ts
  private async assertRosterOwnership(
    classSectionId: string,
    me: { id: string; tenantId: string },
    jwt: KeycloakJwtPayload,
  ): Promise<void> {
    const isPrivileged = isPrivilegedEnrollmentsCaller(jwt.realm_access?.roles ?? []);
    // Le court-circuit privilégié saute les DEUX requêtes : un administrateur
    // n'a jamais de profil professeur, et ne pas le demander est une
    // instruction de moins sur le chemin admin.
    const tp = isPrivileged ? null : await this.teachers.findForUser(me);
    const teachesSection =
      tp !== null &&
      (await this.prisma.teachingAssignment.findFirst({
        where: { tenantId: me.tenantId, teacherProfileId: tp.id, classSectionId },
        select: { id: true },
      })) !== null;
    assertClassRosterReadable({ isPrivileged, teacherProfileId: tp?.id ?? null, teachesSection });
  }
```

`findForUser`, **never** `ensureForUser` (`PF-265` / `ADR-051 §D1`): a refusal path must provision nothing.

### 3.4 The teaching wall — measured, and it carries **no** academic-year clause

`TeachingAssignment` (`schema.prisma:1006-1032`) has `tenantId`, `teacherProfileId`, `classSectionId`,
`subjectId`, `academicYearId`, `@@unique([teacherProfileId, classSectionId, subjectId])` and
`@@index([tenantId, classSectionId])`. A teacher may hold several assignments on one section (one per
subject); `findFirst` is therefore correct and `findUnique` is not.

**No `academicYear` filter, and this is a measurement, not a shortcut.** `ClassSection` itself carries
`academicYearId` (`schema.prisma:457`) and is unique on `[academicYearId, gradeLevelId, name]` — a section
belongs to exactly **one** year. `classSectionId` therefore already pins the year transitively. Adding
`academicYear: { status: 'active' }` would (a) refuse a teacher reading the roster of a past-year section
they genuinely taught, and (b) put a **relational** member in the `where`, which the test double records
but cannot filter (`PF-275`). The `where` above is **entirely scalar**, so the fake Prisma filters it for
real and the negative cells of `AC-3` land on actual filtering rather than on a recorded clause. This is
the opposite call from `attendance`'s `studentAttendance`, where the join ran student → enrollment →
classSection **across** years and a year wall was genuinely needed (`ADR-061 §D1`) — name the difference in
`ADR-063`.

`tenantId` is in the `where` even though `classSectionId` is already tenant-verified by the guard read:
belt and braces on the same query, per `ADR-002`, and it is the indexed pair.

### 3.5 `ParseUUIDPipe` — `PF-51`, one site

`@Param('classSectionId', ParseUUIDPipe)`, the class form used at
`child-claims/admin-child-claims.controller.ts:80` and `:103`. It runs in the pipe phase, i.e. **before**
the handler body and before any database read. Today a malformed id reaches Prisma and a `@db.Uuid` column,
producing a P2023 → 500; after this it is a clean 400. Every id-bearing DTO field in this same file already
declares `@IsUUID()` (`:36`, `:37`, `:42`), so this closes the **param vs. body** asymmetry at this one
endpoint: the body was validated, the path parameter was not.

**Claim it as partial.** `PF-51` covers unvalidated PATCH/query/enum params across the surface;
`S-E05-13` owns it. This story advances it on **one** site and the traceability row must say exactly that.

### 5.1 The `PF-275` trap, named before it is walked into

The attendance harness **records** `select` / `include` without applying them, so an assertion about the
returned body there is really an assertion about the **request**. This harness inherits that. Therefore:

- **Assert the REQUEST SHAPE.** The recorded `enrollment.findMany` statement carries
  `include.student.select` deep-equal to `{ id, firstName, lastName, externalRef }`, and the statement does
  **not** carry the bare `include: { student: true }` form. Assert `medicalNotes`, `address`, `notes`,
  `customFields`, `birthDate`, `email`, `phone`, `gender`, `nationality`, **`photoUrl`** are absent from the
  select **key by key**, not by shape equality.
- **Say plainly, in the file, that this is a request-shape assertion and not a body assertion**, and that
  `PF-275` is why. Do **not** write a body assertion the double cannot honour.
- The **guard read** is separately asserted: the recorded `classSection.findUnique` carries a `select` and
  **no** `include`, and the refused cases record **exactly one** statement (the guard read) plus at most the

## 1. The defect, reproduced

### 1.1 What is live today

`apps/web/src/lib/csv.ts` (verbatim, lines 10–22 at HEAD):

```ts
/** Byte-order mark that makes Excel read the file as UTF-8. */
export const CSV_BOM = '﻿';

/** Field separator — semicolon for FR Excel compatibility. */
export const CSV_SEPARATOR = ';';

/** Escape a single CSV cell, quoting only when needed. */
export function csvEscape(v: string | number | null | undefined): string {
  if (v === null || v === undefined) return '';
  const s = String(v);
  if (/[",;\n\r]/.test(s)) return `"${s.replace(/"/g, '""')}"`;
  return s;
}
```

The module **prepends a BOM** (`buildCsv`), which is precisely what makes Excel/LibreOffice/Sheets open the artefact as
a **spreadsheet** rather than as text. A cell whose stored value is `=cmd|' /C calc'!A0` is emitted **verbatim and
unquoted** (it contains none of `" ; \n \r`), lands in A-column position, and is **evaluated on open**. Quoting alone
would not have helped either: Excel evaluates `"=1+1"` on CSV import — which is the measured fact ADR-037 D7 is built
on.

### 1.2 The reachable free text — this is not latent

`S-E04-11` could argue the worker's audit CSV had no reachable free-text column. These four buttons do:

| Surface | Portal | File | Free-text columns escaped with the broken helper |
|---|---|---|---|
| `/admin/guardians` | admin | `apps/web/src/app/admin/guardians/GuardiansExportButton.tsx:75-83` | `lastName`, `firstName`, `email`, **`phone`**, **`profession`** — arbitrary operator-entered text |
| `/admin/enrollments` | admin | `apps/web/src/app/admin/enrollments/EnrollmentsExportButton.tsx` | guardian + student names, `email`, `phone`, class name, status label |
| `/teacher/reports` | teacher | `apps/web/src/app/teacher/reports/_components/ExportReportButton.tsx:79-114` | term names, class/subject names, assessment `title`, `kind` |
| `/teacher/students` | teacher | `apps/web/src/app/teacher/students/ExportStudentsButton.tsx:82-91` | `lastName`, `firstName`, `externalRef`, class names, levels |

Plus the fifth surface, `/admin/alerts`, on the private copy (b): alert `title`, `body`, `recommendation`,

**Five export surfaces across two portals ⇒ G-PORTAL triggers.** The same operator-entered `profession` string

## 3. Functional requirements

### FR-1 — The shared module (`packages/contracts/src/security/csv-injection.ts`, NEW)

Exports exactly three symbols. **Pure, dependency-free** (no `zod`, no `node:*`) — it runs in a browser bundle, in a
Node worker, and inside a `require()`-based gate script.

```ts
/** The characters a spreadsheet EVALUATES (or that split a record) in first position. */
export const CSV_INJECTION_TRIGGERS: readonly string[] = ['=', '+', '-', '@', '\t', '\r'];

/** The neutralising prefix. An apostrophe, never a tab — see the doc comment. */
export const CSV_NEUTRALISER = "'";

/** Result of the neutralisation decision. A PLAIN OBJECT — never a class instance. */
export interface CsvNeutralisation {
  /** The cell body: the original value, or `CSV_NEUTRALISER + value`. */
  readonly text: string;
  /** `true` when the prefix was applied — the caller MUST then force-quote. */
  readonly neutralised: boolean;
}

/**
 * Applies the neutralisation and reports whether it fired.
 * Never drops anything: the original is recoverable by stripping exactly ONE leading apostrophe.
 */
export function neutraliseCsvCell(value: string): CsvNeutralisation;
```

**Mandatory doc-comment content** (this is a requirement, not a nicety — it is the DNC-06 discharge):

1. Why an apostrophe and **not** a leading tab: a tab is itself in `CSV_INJECTION_TRIGGERS`, so prefixing one produces
   a cell the escaper must consider dangerous again. `'` is not a trigger ⇒ **one pass suffices, no recursion**.
2. That the transform is **additive and reversible** (`replace(/^'/, '')` recovers the original), and that **nothing is
   ever dropped** — silent removal would be a worse defect than the injection.
3. That this is `ADR-037 D7`'s decision, **relocated, not changed**, and that the **dialect** (separator, BOM, record
   terminator) is deliberately **not** part of this module.
4. **The `PF-169` disclaimer, in the code, in this file and in `apps/web/src/lib/csv.ts`** (see FR-3).

**Wiring:** add `export * from './csv-injection';` to `packages/contracts/src/security/index.ts`. That file is already
re-exported by `src/index.ts:7`, so the symbols reach the existing `.` export condition. **Do not** add a new
`./security` subpath to `package.json#exports` — no consumer needs one, and adding one is an unbudgeted decision.

`apps/web/src/lib/csv.ts`:

### 4.1 Two intended behaviour deltas — do NOT "fix" these in review

**Delta 1 — `+33 6 12 34 56 78` becomes `"'+33 6 12 34 56 78"`.** `admin/guardians` and `admin/enrollments` export a
`phone` column. An international phone number starts with `+`, which is a trigger, so it is now neutralised and will
render in Excel as **text** with a leading apostrophe rather than as whatever Excel guessed before. This is
**accepted**, deliberately, and is `ADR-037 D7`'s stated trade: *uniform across every column, never a per-column
allowlist* — an allowlist is exactly what drifts the day a new free-text column joins the export. It must be a **named
test case** (§5) so it is discovered here and not in a support ticket.

**Delta 2 — `AlertsExportButton` now force-quotes what it previously left bare.** Its private copy prefixes and then
tests the ORIGINAL quote regex, so `=1+1` came out as `'=1+1` **unquoted**, and `\tSUM(1)` as `'\tSUM(1)` unquoted.
After the swap both are `"'=1+1"` / `"'\tSUM(1)"`. **`PF-168` calls copy (b) "ALREADY CORRECT"; it was correct about
the neutralisation and not about the force-quoting.** Aligning it is the point of G-TRUTH and must be stated in the PR
rather than absorbed.

**Non-delta, verified:** numeric cells are **not** affected. `ExportStudentsButton.tsx:89` passes `csvFixed1(avg20)`
**directly** into the row, not through `csvEscape`, so a negative average would not acquire an apostrophe. `csvFixed1`
itself is unchanged. State this in the PR — "did a negative number become text?" is the first question a reviewer
should ask about Delta 1, and the answer is on record.

## 6. Acceptance criteria (the definition of done)

1. `neutraliseCsvCell` exists **once**, in `packages/contracts/src/security/csv-injection.ts`, exported through
   `security/index.ts` → `src/index.ts`, alongside `CSV_INJECTION_TRIGGERS` and `CSV_NEUTRALISER`. It is pure and

3. Any value **not** starting with a trigger is emitted **byte-identical to HEAD**, accented French text included.
4. The neutraliser is the **apostrophe**, not a leading tab, and the reason (a tab is itself a trigger ⇒ recursion) is
   written in the shared module's doc comment.
5. The web dialect is untouched: `CSV_SEPARATOR === ';'`, `CSV_BOM` present, CRLF join. The `PF-169` contradiction is
   **named in a code comment** in `apps/web/src/lib/csv.ts` and explicitly deferred to a versioned, announced format
   change.
6. **The duplication is deleted.** `AlertsExportButton.tsx` has no private `csvEscape` and imports `@/lib/csv`; the
   worker generator's local `CSV_INJECTION_TRIGGERS` / `CSV_NEUTRALISER` are gone and it calls `neutraliseCsvCell`.
   Repo-wide, exactly **two** `csvEscape` declarations remain.

## 7. The architectural decision — amend `ADR-037`, do not open `ADR-038`

The guardrail makes an undocumented **new cross-cutting pattern** a blocking finding. This slice moves a security
predicate into `packages/contracts` and makes a **gate script** the thing that keeps it single. That is a decision and
it must be written down.

**Ruling proposed to Winston: append `D8` to `docs/adr/ADR-037-one-canonical-audit-vocabulary.md`, rather than open a
new ADR.** Reasons, in order:

- `ADR-037 D7` **already owns** this decision ("a cell that a spreadsheet would execute is force-quoted and prefixed
  with exactly one apostrophe"). This slice changes its **address and its reach**, not its content. Splitting the
  decision across two ADRs is how D4 and D7 nearly drifted in the first place.
- The precedent for appending exists in that very file: `S-E04-11` appended D6–D7 to `ADR-037` for exactly this reason.
- The placement itself is **not** novel: `packages/contracts/src/security/csp.ts` is already a pure, import-free
  security function shared between `apps/web` (middleware, edge runtime) and a gate script. `csv-injection.ts` is the
  same species at the same address.

**`D8` must state:** (i) the neutraliser has one home, `@pilotage/contracts/security`, and every CSV writer in the
monorepo consumes it; (ii) the **dialect** (separator, BOM, terminator) stays per-surface and is explicitly *not*
shared — `PF-169` is open and needs a versioned change; (iii) the single home is held by
`scripts/csv-escape-check.js`, not by review; (iv) the `S-E04-11` claim that copy (b) was "already correct" is
corrected (§0.3, §4.1 Delta 2). Also add a one-line pointer in `ADR-037`'s header table, as D6–D7 did.

If Winston rules for a standalone `ADR-038` instead, the same four points carry over verbatim and `ADR-037 D7` gets a
"superseded in placement by ADR-038" pointer. **Either way it lands in this slice** — not in a follow-up.

## 8. How the web wiring is evidenced — say this, claim nothing more

There is no web unit runner. The web half of this slice is therefore evidenced by **four** things, and the PR must list
them as such:

1. **`scripts/csv-escape-check.js` rule C**, executed in the gate: `apps/web/src/lib/csv.ts` imports
   `neutraliseCsvCell` from `@pilotage/contracts` **and calls it inside `csvEscape`**. This is an executed check over
   the real file, not a reading.
2. **Rule A**, executed: repo-wide there are exactly two `csvEscape` declarations, and `AlertsExportButton.tsx` is not
   one of them — i.e. the deletion is measured, not asserted.
3. **T-3**, executed in `test:worker`: the shared predicate composed under the web's `;` quote-trigger set produces the
   §4 matrix, including Delta 1.
4. **`pnpm typecheck`** (the single run, by the test-architect): `AlertsExportButton` passes a `boolean` to the widened
   `csvEscape` signature, and the whole web bundle resolves `@pilotage/contracts` — a resolution failure here is a red
   typecheck, not a silent pass.

**What may NOT be claimed:** that a browser downloaded a file; that Excel was opened; that a web unit test exists; that
`apps/web` runs any of these tests. If the PR wants a stronger claim, the honest one to reach for is a Playwright
assertion — and that is **out of scope** for this slice (§9).

**Resolution precedent that de-risks item 4:** `apps/web/src/app/admin/audit/audit-labels.ts:40-53` already imports
**runtime** functions (`auditActionTone`, `classifyAuditAction`, …) from `@pilotage/contracts`, and
`AuditTable.tsx` — a `'use client'` component — consumes them. `next.config.mjs:12-17` lists `@pilotage/contracts` in
`transpilePackages`. A client component importing a pure runtime function from contracts is an existing, shipping
pattern; this slice adds no new resolution risk. **Verify this still holds at implementation time and say so.**

## 3. Locked design decisions

**D1 — `year` becomes REQUIRED. The whole fallback chain is deleted.**
`calendar.controller.ts:277`–`282` (the `if (!year)` ladder, the `academicYear.findUnique` lookup, the
`new Date().getFullYear()` last resort) is **removed**, not guarded. A fallback that a UI happens to override is still
a fallback, and it is exactly the mechanism that produced the audit's stale-year write. AC-2 ("the target year is
chosen, not assumed") is therefore enforced **on the server**, not by client good manners.
The active academic year's start year becomes the **dialog's pre-selected default** — visible, editable, and sent
explicitly on every request.

**D2 — the confirmation is enforced server-side, by `confirm: true`.**
A `window.confirm` is bypassable with one `curl`. AC-1 must hold for any caller. The handler throws
`BadRequestException` when `confirm !== true`, with a message that **names the scope**.
Validation split follows house style exactly (`createEvent`'s `startsAt > endsAt` at `:358`, `publish`'s
missing-grades check at `assessments.controller.ts:271`): the **DTO validates shape**, the **handler validates the
business rule** — because only the handler can put the computed count into the message. Do **not** reach for
`@Equals`/`@ValidateIf`; `grep -rn 'ValidateIf|@Equals' apps/api/src` → **0 matches**, they would be new idioms here.

**D3 — the dialog's numbers are SERVER-derived, via `dryRun`. This is what makes DNC-06 structurally impossible.**
A hand-written "22 événements" in the FE is a promise that can drift from the runtime the day someone edits
`FRENCH_PUBLIC_HOLIDAYS`. Instead the same handler accepts `dryRun: true`, returns the **plan** and **writes nothing**
(no events, **no audit row** — a dry run is a read, and G-AUDIT covers mutations). The dialog renders that plan. The
count in the dialog and the count written are produced by one code path, so they cannot disagree.
`dryRun` does not require `confirm` — you are previewing, not writing.

**D4 — `academicYearId` is resolved PER ROW, by date containment.**
```ts
// tenant + school scoped; startDate/endDate are @db.Date → UTC-midnight DateTime.
const years = await tx.academicYear.findMany({
  where: { tenantId: me.tenantId, schoolId },
  select: { id: true, name: true, startDate: true, endDate: true },
  orderBy: { startDate: 'asc' },           // deterministic when two rows overlap
});
const yearFor = (d: Date) => years.find((y) => d >= y.startDate && d <= y.endDate) ?? null;
```
- Containment is **inclusive** at both ends.
- Overlapping academic-year rows: **first by `startDate` asc** wins. Deterministic, documented.
- **No containing year → `academicYearId: null`.** The column is `String?` with `onDelete: SetNull`
  (`schema.prisma:673,693`), so null is a legal, meaningful value: "this holiday belongs to no declared school year".
  A **null is correct; the active year's id is a lie.** This will be common — a French academic year runs Sept→July, so
  the Jan–Aug holidays of `year` belong to the row that started in `year − 1`, which a fresh tenant may not have.
- `activeAcademicYearId` from `ctx.forTenant` is **no longer used for stamping**. It is used for **one** thing only:
  the dialog's default year suggestion.

**D5 — one `$transaction`, a set-based existence check inside it, `createMany`, and the audit row in the same tx.**
```ts
const result = await this.prisma.$transaction(async (tx) => {
  // 1. narrow read — the two `in` filters are a PREFILTER; correctness comes from the exact-pair Set below,
  //    because `title IN (...) AND startsAt IN (...)` is a cross-product and can match a pair not in the plan.
  const existing = await tx.calendarEvent.findMany({
    where: {
      tenantId: me.tenantId,                 // G-TENANT — the fix for D-5
      schoolId,
      title:    { in: plan.map((p) => p.title) },
      startsAt: { in: plan.map((p) => p.startsAt) },
    },
    select: { title: true, startsAt: true },
  });
  const key = (t: string, d: Date) => `${t}@${d.toISOString()}`;
  const present = new Set(existing.map((e) => key(e.title, e.startsAt)));
  const toCreate = plan.filter((p) => !present.has(key(p.title, p.startsAt)));

  if (toCreate.length > 0) await tx.calendarEvent.createMany({ data: toCreate.map(rowFor) });
  await tx.auditLog.create({ data: auditRow });   // G-AUDIT — same transaction, ALWAYS, even when toCreate is empty
  return { ... };
});
```
- **The existence key is `(tenantId, schoolId, title, startsAt)` and deliberately carries NO `type` filter.**
  Today's `findFirst` has no `type` filter either. Adding one would make a manually-created "Noël"
  (`type: vacation_break`) stop suppressing the import → silent duplicates. Preserve today's suppression semantics;
  add `tenantId`, change nothing else.
- **The audit row is written even when `toCreate.length === 0`.** An operator pressed a bulk-write button; that is an
  auditable event whose truthful `after.created` is `0`. Skipping it would make the audit trail lie by omission.
- **No `isolationLevel: 'Serializable'`.** `grep -rn isolationLevel apps/api/src` → **0 matches**; it would be a new
  idiom on a shared `PrismaService`, and it needs a retry policy that does not exist. The residual race is recorded
  honestly in §8 instead of papered over.

**D6 — G-MIGRATION does not trigger, and that is a decision, not an oversight.**
The durable fix for the concurrent-double-click race is a unique constraint. It is **deliberately deferred**: the table
is populated (the audit's own 22 rows are proof), so the migration would need a pre-flight duplicate survey and a
dedup step in the same SQL, on data this routine cannot inspect on the hosted deployment. That is a G-MIGRATION slice
of its own. **Record the residual (§8); do not add the constraint here.** If an implementer nonetheless goes that way,
G-MIGRATION triggers in full: a reviewed file under `apps/api/prisma/migrations` (never `db push`), an expand/contract
plan, a stated rollback, a documented handling of pre-existing duplicates, and `node scripts/schema-drift-check.js`
still green.

**D7 — actor provenance: reuse the existing helper; capture IP/UA with Nest built-ins only.**
- `actorRole` / `portal` come from **`deriveAlertActorProvenance(jwt)`** —
  `apps/api/src/modules/alerts/alert-provenance.ts`, already imported cross-module by `teacher-exports`,
  `parent-exports`, `messaging`, `remediation`. **Do not hard-code `'school_admin'`** (that is D-9, and a hard-coded
  role string in a governance field is DNC-10's shape). **Do not copy the helper** — import it.
- IP/UA come from Nest's built-in `@Ip()` and `@Headers('user-agent')` on this handler. Two decorators, zero shared
  infrastructure, no interceptor. This is the first handler in `apps/api` to do it — say so in the PR.
- **Both are sanitised BEFORE the transaction opens.** `AuditLog.ipAddress` is `@db.Inet` (`schema.prisma:1236`): a
  malformed `X-Forwarded-For` would make the audit insert throw **inside** the transaction and roll back the whole
  import. The audit row must never be the reason the import fails, and it must still be in the same transaction — the
  only way to have both is to make the data unfailable before the tx starts.
  - IP: write it only if it matches a conservative IPv4/IPv6 shape (Express yields e.g. `::ffff:127.0.0.1`, which
    Postgres `inet` accepts); otherwise `null`.
  - UA: `String?` (unbounded text) — truncate to **512** chars anyway.

**D8 — FE reuses `ConfirmDialog` from `@pilotage/ui`. No `packages/ui` change.**
`packages/ui/src/components/ConfirmDialog.tsx` already exists, is exported from `packages/ui/src/index.ts`, takes a
`ReactNode` `description` (so the year `<select>` and the scope table go inside it), has `busy`, Escape-to-close,
backdrop click, and auto-focuses Confirm. Precedent for consuming it:
`apps/web/src/components/parent/ChildClaimsStatusStrip.tsx:237`. Do **not** hand-roll a modal, and do **not** use
`window.confirm` — the copy is a multi-line scope statement with a control in it.

## 4. Deliverable 1 — `apps/api/src/modules/calendar/calendar.controller.ts`

### 4.1 The DTO (shape only)

```ts
class SeedHolidaysDto {
  /** Calendar year to import. REQUIRED — there is deliberately no server-side fallback (see spec §3 D1). */
  @IsInt() @Min(2000) @Max(2100) year!: number;

  /** Must be `true` to write. Absent/false → 400 naming the scope. Not required when `dryRun` is true. */
  @IsOptional() @IsBoolean() confirm?: boolean;

  /** Compute and return the plan; write nothing (no events, no audit row). */
  @IsOptional() @IsBoolean() dryRun?: boolean;
}
```
- `@IsInt() @Min() @Max()` with **no** `@Type(() => Number)` is the house idiom for a JSON body number — see
  `classes.controller.ts:34`, `cycles.controller.ts:31`, `remediation/dto/admin-upsert-availability.dto.ts:32`. The
  global `ValidationPipe` (`main.ts:101`–`107`) is `{ transform: true, whitelist: true, forbidNonWhitelisted: true }`
  with **no** `enableImplicitConversion`, so a JSON number stays a number and `{ year: 'abc' }` fails `@IsInt` with a
  400. This closes **D-8**.
- `2000`–`2100`: `computeEaster` is a Gregorian Computus; the range keeps `Date` arithmetic and the `${year}-01-01`
  template strings well inside sane bounds. State the reason in a comment.
- `forbidNonWhitelisted: true` means **every** field the FE sends must be declared here. Three fields, no more.

### 4.2 The handler

```ts
@Post('events/seed-french-holidays')
@RequiresPermission('calendar.write')
async seedFrenchHolidays(
  @Body() body: SeedHolidaysDto,
  @CurrentJwt() jwt: KeycloakJwtPayload,
  @Ip() ip: string,

```

Order of operations:

1. `me = await this.users.ensureUser(jwt)`; `{ schoolId } = await this.ctx.forTenant(me.tenantId)`.

2. Build the plan from `body.year` — **one** function, used by both the dry run and the write:
   ```ts

   const plan = years.flatMap((y) => FRENCH_PUBLIC_HOLIDAYS(y)).map((h) => ({
     title: h.title,
     startsAt: new Date(`${h.date}T00:00:00Z`),
     endsAt:   new Date(`${h.date}T23:59:59Z`),
   }));                                     // length 22 — the two-year span is now stated, not discovered
   ```
3. **If not `dryRun` and `confirm !== true` → `BadRequestException`**, before any read, naming the scope:
   > `Confirmation requise : cette action écrit 22 événements (les 11 jours fériés de 2026 et les 11 de 2027). Renvoyez la requête avec confirm: true.`
   Build the numbers from `plan.length` and `years`, never from literals.
4. Sanitise `ip` / `userAgent` (D7).
5. `this.prisma.$transaction(async (tx) => …)` exactly as §3 D5, including the per-row `academicYearId` from D4.
   Row shape for each created event — identical to today's except `academicYearId`:
   ```ts
   {
     tenantId: me.tenantId, schoolId,
     academicYearId: yearFor(p.startsAt)?.id ?? null,   // ← D-4 fixed
     type: 'public_holiday', scope: 'school_wide', visibility: 'all',
     title: p.title, startsAt: p.startsAt, endsAt: p.endsAt, allDay: true,
     color: 'oklch(0.68 0.18 25)', icon: 'Flag', createdBy: me.id,

   ```
6. On `dryRun`: do the same **read** (so the preview counts are real), skip `createMany`, skip `auditLog.create`,

### 4.3 The audit row (G-AUDIT)

Written with `tx`, inside the same `$transaction` as the events. Reference implementation to copy:
`apps/api/src/modules/grades/assessments.controller.ts:281`–`299`.

```ts
await tx.auditLog.create({
  data: {
    tenantId: me.tenantId,
    actorId: me.id,
    actorRole,                     // from deriveAlertActorProvenance(jwt) — never hard-coded
    portal,                        // idem ('admin' for super_admin/school_admin)
    action: 'calendar.seed_french_holidays',
    resourceType: 'calendar_event',
    // `resourceId` is a single uuid column and this action touches up to 22 rows, so it cannot hold them.
    // Left null deliberately; the identifying facts live in `after`.
    resourceId: null,
    before: null,                  // nothing is mutated — this action only inserts
    after: {
      requestedYear: body.year,
      years,                       // [year, year + 1] — the REAL scope, both years
      planned: plan.length,        // 22
      created,
      alreadyPresent,
      academicYearIds,             // distinct non-null ids the rows were attached to
      unattachedCount,             // rows with academicYearId: null
    },
    ipAddress,                     // sanitised; null when not a valid inet
    userAgent,                     // truncated to 512
  },
});
```

### 4.4 Response contract (one shape for both the dry run and the write)

```ts
{
  ok: true,
  dryRun: boolean,
  years: [number, number],
  planned: number,            // 22
  alreadyPresent: number,     // suppressed by the existence check
  toCreate: number,           // planned - alreadyPresent
  created: number,            // 0 on a dry run; === toCreate after a successful write
  academicYearAttachment: Array<{ academicYearId: string | null; academicYearName: string | null; count: number }>,
}
```
- One shape ⇒ **one** copy builder in the FE for both the dialog and the toast. The dialog cannot promise a scope the
  write does not produce (DNC-06).
- `created === toCreate` after a successful write is an invariant worth asserting in the spec file.
- **This replaces the old `{ ok, created, skipped, year }`.** The only consumer is
  `apps/web/src/app/admin/calendar/actions.ts:52`, changed in the same PR. There is no other caller: a repo-wide grep
  for `seed-french-holidays` / `seedFrenchHolidays` matches only this controller, its compiled `dist`, `actions.ts`,
  `CalendarManager.tsx` and their `.next` build output.

### 5.2 `apps/web/src/app/admin/calendar/CalendarManager.tsx`

The trigger (`:147`) no longer writes. It **opens the dialog** and kicks off the dry run.

- Label: `Importer les jours fériés (France)…` — the ellipsis is the standard "this opens a dialog" signal, and the
  current label's silence about the two-year span is half of D-3.
- New state: `seedOpen`, `seedYear` (number), `seedPlan` (the dry-run result or `null`), `seedLoading`.
- `seedYear` defaults to the **active academic year's start year**, derived from the `years` prop
  (`years.find((y) => y.status === 'active')`) — the same source the `EventEditor` already uses at `:355`. If there is
  no active year, default to `new Date().getFullYear()` **in the UI** (a visible, editable suggestion is not a silent
  server fallback).
- On open and on every `seedYear` change: fetch the dry run, render its numbers.
- `<ConfirmDialog open={seedOpen} … busy={seedLoading || busy} tone="default">` with `description` containing:

  1. A year `<select>`, label **`Année civile de départ`**, options `seedYear − 1 … seedYear + 3`, plus the academic
     year's name as a hint when one matches.
  2. The scope statement, **rendered from `seedPlan`, never from literals**:
     > `Cette action écrit {planned} événements dans le calendrier de l'école : les 11 jours fériés de {years[0]} et les 11 de {years[1]}.`
  3. The idempotency line:
     > `{toCreate} à créer · {alreadyPresent} déjà présent(s), qui ne seront pas dupliqués.`
  4. The attachment line, from `academicYearAttachment`:
     > `Rattachement : {name} ({count})…` and, when `academicYearId` is null,
     > `{count} événement(s) ne correspondent à aucune année scolaire déclarée et n'y seront pas rattachés.`
  5. `Cette action est enregistrée dans le journal d'audit.`

### 6.1 The Prisma double — build it to make the rollback claim executable

A plain `jest.fn()` double cannot prove rollback. Build a **buffering** double:

- `$transaction(fn)` creates a `tx` whose `calendarEvent.createMany` and `auditLog.create` push into a **pending**
  buffer; runs `await fn(tx)`; on resolve, flushes pending into the committed store; on reject, **discards** it and
  re-throws.
- `tx.calendarEvent.findMany({ where })` filters the committed store by `tenantId`, `schoolId`, and the `title`/
  `startsAt` `in` lists — **honouring `tenantId` is the point**, otherwise the G-TENANT test proves nothing.
- The non-tx `prisma.auditLog.create` and `prisma.calendarEvent.create` are separate `jest.fn()`s that must record
  **zero** calls in every test — that is how "in the same transaction" is asserted rather than asserted-about.

## 10. Pre-mortem — the ways this ships broken

1. **The dialog names one year, the runtime writes two.** That is DNC-06 with a confirmation button on it, and it would
   be *worse* than today's silence because the operator would have consented to something false. Mitigation: §3 D3 —
   the numbers are server-derived; T14 pins it.
2. **The `title IN (...) AND startsAt IN (...)` prefilter is mistaken for the correctness check.** It is a
   cross-product: it can return a row whose title comes from one holiday and whose date comes from another. Suppression
   **must** be decided by the exact-pair `Set`. Getting this wrong silently skips a real holiday.
3. **`tenantId` is added to the `create` but not to the existence check.** The import then looks tenant-safe and
   silently refuses to create a holiday because *another school in another tenant* already has one. T7 exists precisely
   to fail on this.
4. **The audit insert throws inside the transaction and rolls back a valid import.** `ipAddress` is `@db.Inet`; a
   proxy-supplied garbage value is enough. Sanitise **before** the tx (§3 D7).
5. **Someone "fixes" the `confirm` friction by defaulting it in `actions.ts`.** The endpoint then behaves exactly as it
   does today with extra ceremony — DNC-12. `confirm: true` is sent from the confirmed path only, never as a default,
   never on the dry run.
6. **The existence check gains a `type: 'public_holiday'` filter** because it "looks more precise". It changes
   suppression semantics and produces duplicates against manually-created events. Keep the key as it is today, plus
   `tenantId`.
7. **`computeEaster` gets refactored** during the cleanup and Ascension drifts by a day. T15 pins four dates verified
   against the real French calendar.
8. **The audit row is skipped when nothing was created.** A pressed bulk-write button that leaves no trace is the
   finding, not the fix.
9. **The lint ceiling is raised to absorb a new warning.** Run 21 lost time to exactly this. Fix the warning.
10. **`resourceId` is stuffed with the first created id** to "not leave it null". It would make the audit trail claim
    the action touched one event. Leave it null with the comment.

## 1. Why (the defect, measured)

Three separate leaks, all shipping to the hosted deployment today.

**(a) Maildev development copy on four production-facing surfaces.** Grep over `apps/web/src` returns exactly
four hits for `Maildev` / `localhost:1080`, all of them rendered to a real user:

| File:line | What renders |
|---|---|
| `apps/web/src/app/admin/register/page.tsx:53` | `Dev: les emails sont catchés par Maildev → <a href="http://localhost:1080">localhost:1080</a>` |
| `apps/web/src/app/teacher/register/page.tsx:42` | `Dev: les emails arrivent dans Maildev → <a href="http://localhost:1080">localhost:1080</a>` |
| `apps/web/src/app/admin/users/invite/InviteForm.tsx:104` | success panel text: `Vous pouvez le suivre via Maildev (http://localhost:1080).` |
| `apps/web/src/app/admin/users/invite/InviteForm.tsx:273` | live `<a href="http://localhost:1080">localhost:1080</a>` under the submit button |

A school administrator on the hosted product is told to open a link that does not exist on their machine. It is the
single most legible "this is a demo" signal in the product (`PF-17`, audit A2 §4/§12).

**(b) Hard-coded credential fallbacks.** `apps/api/src/shared/keycloak/keycloak-admin.service.ts:42-47`:

```ts
this.baseUrl        = config.get<string>('KEYCLOAK_URL')            ?? 'http://localhost:8180';
this.realm          = config.get<string>('KEYCLOAK_REALM')          ?? 'pilotage-scolaire';
this.masterUser     = config.get<string>('KEYCLOAK_ADMIN_USER')     ?? 'admin';
this.masterPassword = config.get<string>('KEYCLOAK_ADMIN_PASSWORD') ?? 'admin';
```

These are the credentials the API uses to mint an `admin-cli` token against the Keycloak **master** realm — the most
privileged thing this codebase does. **Measured, and this is the load-bearing part of the story:** neither
`infra/docker-compose.yml` (the `x-app-env` anchor, lines 15-40) nor `infra/docker-compose.prod.yml` (the `api`
service, lines 59-65) passes `KEYCLOAK_ADMIN_USER` or `KEYCLOAK_ADMIN_PASSWORD` to the API at all. Only the one-shot
`seed` service does (prod compose lines 132-135). So **the production API is authenticating as `admin`/`admin`
today, purely through these two fallbacks**, and nothing anywhere says so. A fallback that is silently load-bearing
in production is exactly `PF-54`.

**(c) Nothing detects a reintroduction.** `scripts/ci-gate.sh` has ten stages and `.github/workflows/ci.yml` mirrors
them; not one reads application source for dev artefacts. The four Maildev strings survived every gate the V3
programme has built so far.

## 2. Scope — what this slice ships

A thin vertical slice: the rendered copy (web) + the configuration wall (api) + the gate that keeps both closed.

```ts
export const SUPPORT_EMAIL =
  process.env.NEXT_PUBLIC_SUPPORT_EMAIL ?? 'support@pilotage-scolaire.app';
```

`support@pilotage-scolaire.app` is **already** hard-coded at `apps/web/src/app/admin/register/page.tsx:38-39`; this

### 2.2 BE — turn the fallbacks into required configuration that fails fast

**New `apps/api/src/shared/config/config-preflight.ts`** — house style is already set by
`shared/migrations/migration-preflight.ts` and `shared/release/release-preflight.ts`: an exported error class + a pure
`assert*` function taking its inputs as arguments so it is testable without DI, without a network and without Nest.

```ts
export const REQUIRED_ENV = ['KEYCLOAK_URL', 'KEYCLOAK_ADMIN_USER', 'KEYCLOAK_ADMIN_PASSWORD'] as const;

export class MissingConfigError extends Error { readonly missing: string[]; /* … */ }

/** Lève en nommant CHAQUE variable absente (jamais la première seulement). */
export function assertRequiredConfig(env: NodeJS.ProcessEnv, logger?: ConfigLogger): void
```

Rules the implementation must honour:

- **Names every missing variable in one throw**, not the first one. An operator fixing one key at a time across three
  deploy cycles is the failure mode this avoids.
- The message states *what breaks*: « L'API ne peut pas s'authentifier auprès de Keycloak sans ces variables. Elle
  refuse de démarrer plutôt que de retomber sur des identifiants par défaut (`admin`/`admin`) — voir S-E06-1 / PF-54. »
- A variable set to `''` or a whitespace-only string counts as **missing** (an empty env var in compose is the common
  real-world shape).
- **No bypass flag.** No `SKIP_CONFIG_CHECK`, no `ALLOW_DEFAULT_CREDENTIALS`, no `NODE_ENV` escape hatch. DNC-10.
  (Unlike `MIGRATION_PREFLIGHT`, there is nothing legitimate to opt out of: a developer without these variables has a
  broken `.env`, and §2.4 fixes `.env.example` so nobody hits it by accident.)
- `KEYCLOAK_REALM` is **deliberately not required** — it is neither a credential nor a dev URL, it is
  `pilotage-scolaire` in `.env.example`, in `x-app-env` and in the prod override, and a product default for it is
  honest. Say so in a comment so a later reader does not "fix" it.

**Wiring:**

- `apps/api/src/main.ts` — call `assertRequiredConfig(process.env, logger)` **before**
  `assertMigrationsClean(...)`, i.e. as the first preflight (a missing credential should not wait behind a DB round
  trip). Keep it inside `bootstrap()`, where the two existing preflights live: `scripts/boot-check.js` constructs the
  module graph from `dist/app.module.js` and does **not** execute `main.js`'s bootstrap, so stage 7 of the gate is
  unaffected — the same reason `assertMigrationsClean` (which needs a database) does not break it today.
- `apps/api/src/shared/keycloak/keycloak-admin.service.ts` — remove all four `??` fallbacks. Resolve the three
  required values through a small `requireEnv(config, name)` local helper that throws `MissingConfigError` **at the
  point of use** (inside `getToken()` / `adminFetch()`), not in the constructor. Two reasons, both concrete: the
  constructor runs during Nest DI, so throwing there would fail `scripts/boot-check.js`; and a lazy required read
  means there is no fallback even on a code path that somehow skips `main.ts`. Keep
  `config.get('KEYCLOAK_REALM') ?? 'pilotage-scolaire'`.
- `apps/api/src/shared/auth/jwt.strategy.ts:25` — same variable, same treatment: `?? 'http://127.0.0.1:8180'` goes.
  `KEYCLOAK_URL` is required as of this story, so the fallback is now provably dead code sitting on the auth path.
- `apps/api/src/shared/keycloak/keycloak.module.ts:25` — the dev-only SMTP bootstrap (`onModuleInit`, already
  short-circuited for production at line 22) carries `?? 'maildev'`. Replace with an explicit skip:
  `const host = this.config.get<string>('MAIL_HOST'); if (!host) { this.logger.log('SMTP bootstrap ignoré (MAIL_HOST absent).'); return; }`.
  Behaviour in dev is unchanged (`x-app-env` sets `MAIL_HOST: maildev`); this removes the last `maildev` **string
  literal** in `apps/api/src`, which §2.3 rule 2 requires.

### 2.3 The gate — a production-artefact string scan

**New `scripts/production-artefact-check.js`** (plain Node, no dependencies, same shape as
`scripts/web-artifact-check.js` / `scripts/runtime-engines-check.js`: prints every hit, `process.exit(1)` on any).

**Scan roots:** `apps/web/src`, `apps/api/src`, `apps/worker/src`.
**Excluded:** `*.spec.ts(x)`, `*.test.ts(x)`, `__tests__/`, `__fixtures__/`. (Measured: every `Dupont` hit inside
`apps/*/src` today is a test fixture; scanning specs would produce noise with no production meaning.) Everything
outside `apps/*/src` — `infra/`, `scripts/dev.sh`, `.env*.example`, `docs/`, `prisma/` seeds — is **out of scope by
design**: those are the dev stack, and a gate that flags `infra/docker-compose.yml` for defining Maildev is a gate
nobody will keep.

**Tier A — zero tolerance, no allowlist, no ratchet.** Any hit ⇒ exit 1, printing `file:line` and the matched text.

| # | Rule | Pattern | Roots |
|---|---|---|---|
| A1 | `maildev-rendered` | `/maildev/i` | `apps/web/src` (whole file — web is the artefact a user sees, comments included) |
| A2 | `maildev-literal` | `maildev` inside a quoted string literal (`/['"\`][^'"\`]*maildev/i`) | `apps/api/src`, `apps/worker/src` |
| A3 | `maildev-port` | `/(localhost\|127\.0\.0\.1):1080/` and `/\bhttp:\/\/[^\s"'\`]*:1080/` | all three roots |
| A4 | `seed-identity` | reviewed literal list: `Sophie Dupont`, `M. Lefebvre`, `mme.dupont@voltaire.fr`, `voltaire-demo`, `Demo!2024Pilotage`, `Changeme123!` (case-insensitive) | all three roots |
| A5 | `credential-fallback` | `/\?\?\s*['"\`](admin\|password\|changeme\|secret)['"\`]/i` | all three roots |
| A6 | `dev-service-url` | `/https?:\/\/(localhost\|127\.0\.0\.1):(1080\|8025\|9000\|9001\|5432\|6379)/` | all three roots |

Rules A2 and A5 are string-literal-shaped **on purpose**: `apps/api/src` and `apps/worker/src` legitimately explain
Maildev in doc comments (`mailer.service.ts:13-14,35`, `notifications-email.processor.ts:13`,
`keycloak.module.ts:20`, `register.controller.ts:53`). Deleting accurate documentation to satisfy a regex would make
the codebase worse. A comment cannot contain `?? 'admin'`, so A5 needs no such carve-out.

**Verified against the checkout:** after §2.1 and §2.2 land, every Tier-A rule returns **zero** hits. Before them,
A1/A3 fire 4× and A5 fires 2×. That is the "both directions" proof, and it is real, not constructed.

**Tier B — ratcheted residual inventory.** `scripts/production-artefact-baseline.json`, per-file counts of the
dev-URL fallbacks this slice deliberately does **not** fix (measured today, after §2.2's four removals):

- `apps/web/src`: `auth.ts` ×2, `PortalLoginForm.tsx` ×2, `api-client.ts` ×1, `app/api/proxy/[...path]/route.ts` ×1,
  `app/parent/register/actions.ts` ×1, `app/{admin,teacher,parent}/settings/page.tsx` ×1 each,
  `app/admin/imports/new/ImportWizard.tsx` ×1
- `apps/api/src`: `main.ts` ×3 (CORS default + two startup log lines), `shared/queue/queue.module.ts` ×1,
  `modules/identity/invite.controller.ts` ×1
- `apps/worker/src`: `shared/queue/queue.module.ts` ×1, `shared/mail/mailer.service.ts` ×2 (`'localhost'`,
  `no-reply@pilotage.local`), `modules/notifications-digest/notifications-digest-cron.service.ts` ×1,
  `modules/parent-digest/parent-digest-cron.service.ts` ×1,
  `modules/notifications-email/notifications-email.processor.ts` ×1, three `*.template.ts` doc comments ×1 each

Ratchet semantics, identical in both directions to `scripts/lint-ratchet.js` — **the number can only go down**:
a file not in the baseline with a hit ⇒ exit 1; a count **above** its baseline ⇒ exit 1; a count **below** its
baseline ⇒ exit 1 with « abaissez la ligne de base ». `--update` rewrites the baseline and **refuses to write when
any Tier-A rule fires** (the `web-artifact-check.js` rule: never freeze a broken tree into the reviewed inventory).

**No bypass.** No `SKIP_*` / `ALLOW_*` / `FORCE_*` env read anywhere in the script (`web-artifact-gate.spec.ts:150`
asserts this shape for its sibling; do the same here).

**A `--root <dir>` argument** exists so the spec can run the real scanner over a temporary fixture tree. It cannot
skip anything — it only points the same rules elsewhere — and §3 asserts that neither `ci-gate.sh` nor `ci.yml`
passes it.

**Wiring (both files, or they drift — S-E02-2 AC-4):**

- `scripts/ci-gate.sh`: a new stage **immediately after stage 0 (`runtime engines`) and before `prisma generate`** —
  `run_stage "production artefacts (string scan)" node scripts/production-artefact-check.js`. It reads source only,
  so it needs no install, no client and no build, and it therefore also runs under `--quick`. Carry a comment
  explaining `PF-17`/`PF-54` and why it is early (it fails on the diff, not after a ten-minute build).
- `.github/workflows/ci.yml`: the same command as a step of the **`lint`** job (source-only, no build needed), with
  the matching comment.

### 2.4 Configuration and infrastructure (this is what stops the change breaking the deploy)

Making the variables required is only safe if the stack supplies them. All four edits are mandatory:

- **`infra/docker-compose.yml`**, `x-app-env` anchor (after `KEYCLOAK_REALM`, line 22):
  `KEYCLOAK_ADMIN_USER: admin` / `KEYCLOAK_ADMIN_PASSWORD: admin`, with a comment saying these must equal the
  `keycloak` service's own `KEYCLOAK_ADMIN`/`KEYCLOAK_ADMIN_PASSWORD` (lines 118-119). Dev behaviour is byte-identical
  to today — the difference is that the value is now *stated* instead of hidden in a `??`.
- **`infra/docker-compose.prod.yml`**, the `api` service: 
  `KEYCLOAK_ADMIN_USER: ${KEYCLOAK_ADMIN_USER:?KEYCLOAK_ADMIN_USER est requis (S-E06-1/PF-54) — doit correspondre à l'admin master Keycloak existant}`
  and the same for `KEYCLOAK_ADMIN_PASSWORD`. Compose's `:?` fails the *deploy command* with a named variable, which
  is a better failure than a container crash-looping.
  **Do NOT touch the `keycloak` service's own `KEYCLOAK_ADMIN`/`KEYCLOAK_ADMIN_PASSWORD`**, and do not rotate any
  credential: those env vars only create the bootstrap admin on a *first* start, so changing them against the existing
  hosted Keycloak database would leave the API unable to authenticate. This story makes the credential *explicit*; it
  does not rotate it. (Rotation is an operator action — record it, do not perform it.)
  The `seed` service's literal `admin` values (lines 132-135) are left exactly as they are: out of scope, and covered
  by the S-E02-4 seed guard.
- **`.env.example`**: add `KEYCLOAK_ADMIN_USER=admin` and `KEYCLOAK_ADMIN_PASSWORD=admin` next to `KEYCLOAK_URL`
  (line 26) — measured: they are **absent** today, which is why the fallback existed.
- **`.env.prod.example`**: add both keys with a comment stating that they must match the master admin of the
  **already deployed** Keycloak, and that changing them here does not rotate anything — rotation is a separate
  operator action performed in Keycloak first.

## 5. Explicitly NOT claimed (write this into `PROGRESS.md`)

- **`PF-17` is only half closed.** Seed author labels already written to the **hosted database** stay there. Deleting
  data on a hosted deployment is routine **STOP condition #3** (destructive action on production data) and needs an
  operator. This slice stops the *code* from carrying them and stops new ones arriving.
- **The scan reads source, not the emitted bundle.** The epic's AC-1 says "production build". A source scan fails on
  the pull request instead of ten minutes later, and agents are forbidden from building — but it would not catch a
  string injected by a dependency or a generated file. Extending the same rule set over `.next/server` and `dist/` in
  the post-build stage is carried to `S-E06-2`/hardening.
- **The residual dev URLs are inventoried, not fixed.** ~22 `?? 'http://localhost:…'` fallbacks remain (§2.3 Tier B).
  They are held by a one-way ratchet so the number can only fall; removing them means making
  `NEXT_PUBLIC_KEYCLOAK_URL` / `NEXT_PUBLIC_API_URL` / `WEB_BASE_URL` / `REDIS_URL` required, which is its own story
  (build-time inlining of `NEXT_PUBLIC_*` makes it materially different work).
- **No credential is rotated.** `admin`/`admin` remains the Keycloak master credential on the hosted stack; this story
  makes it *declared* rather than *implicit*. Rotation is an operator action, recorded as such.

## 7. Pre-mortem — the four ways this breaks production


## 4. `scripts/link-integrity-check.js` — the contract

Additive. The four existing verdicts, the ratchet, the `--update` refusals and the no-bypass posture (DNC-10: no env
var read anywhere, only `--update`/`--help`) are unchanged. Keep the file's `if (require.main === module) main();`
guard and its side-effect-free `require`.

### 4a. New pure exports (all must be exported; the guard spec drives them)

```
stripCommentsPreservingLines(source)        → source with // and /* */ blanked (length + newlines preserved),
                                              string and template literals left intact
resolveDeclaredUnion(name, source)          → string[] | null      (null = unresolvable, never a guess)
expandTemplateTarget(raw, source)           → { kind: 'expanded',  expansions: string[] }
                                              | { kind: 'shape',  pattern: string, vars: string[] }
classifyPattern(pattern, routes)            → 'shape-alive' | 'shape-dead'
extractTemplateLinks(srcDir)                → Array<{ raw, file, line, kind, expansions?, pattern?, vars? }>
extractLiteralLinks(srcDir)                 → UNCHANGED SHAPE: Array<{ target, file, line }>
                                              = comment-stripped quoted literals ∪ every union expansion
```

`resolveDeclaredUnion` accepts exactly three declaration forms, searched in the **same file** (comment-stripped):

- **(a) inline union** — `portal: 'admin' | 'teacher' | 'parent'` (property or parameter). Matches
  `UserMenu.tsx:17` and `TopbarUserMenuProps` at `TopbarUserMenu.tsx:9`.
- **(b) named alias** — `portal: AccountPortal` + `type AccountPortal = 'a' | 'b'`.
- **(c) `keyof typeof C`** — `portal: keyof typeof PORTAL_REQUIRED_ROLES` + `const PORTAL_REQUIRED_ROLES = { admin: …, teacher: … }`. This is `middleware.ts:129`'s form; supporting it is **recommended**, not required.

**Ambiguity is unresolvable, never a pick.** If a file yields **more than one** candidate union for the same name, the
site is reported as `shape` with `vars` naming the variable — resolving it by proximity would silently
under-approximate, and an under-approximation is a silent drop wearing a different hat. Measured: **no file in
`apps/web/src` triggers this** after §5b, so it costs nothing today and is pinned by a synthetic guard case.

### 4b. What happens to each template row — nothing is dropped

1. Mask interpolations (**T1**), strip `?`/`#` outside masks, unmask.
2. If nothing interpolated remains → an ordinary literal target (this is how `/teacher/messaging` surfaces).
3. Else if every interpolation is a whole segment **and** every variable resolves (4a) → **expand** the cross-product;
   each expansion is classified by the **existing** four-verdict `resolveTarget`, so a dead expansion **FAILS** and a
   captured expansion fails unconditionally.
4. Else → **`shape`**: build the pattern (whole-segment interpolations → `*`; a mixed segment truncates per **T3**) and
   run `classifyPattern`. `shape-dead` (no emitted route has that shape at that depth) **FAILS unless baselined** in
   the new `deadShapes` section; `shape-alive` is reported, never silent.
5. A `/`-leading backtick string that cannot be parsed at all (unterminated at EOF) is an **`unparsed`** row and a
   **structural failure** — never a skip (DNC-08). Measured today: 0.

**The anti-drop invariant, asserted in code and in the guard:**
`templateRows === expanded + shape + unparsed`. If it does not hold, the run is a structural failure. This is the
run-10 lesson made executable: a check that discovers nothing must not pass.

`classifyPattern` is deliberately **weak-matching** — a `*` may align to a literal segment as well as to a `[param]`.
Requiring alignment to a dynamic segment would make `` `/${portal}/settings` `` report dead on a correct repository.
It therefore proves *"a route of this shape and depth exists"*, and that is exactly what it is allowed to claim (§10).

### 4d. The `prefix-constant` class, and why it cannot hide a real href

A `dead` entry may carry `"class": "prefix-constant"` (the field the guard spec's `BaselineEntry` interface already
anticipates at `link-integrity-gate.spec.ts:109`). Such a row is counted as `prefixConstants`, **not** as `dead` debt —
this is the mechanism `PF-93`'s own text prescribes (*"the follow-up is a `class: \"prefix-constant\"` tag so the
ceiling can reach zero"*).

**Definition, narrow on purpose:** a target that is referenced **only as a string prefix** and that **nothing will ever
create**. `/api/auth` qualifies (`middleware.ts:35`; `/api/auth/[...nextauth]` is a catch-all needing ≥1 segment, so the
bare namespace cannot resolve **by construction**). `/favicon` qualifies (asset prefix for `/favicon.ico`).

**The refusal (AC-5).** The extractor tags each reference with `context: 'href-like' | 'plain'`, where `href-like` means
the reference's line matches `href|<Link|redirect|router\.(push|replace)|NextResponse\.redirect|callbackUrl|new URL\(`.
If **any** reference to a `prefix-constant` target is `href-like`, the gate emits

```
PREFIX-CONSTANT CLASSIFICATION REFUSED — <target> is referenced as an href at <file>:<line>.
        The class is for a string used only as a prefix. It is not a quieter baseline.
```

and **fails**. Both `prefix-constant` rows keep `reason` **and** `finding: "PF-93"` (provenance), so the existing
"every entry carries a reason and an owning finding" validation (`:549`) is **not relaxed**.
Proven in the negative against real code: `/admin/reports` is referenced at
`components/shell/sidebar-items.ts:175` as `href: '/admin/reports'` → tagging it `prefix-constant` must be **refused**.

### 1b. A pure route-existence check cannot see this defect — which is why the gate is the point of the story

`/admin/classes/new` **resolves**. It resolves to `/admin/classes/[id]`. Any gate that asks "does this link match a
route?" answers *yes* and stays green while the link crashes. The rule that catches it is a different one:
**a fully-literal link target that matches a route only because a `[param]` swallowed a literal segment.** A
literal in a dynamic slot means the author intended a static page. That failure class — call it **DYNAMIC
CAPTURE** — is the non-obvious half of this slice, and it is the half that stops the class of defect rather than
one instance of it.

### 3.1 The API contract (already exists — do not add an endpoint, do not weaken a check)

## 4. Deliverable 2 — `scripts/link-integrity-check.js` (the gate)

### 4.1 The one non-negotiable design rule

It reads the **EMITTED** artefact — `apps/web/.next/app-path-routes-manifest.json` — **not** the `app/` directory
tree. Same reason as `scripts/web-artifact-check.js`, which you should read **first** (lines 1-76 state the reason
in full) and imitate closely. `PF-82` exists precisely because a sibling gate reads source instead of the artefact;
do not reproduce it at a new address. A route that exists in `app/` and was not emitted is exactly the state in
which a source-reading gate reports "the link is fine".

### 4.2 Shape to copy from `scripts/web-artifact-check.js`

- Discovery **from the filesystem**, never from the baseline (`discoverNextApps()`, lines 100-109) — a second Next
  app added tomorrow must **fail** this gate until it is entered deliberately.
- `--update` rewrites the reviewed baseline and **refuses to run from a structurally broken artefact**
  (lines 329-346): missing `.next`, missing / empty `app-path-routes-manifest.json` → refuse to write, exit 1.
  A baseline recorded from a broken build freezes the breakage into the reviewed inventory.
- **Structural failures `--update` can never accept.**
- **No bypass flag** (DNC-10). No `SKIP_*`, no `ALLOW_*`, no `NODE_ENV` branch, anywhere in the file.
- A `$comment` at the top of the written baseline saying what it is and how to regenerate it
  (`BASELINE_COMMENT`, lines 360-366).
- `module.exports = { … }` + `if (require.main === module) main();` — the idiom already used by
  `scripts/restore-drill.js:1483,1497`, `scripts/compose-invocation-check.js:578`,
  `scripts/runtime-engines-check.js:402`, `scripts/observability-check.js:859`. **This is required**, because §5
  drives the classifier over synthetic inventories and there must be no flag that lets a fixture in.

### 4.3 What it extracts (scope of "literal internal link")

Source set: `apps/web/src/**/*.{ts,tsx}`, walked from the filesystem.

In scope: a **fully-literal** string (single- or double-quoted; **never** a template literal) whose value starts
with `/`. Template literals are correctly and deliberately excluded — an interpolated href is a dynamic target and
a literal in a dynamic slot is the thing this gate is looking for, not the thing it should chase.

Exclusions, each of which must be named in the file header with its reason:
`/` itself · anything under `/_next` · a last segment containing a `.` (asset paths such as `/favicon.ico`) ·
query string and `#fragment` stripped before matching · `//` protocol-relative and any string containing `://`.

The probe that produced §1c found **102** distinct targets under these rules. A run producing an order of
magnitude fewer means the extractor is broken, not that the repo got better — see the vacuity test in §5.

### 4.4 Resolution against the emitted inventory

Build a matcher per route template from the manifest **values**:

- `(group)` route-group segments stripped (they never appear in a URL).
- `[param]` matches exactly **one** non-empty segment.
- `[...slug]` matches **one or more** segments.
- `[[...slug]]` matches **zero or more** segments.

Classify every extracted target:

| Class | Rule | Verdict |
|---|---|---|
| **ALIVE** | matches a route template with **no** dynamic segment consuming a literal segment (i.e. an exact literal route) | ok |
| **DYNAMIC CAPTURE** | matches **only** through a `[param]` / `[...slug]` swallowing a literal segment | **FAIL, unconditionally. Not baselineable.** |
| **DEAD** | matches nothing | FAIL unless present in the baseline with a `reason` **and** an owning `finding` |

The file header must state, in prose, **why (b) exists and why a route-existence check cannot see it** — using
`/admin/classes/new` → `/admin/classes/[id]` as the worked example. That is the half a reader will otherwise
delete as redundant.

### 4.5 Ratchet discipline

is the wording to imitate — *"may only ever SHRINK"*, *"every entry carries the finding id that owns the fix, so
nothing here is 'silenced' — it is queued"*):

- a **new** dead target → FAIL;
- a baselined target that is **now alive** → **FAIL** (remove the entry and close the finding; a ratchet that never

- **any** dynamic capture → FAIL, and `--update` refuses to record it;

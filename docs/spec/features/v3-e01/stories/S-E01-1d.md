## 1. The slice in six sentences

The application connects as `pilotage`, which **owns** all 55 tables, so it is exempt from every RLS policy shipped by
`S-E01-2b`/`2c`/`2d`/`1b`/`1c` — the policies are complete and enforce nothing on the running system. Flipping
`DATABASE_URL` to `app_user` is all-or-nothing: 792 Prisma call sites would have to set the tenant GUC on the same day,
across 223 files, or return zero rows. This slice adds a **second Prisma client bound to `DATABASE_URL_APP`** (the
`app_user`, non-owner, RLS-subject connection that already exists in `.env:20` and `.github/workflows/ci.yml:170` and
that **nothing in application code reads**), plus an ambient tenant scope that opens the existing, proven
`PrismaService.withTenant` on it. The owner connection keeps serving the other 782 call sites, unchanged and working.
The `calendar` module's seven controller call sites move inside a scope, so `calendar_event` reads and writes are
refused **by PostgreSQL** rather than by an application `if`. The cutover therefore stops being an event and becomes a
per-module migration, and `AC-9 CUTOVER READINESS` is redefined — consciously, once — from *"how many times does the
string `.withTenant(` appear"* to *"how many Prisma call sites are inside a tenant scope, and is every site outside one
enumerated with a reason."*

## 3. Functional requirements

- **FR1** A tenant scope module exists at `apps/api/src/shared/prisma/tenant-scope.service.ts` (+ `tenant-scope.ts` for
  the `AsyncLocalStorage` store), exported from `PrismaModule` (which is `@Global()`), carrying `{ tenantId, tx }` for
  the duration of one callback.
- **FR2** Opening a scope calls the existing `PrismaService.withTenant` / `runWithTenant`. **`set_config`, its bound
  parameter, its `nullif` and its read-back are not reimplemented** (`ADR-032 §D1–D3`).
- **FR3** A second `PrismaClient` is constructed **lazily, once**, from `process.env.DATABASE_URL_APP`. Never from a
  rewritten `DATABASE_URL`; never from a literal; no other variable is consulted.
- **FR4** When `DATABASE_URL_APP` is unset or empty, the scope still opens, **on the owner client**, and the degraded
  state is named in three places (§4.3). It is never silent and never green.
- **FR5** The calendar controller's seven Prisma call sites (§2.3) run inside a scope, on `tx`, keeping their explicit
  `tenantId` in every `where`.
- **FR6** `cutoverReadiness` / `cutoverVerdict` count **scoped call sites**, not `.withTenant(` occurrences, and the
  affirmative branch additionally requires every unscoped site to be enumerated (§5).
- **FR7** `scripts/tenant-scope-check.js` proves AC-2 by execution against a real PostgreSQL as `app_user`, and is wired
  into `scripts/ci-gate.sh` and `.github/workflows/ci.yml` with no skip path (`DNC-08`).
- **FR8** `ADR-048` records the decision set (§7).

## 4. Design — the decisions, and why each is the one to take

### 4.1 The scope: `AsyncLocalStorage`, opened explicitly, never ambient

```ts
// apps/api/src/shared/prisma/tenant-scope.service.ts  (shape, not final code)
@Injectable()
export class TenantScopeService {
  async run<T>(tenantId: string, fn: (tx: Prisma.TransactionClient) => Promise<T>): Promise<T>
  /** The active transaction client, or `undefined` outside a scope. */
  current(): { tenantId: string; tx: Prisma.TransactionClient } | undefined
}
```

`run` opens `withTenant` on the **scoped client** (§4.2) and stores `{ tenantId, tx }` in an `AsyncLocalStorage` for the
duration of `fn`. The `AsyncLocalStorage` is what lets a private helper (`resolveParentClassSectionIds`) reach `tx`
without threading a parameter through three signatures; the **explicit `run(...)` at the handler** is what keeps the
seam greppable, per `S-E04-1` (§2.6).

**Why not a Nest interceptor** (and this is a correction to the brief, made by measurement): an interceptor opens the
scope for the *whole request*, which would hold a Prisma **interactive transaction** open across
`users.ensureUser(jwt)` (a Keycloak-fed upsert), `ctx.forTenant(...)` and `studentAccess.scopeForUser(...)` — none of
which can run inside it (§4.4) — and would blow the documented 5 s `timeout` / 2 s `maxWait`
(`prisma.service.ts:276-282`) on the first slow identity sync. It would also make the seam **ambient by default**,
which is precisely what AC-4 asks us to disprove. Rollback becomes "revert the `run(...)` call sites", which is a
smaller and more honest statement than "remove the interceptor".

### 4.2 The second client

- Lazily constructed on first `run(...)`, memoised on the service, disconnected in `onModuleDestroy`.
- URL: `process.env.DATABASE_URL_APP` **verbatim**, passed as `datasourceUrl` to `new PrismaClient({ datasourceUrl })`.
- **Pool size: `connection_limit=5`, appended only if the URL does not already carry the parameter**, plus
  `pool_timeout=10`. Stated reason: the scoped surface is one low-traffic module (a month of calendar events for one
  school, ≤ 2 statements per request) and every scoped statement holds a pooled connection for the life of an
  interactive transaction; 5 bounds the second pool's cost against the owner pool's Prisma default
  (`num_cpus × 2 + 1`) while leaving headroom for the parent branch's two round trips. The effective value is logged
  once at construction, **with the password masked and the address never printed in full** (precedent:
  `scripts/lib/default-database-url.js`'s closing rule). If the operator sets `connection_limit` in `.env`, theirs wins
  and the log says so.
- `.env.example` gains `DATABASE_URL_APP` with a comment naming what it is for. **`.env` itself is gitignored and is
  not edited by this diff.**

### 4.3 The degraded mode — the single most dangerous line in the slice

`DATABASE_URL_APP` unset ⇒ the scope opens on the **owner** client. Behaviour is identical to today (owner bypasses
RLS), which is why it is safe; **saying so is what stops it from being `DNC-10`.** It must be named in three places,
and there is no flag, no `NODE_ENV` branch, no `ALLOW_*`/`SKIP_*` that changes any of them:

1. **One boot-time log line**, `Logger.warn`, emitted **once** at the first scope open (not per request):
   `tenant scope: DEGRADED — DATABASE_URL_APP is unset, the tenant scope runs on the OWNER connection and RLS is NOT
   enforced (S-E01-1d / ADR-048)`. No URL, no credentials, no role name.
2. **A Prometheus gauge** on the existing dedicated registry (`apps/api/src/modules/metrics/metrics.registry.ts`):
   `pilotage_tenant_scope_enforced` — `1` enforced, `0` degraded. Constant cardinality, **no labels carrying an
   identifier** (that file's rule 1), and `/metrics` is never published by nginx (its rule 2). This is the observable
   verdict.
3. **The gate**: `scripts/tenant-scope-check.js` fails, loudly and by name, if it cannot connect as a role that is
   **not** an owner of the tables under test (§6, `DNC-08`).

**Not `/readyz`, and not `/version` — decided, with the reason.** `/readyz` down on a degraded scope would take PROD
offline the first time an operator's `.env` lacks the variable: a self-inflicted outage, not a defence. `/version`'s
own docblock (`health.controller.ts:35-41`) says the manifest carries *« aucune donnée de tenant, aucune chaîne de
connexion »*; a public, unauthenticated posture oracle is a widening of that surface for no operator benefit the gauge
does not already give.

### 4.4 What stays OUTSIDE the scope, enumerated with reasons

This list is not a residual — it is part of the design, and `cutoverReadiness` must consume it as data (§5.2).

| Call site | Why it is outside |
|---|---|
| `users.ensureUser(jwt)` (`calendar.controller.ts:161`, `:203`, `:215`, `:248`, `:288`) | **It resolves the tenant.** A scope cannot be opened before its `tenantId` is known — the chicken-and-egg of identity resolution. Owned by `S-E01-1`; recorded as `PF-199`. |
| `ctx.forTenant(...)` (`:162`, `:204`, `:289`), `studentAccess.scopeForUser(...)` (`:323`) | Shared services with many other callers; converting them is a different module's slice. They read `school` / `student` on the owner connection, exactly as today. `PF-199`. |
| `calendar-seed.service.ts:128/:169/:173/:211` | The seed opens **its own** `$transaction` and performs a **bulk** import (22 events + one audit row). Nesting it inside an interactive transaction is what `prisma.service.ts:276-282` forbids, and `Prisma.TransactionClient` has no `$transaction`, so it would not compile anyway. Deliberate, recorded as `PF-198`. |
| every call site in the other 222 files | Untouched. AC-4. |

### 4.5 Nested scopes — refuse on mismatch, reuse on match (AC-5)

`current()` is consulted at the top of `run(...)`:

- **No active scope** → open one.
- **Active scope, same `tenantId`** → **reuse it**: pass the existing `tx` to `fn`, open nothing. Reason: Prisma would
  otherwise open a **second** interactive transaction on **another pooled connection where the GUC is not set**, and
  every statement in it would silently return zero rows — the outage shape, arriving as a "bug in the feature".
- **Active scope, different `tenantId`** → **throw** a `TenantScopeError` naming both scopes and emitting nothing else.
  Reason: a second tenant id inside an open scope is either a bug or a confused-deputy attempt; it is not
  representable, so it fails loudly (`DNC-08`). It must **not** be silently reused, and it must **not** open a nested
  scope.

### 4.6 What must NOT change

- **Keep the application `if`** at `:217` and `:250`. Defence in depth; removing it would be a visibility change dressed
  as a fix, and it is the only guard on the owner connection and in degraded mode.
- **Keep the explicit `tenantId`** in every `where`. RLS is a floor, not a replacement for the filter.
- **`calendarVisibilityWhere` (`:65`) is unchanged, byte for byte**, and `calendar.access.spec.ts` stays green
  untouched (G-AUTHZ).
- **Do not switch `DATABASE_URL`.** The global flip stays blocked on `PF-185` (`register.controller.ts:365` needs
  INSERT/UPDATE on `tenant`) and `PF-197` (six raw-SQL sites, two of them boot-time `CREATE UNIQUE INDEX` that swallow
  their own failure).
- **No migration.** `scripts/restore-drill-baseline.json` therefore needs no entry (`PF-80`). If implementation
  discovers a migration is needed, **stop and say so** rather than adding one late.

## 5. The honest redefinition of AC-9

### 5.1 The counter changes from a string count to a coverage attribution

`.withTenant(` occurrences are the wrong unit: five `run(...)` calls cover seven call sites, so the old counter would
under-report by construction, and a helper that opens no scope but sits inside one would be invisible to it. Replace
it with an attribution pass, kept **pure and spec-drivable** exactly as `cutoverVerdict` and `privilegesForVerb` are:

1. For each file, locate every scope-opening call (`\.(?:withTenant|run)\s*\(` on the scope service / `PrismaService`),
   then brace-match from its opening parenthesis to find the callback's byte range.
2. A Prisma call site whose match index falls inside such a range is **covered**; otherwise **uncovered**.
3. `scopedCallSites` replaces `withTenantCallers` in the returned shape (`:2071`) and in the verdict.

### 5.2 The affirmative branch requires enumeration, not just a ratio

`cutoverVerdict` gains a third input: `enumeratedOutsideScope`, a **named, in-source constant** listing the file globs
that are legitimately outside a tenant scope — bootstrap (`main.ts`, `config-preflight.ts`), migrations and seeds,
health, the release/migration-state readers, the worker, and the entries of §4.4 **each with its reason string**. The
affirmative branch fires only when `scopedCallSites + enumeratedCallSites === prismaCallSites`. Anything else stays a
`[LIMIT]`.

**The trap this slice must not fall into:** manufacturing a green by widening the enumeration. The enumeration is a
list of *reasons*, and a reason that says "not converted yet" is not a reason — it belongs in the uncovered count. It
is expected and correct that this slice lands with the verdict still a **`[LIMIT]` naming a new ratio** of roughly
`7 / 792` covered. **A truthful `[LIMIT]` is the deliverable; a green here would be the finding.**

### 5.3 The gate spec moves with it

`apps/api/src/shared/quality/tenant-adversarial-gate.spec.ts` must, in this diff:

- replace the source-text assertion at `:1045` (`withTenantCallers === 0`) with one pinning the **new** wall — the
  `scoped + enumerated === total` equality — so the pin still fails if someone reintroduces a tunable floor;
- keep and re-express the four branch cases (`:923`, `:930`, `:940`, `:946`), including the one that matters most:
  **a single covered site out of 792 is still a `[LIMIT]`**, now expressed with `scopedCallSites: 1`;
- add a case where `enumeratedCallSites` is inflated to close the gap **without** covering anything, asserting the
  verdict is **not** affirmative when the enumeration lacks a reason string. That is the "manufactured green" mutant,
  and it must be shown red.

     (Copied from `scripts/rls-isolation-check.js`'s opening assertions — without it, a DSN accidentally pointed at

     implementation that forgot to set the GUC fails here.
  5. **Cleanup executed and verified independently of the script that asserts it**; the live `pilotage` database is

- **AC-3** With `DATABASE_URL_APP` unset, the scope still opens on the owner client, and the degraded state is named by

- **AC-5** Nested scopes behave as §4.5 — **reuse on same tenant, throw on a different tenant** — both asserted, with

- **AC-6** **Rollback stated and true:** reverting the `run(...)` call sites in `calendar.controller.ts` returns the

## 7. `ADR-048` — what it must record

`docs/adr/ADR-048-tenant-scope-two-connections.md`, status `accepted`:

- **D1 — Two connections, not one.** The owner client keeps the 782 unconverted sites; a second client bound to
  `DATABASE_URL_APP` serves scoped sites. Coverage grows module by module, each genuinely RLS-enforced the day it
  converts; an unconverted site keeps working instead of becoming an outage. Cite `tenant-adversarial-check.js:1914-1930`
  as the refutation of per-call-site adoption on one connection.
- **D2 — Why per-module beats big-bang.** 792 sites / 223 files in one diff is not reviewable; and the failure mode of
  a missed site is a *silent zero-row read*, not an error — the worst shape this programme has repeatedly ruled against.
- **D3 — The interactive-transaction cost.** `withTenant` opens a Prisma interactive transaction (maxWait 2 s /
  timeout 5 s, `prisma.service.ts:276-282`). Record the measured per-handler statement count (AC-8) and the rule:
  **identity resolution, bulk imports and reports never enter a scope.**

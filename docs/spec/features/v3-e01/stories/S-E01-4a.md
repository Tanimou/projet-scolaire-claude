## 1. The slice in five sentences

The student portal has no OIDC client of its own: `apps/web/src/auth.ts:37` aliases it to `portal-parent`, and
`apps/web/src/components/PortalLoginForm.tsx:27` carries a **second, hard-coded copy** of that same alias used to build
the Keycloak password-reset URL. The realm export declares four clients and `portal-student` is not among them, and
`portal-parent` registers no student redirect URI — so on the artefact that provisions the realm, student SSO login
(`/api/auth/callback/keycloak-student`) and student password reset (`/student/login`) are both refused
`invalid_redirect_uri`. Even with the redirects registered the security half survives untouched: a student's token
would carry `azp = portal-parent`, so **no audience or `azp` check can ever distinguish a student from a parent** —
which is why the audit graded this `BROKEN_SECURITY` and not `BROKEN_LINK`. The divergence is its own, separate defect:
`auth.ts:74` documents an opt-in `KEYCLOAK_STUDENT_CLIENT_ID` escape hatch and `PortalLoginForm.tsx:27` does not
consult it, so an operator who takes the documented path gets login on the new client and a reset link still pointing
at `portal-parent`, **silently**. This slice ships the fourth client, collapses every portal→client-id rule in
`apps/web` into **one** exported module both seams call, deletes the alias, and adds a no-skip executable gate that
reads the realm export as data and refuses the wrong fix by name.

## 3. The design decision — one module, and which of the brief's two options was taken

`PortalLoginForm.tsx` is `'use client'`. It cannot read server-only env, and a module it imports that reads
`process.env.KEYCLOAK_STUDENT_CLIENT_ID` would have that value **inlined as `undefined` into the client bundle** at
build time — a silent divergence with a nicer shape than the one being deleted. `NEXT_PUBLIC_*` is rejected for the
same family of reasons (build-time inlining is a known trap on this project, and it would mean four new public
variables to keep in step with four private ones).

**Decision — option (a), narrowly: compute server-side, pass one prop.** Recorded in `ADR-050 §D2`.

Ship **one** module, `apps/web/src/lib/keycloak-clients.ts`, modelled **exactly** on `apps/web/src/lib/portals.ts`
(read it first — it is the house precedent for "the value is written exactly once"): **import-free, `process.env`-free,
edge-safe**, importing only the `PortalId` type from `./portals`. It exports:

```ts
/** The canonical OIDC client id per portal — the ids `infra/keycloak/realm-export.json` declares. */
export const PORTAL_CLIENT_IDS: Record<PortalId, string>;   // admin|teacher|parent|student → `portal-<portal>`
export function portalClientId(portal: PortalId): string;   // pure, env-free

/** The two redirect targets the realm must register for a portal — the ONLY definition of either. */
export function portalCallbackPath(portal: PortalId): string;      // `/api/auth/callback/keycloak-<portal>`
export function portalLegacyCallbackPath(portal: PortalId): string; // `/api/auth/callback/<portal>`
export function portalResetRedirectPath(portal: PortalId): string;  // `/<portal>/login`

/**
 * The EFFECTIVE client id, override included. Env is a PARAMETER, never read
 * from `process.env` inside — which is what makes this function server-only by
 * CALL SITE rather than by convention, and what lets one test drive both seams.
 */
export function resolvePortalClientId(portal: PortalId, env: Record<string, string | undefined>): string;
```

`resolvePortalClientId` is `env[\`KEYCLOAK_${portal.toUpperCase()}_CLIENT_ID\`] ?? PORTAL_CLIENT_IDS[portal]`. There is
**no alias map and no second portal argument** — a portal resolves to its own client or to an operator-supplied id,
never to another portal's. That absence is AC-4.

Wiring:

- `auth.ts` — `clientCreds` calls `resolvePortalClientId(portal, process.env)` for the id and keeps its own
  `KEYCLOAK_<PORTAL>_CLIENT_SECRET ?? 'change-me-portal-<portal>'` read for the **secret**, which never leaves the
  server and never enters the shared module. `CLIENT_PORTAL_OVERRIDE` is **deleted**, and so is the `clientPortal`
  indirection in the two template literals at `:80-85`.
- The four login **pages** are already server components (`app/<portal>/login/page.tsx`). Each passes
  `resetClientId={resolvePortalClientId('<portal>', process.env)}` into `PortalLoginForm`.
- `PortalLoginForm` gains a `resetClientId?: string` prop; `buildKeycloakResetUrl(portal, resetClientId)` uses
  `resetClientId ?? portalClientId(portal)` and `portalResetRedirectPath(portal)`. The template literal at `:27` and
  its ADR-021 comment are **deleted**. The prop is optional so no third-party call site breaks; the fallback is the
  canonical id, never another portal's.

**Why this satisfies DNC-10.** No string comparison decides a client id anywhere. No second literal is introduced —
`portal-<portal>` is composed in exactly one function. The env override can no longer diverge between the two seams,
because both seams call the **same function with the same env object**, and AC-3's test proves that by driving it.

## 4. Acceptance criteria

### AC-1 — the fourth client EXISTS, derived from its siblings

`infra/keycloak/realm-export.json` gains a `portal-student` entry whose shape is **copied from `portal-parent`**
(F-13), with every portal-specific value substituted: `clientId: "portal-student"`, `name: "Portail élève"`,
`secret: "change-me-portal-student"`, `baseUrl: "/student"`,
`redirectUris: ["http://localhost:3000/student/*", "http://localhost:3000/api/auth/callback/student", "http://localhost:3000/api/auth/callback/keycloak-student"]`,
`webOrigins: ["http://localhost:3000"]`,
`attributes: { "pkce.code.challenge.method": "S256", "post.logout.redirect.uris": "http://localhost:3000/student/login" }`.
**Add no key the three siblings do not carry** — in particular no `protocolMappers` block, because none of them has
one. Place it after `portal-parent` and before `api-backend`, matching the existing portal-then-api ordering. `name`
is French, matching `Portail administrateur` / `Portail professeur` / `Portail famille`.

### AC-1b — the `student` realm role (F-12)

`roles.realm` gains `{"name": "student", "description": "…"}` mirroring the three siblings' shape exactly. This is
**purely additive, creates no identity, grants nothing to anybody**, and does not touch INV-1 (`auth.ts:140-149`
already declares the disjoint role set). Without it, a freshly imported realm cannot satisfy
`REALM_ROLES_FOR_PORTAL.student` and student login is refused for a **second, independent** reason — see `PF-210`,
which stays open for the provisioning half.

### AC-2 — THE WRONG FIX IS FORBIDDEN, and the gate says so by name

Adding `/student/*` or `/api/auth/callback/keycloak-student` to **`portal-parent`'s** redirect list is **not** the fix
and must be refused. It would make the symptom disappear while leaving `azp` collapsed — a green light over an unfixed
`BROKEN_SECURITY`. Three parts, all executable:

- **AC-2a** — the gate asserts that **no portal client lists a redirect URI whose path belongs to a different
  portal**, for all four portals, both directions, derived (never re-typed) from
  `portalCallbackPath` / `portalLegacyCallbackPath` / `portalResetRedirectPath` and the `/<portal>/*` prefix.
- **AC-2b** — the gate asserts no two clients share a `clientId`, and that `portal-parent`'s `redirectUris` are
  **exactly** F-4 plus nothing (set equality against a derivation, not a `length` check).
- **AC-2c** — the gate reads `infra/kc-prod-redirects.mjs` and fails if its `CLIENTS` map binds more than one portal
  path segment to one client id, or if any emitted redirect template contains a `*` in the
  `/api/auth/callback/` segment. `kc-prod-redirects.mjs` is updated in the same diff:
  `'portal-parent': ['parent']`, a new `'portal-student': ['student']`, and the wildcard
  `${BASE}/api/auth/callback/*` replaced by the two exact paths per portal. **This is the half that stops production
  from re-collapsing the seam** (`PF-209`, §0(d)). It is `infra/`, which this slice owns.

### AC-3 — ONE source of truth, and a test that proves the two seams cannot diverge

The module of §3 exists and is the only place in `apps/web/src` composing a `portal-` client id. Both `auth.ts` and
`PortalLoginForm.tsx` consume it. The proof is **driven, not read**: for all four portals, and under **three** env
fixtures — (i) empty env, (ii) `.env`'s real shape (three ids set, student unset), (iii) student promoted via
`KEYCLOAK_STUDENT_CLIENT_ID=portal-student-2` — assert
`loginClientId(portal) === resetClientId(portal)`, where both sides are obtained through the **same accessor call the
production code makes**, not by comparing two strings the test wrote. Fixture (iii) is the one that fails today: it is
the documented escape hatch, and it is the shape the divergence takes.

### AC-4 — the alias is GONE, not merely unused

`CLIENT_PORTAL_OVERRIDE` is **deleted** from `auth.ts`, mechanism included — not emptied. The decision and its reason
go in `ADR-050 §D3`: *a dead alias map that a future portal can silently fall into is worse than no map*, and the
legitimate need it served (an operator promoting a portal to a different client) is fully served by the
`KEYCLOAK_<PORTAL>_CLIENT_ID` override, which resolves **to an operator-chosen id, never to another portal**. Asserted,
not asserted-about: a source ratchet over the stripped `auth.ts` + `PortalLoginForm.tsx` sources fails if either file
regains a `portal-` string literal, a `=== 'student'` / `'student' ?` portal comparison, or a `Record<Portal, Portal>`
alias shape — with a **non-vacuity floor** (the scan must have read a non-empty corpus) and `__filename`
self-exclusion, the shape `user-sync.service.spec.ts:451-462` already uses on this project.

### AC-6f-bis — the port disagreement, decided rather than left implicit

The brief asks whether the two pre-existing mismatches affect AC-6's derivation. **They do, one of them, and here is
the ruling:**

- **`http://localhost:3000` (export) vs `:3100` (dev) — YES, it affects AC-6c**, and the gate must therefore compare
  **paths against each client's own `rootUrl` as origin basis** (`new URL(uri).pathname` vs the derived path), never
  raw whole-URL strings. A raw-string comparison would be green today and red the day someone runs the app on the port
  it actually uses. The mismatch itself is **recorded as `PF-212`, not fixed**: the reset link's `redirect_uri` is
  built from `window.location.origin`, so on a local/hybrid run at `:3100` the "Mot de passe oublié ?" link is refused
  for **all four** portals, not just student — a pre-existing, wider defect than `PF-18` and not this slice's.
- **`KEYCLOAK_PORT=8180` vs `KEYCLOAK_URL=http://localhost:8080` in `.env` — NO, it does not affect AC-6.** The gate
  never contacts Keycloak and never reads `.env`. Recorded as **`PF-213`**.

## 10. Risk & pre-mortem — assume this broke production, why?

1. **An existing realm is not re-imported.** `realm-export.json` provisions a realm at **first import only**; on the
   Hostinger deployment the realm already exists, so the new client does **not** appear and, once `auth.ts` stops
   aliasing, student login moves from "works via the wildcard" to **`invalid_client`**. → **This is the single
   highest-risk consequence of the slice and it must be in the PR description and in the rollout note**: the operator
   must create `portal-student` (or re-run the corrected `kc-prod-redirects.mjs` after adding the client) **before or
   with** the deploy. Note the mitigation already in the code: an operator who cannot do it yet can set
   `KEYCLOAK_STUDENT_CLIENT_ID=portal-parent` in `.env` and get today's behaviour back **as config, deliberately and
   visibly**, which is strictly better than the invisible alias — say so in `ADR-050 §D3`.
2. **The secret drifts.** The export's `secret` and `.env.example`'s `KEYCLOAK_STUDENT_CLIENT_SECRET` must be the same
   literal (AC-5); `infra/docker-compose.yml:511-513` has no student line, so a containerised web falls back to
   `auth.ts`'s `change-me-portal-student` default — which happens to match, today. Record it in the rollout note;
   do not edit compose in this slice.
3. **The gate passes vacuously.** Covered by the non-vacuity floor and the named failure branches (AC-6f), and proven
   by AC-7's fail-before transcript. A gate never shown red is a gate we hope works.
4. **The AC-4 source ratchet reddens on an unrelated future edit.** Keep it narrow: two named files, stripped of
   comments and strings-in-comments, three specific shapes, `__filename` excluded.
5. **CRLF.** `.gitattributes` pins `*.ts`/`*.sh`/`*.yml` to `eol=lf` but **not `*.js`** — the checker is a `.js` file
   and will be CRLF on this Windows checkout and LF in CI (this exact trap cost run 56 a day, see `S-E01-3`'s row).
   Normalise `\r\n` → `\n` at every read inside the checker, so it judges content and never checkout style.

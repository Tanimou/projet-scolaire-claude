## 3. Design decisions — these become `ADR-052`

### D1 — how a plain node script reads a TS/ESM accessor without re-typing the rule (AC-2's whole difficulty)

`scripts/keycloak-client-check.js` must run under bare `node`, with no jest, no ts-node and no build (agents never
build). `keycloak-clients.ts` is TypeScript, imports `./portals` **without a file extension**, and is therefore not
`import()`-able from plain ESM even with `--experimental-strip-types`.

Three candidates were considered. **Decision: (a), hardened by (a′).**

- **(a) A narrow, documented parse.** Read the two files as text and extract exactly three anchors:
  `PORTAL_IDS = [...] as const` (F-2), `CLIENT_ID_PREFIX = '…'` and `PROVIDER_ID_PREFIX = '…'` (F-1). Compose
  `portal-<id>` and `/api/auth/callback/<providerPrefix><id>` from them. **Each anchor that does not match must
  `process.exit(1)` naming the file, the anchor and the remedy.** A parse that silently yields `[]` and then passes
  zero assertions is DNC-08's exact defect wearing a new hat — an empty derivation is a **failure**, never a pass.
- **(a′) The anti-drift closure, and it is what makes (a) honest.** Add to the *existing*
  `apps/api/src/shared/quality/keycloak-client-identity-gate.spec.ts` a block that `require`s the new script's
  exported derivation and asserts it **deep-equals** what the compiler-checked import produces
  (`PORTAL_CLIENT_IDS`, `portalCallbackPath(p)` for every `p` in `PORTAL_IDS`). Two independent derivations — one by
  parse, one by real import — that must agree, and **neither is hand-typed**. If the parse ever drifts from the
  module, jest goes red. Structure the script so this is possible: a pure `deriveRule()` function, exported, with the
  CLI entry point behind `if (require.main === module)`.
- **(b) `--experimental-strip-types`** — rejected: cannot resolve the extensionless import without editing the
  production file, and editing production code to please a checker is backwards.
- **(c) A generated JSON artefact** — rejected: needs a build step (forbidden), and creates a fourth artefact that can
  go stale between generation and use. That is the two-lists trap with an extra file.

**If the implementer ends up re-typing `'portal-'`, `'keycloak-'`, `/api/auth/callback/`, or the four portal names
inside `scripts/keycloak-client-check.js`, AC-2 FAILS.** Say so in the PR body rather than smoothing it over; a
recorded failure is worth more than a false green (this is the same standard `S-E01-1d` was held to on `AC-9`).

### D2 — the wildcard rule is W-1/W-2/W-3, not "no wildcard"

See §0(b). Written into the ADR because the brief's wording will be read again by a future run and must not be
re-implemented literally.

### D3 — standalone container, not the compose stack, for the live evidence

Compose `keycloak` depends on compose `postgres`, which publishes host port 5432 — already held by the native
`postgresql-x64-15` service (F-14). Bringing the stack up therefore risks either a bind failure or, worse, a
half-started stack whose failure gets attributed to the realm.

**Decision: run a standalone `quay.io/keycloak/keycloak:26.0` container** with `start-dev --import-realm`, the export
bind-mounted at `/opt/keycloak/data/import/realm-export.json`, and a host port that is measured free (prefer 8180;
if held, pick another and **state which**). The import semantics are identical — the compose service runs the same
image with the same command — and AC-6..AC-8 claim nothing about compose. **State in the evidence which option you
took and why**, including the measured port. Do not silently switch options mid-run.

If you instead choose the compose route, you must override the postgres host port
(`POSTGRES_PORT=<free port>`) and you must invoke compose as
`docker compose --env-file .env -f infra/docker-compose.yml …` **from the repo root** (PF-86: a bare invocation
resolves `.env` from `infra/`, which does not exist, and silently starts a different stack).

Local data is expendable. Recreating containers, wiping volumes and re-importing realms are ordinary work here.
**Leave the stack running and healthy at the end, or say explicitly that you did not.**

### D4 — `VAL-04` point 5 is RE-SCOPED, and the re-scope is stated, not slipped in

`VAL-04`'s original point 5 reads *"the **running** Hostinger realm no longer holds the `/api/auth/callback/*`
wildcard after the corrected provisioner runs."* **The Hostinger VPS is an audit fixture, never a target** — no HTTP
request, no deploy, no admin-API call, not once. The claim this slice can honestly make and does make is:

> **the corrected provisioner removes the `/api/auth/callback/*` wildcard from a real realm** — proven against the
> LOCAL realm.

Record the residue explicitly: *"point 5 against the production realm is an OPERATOR action, unproven here, tracked
as `PF-223`."* Do not mark VAL-04 point 5 "closed" without that sentence beside it.

### D5 — the student test identity is EPHEMERAL and lives only in the running realm

`AC-7` needs a token. No student identity exists in the export (F-5 / `PF-210`), and **adding a demo student to
`realm-export.json` is refused**: minting one decides a password policy, a tenant, and a `Student.userProfileId`
link — that is `ADR-021`'s provisioning story and is a different slice.

**Decision: create the user through the running realm's admin API, use it, delete it, and prove the deletion.**
`infra/keycloak/realm-export.json` must be byte-identical before and after the live run (`git status` clean —
prove it, do not assert it).

### D6 — the new stage runs in TIER 1, **unconditionally**

The brief asks for a fast-tier stage with a trigger over `infra/keycloak/`, `infra/kc-*.mjs`,
`apps/web/src/lib/keycloak-clients.ts` and `apps/web/src/auth.ts`. The **intent** — *"closing the `GATE_MACHINERY`
hole is the point; a stage that only fires on `infra/` reproduces the hole"* — is satisfied *a fortiori* by a stage
with no trigger at all, and an untriggered stage cannot grow a trigger hole later. The check is a pure read of two
JSON/JS/TS files with no database, no network and no build; its natural neighbours (`production artefacts`,
`audit writes`, `csv escapers`) are all unconditional tier-1 stages of the same shape and cost (F-10).

**Decision: unconditional, in TIER 1, placed immediately after `csv escapers` (`scripts/ci-gate.sh:202`).**

**Documented fallback, and the only permitted one:** if the measured wall time exceeds ~3 s, move it into TIER 2
behind exactly this trigger — no narrower —

```
'^(infra/keycloak/|infra/kc-.*\.mjs|apps/web/src/lib/keycloak-clients\.ts|apps/web/src/auth\.ts)'
```

— and say in the PR body which form you shipped and what you measured. `infra/` alone is **not** acceptable: that is
the hole with a new name.

## 4. Acceptance criteria

### AC-1 — `scripts/keycloak-client-check.js` exists and is a real gate

A standalone node script. **Exit 0 pass / exit 1 fail. No `--skip`, no `SKIP_*` env var, no `continue-on-error`, no
fail-open branch, no jest** (G-DNC / DNC-10: the new gate has no escape hatch). Every failure prints the file, the
offending value, the rule it broke, and the remedy. Every *count* it reports is derived, never asserted against a
typed constant.

It asserts **both** artefacts:

**(a) `infra/keycloak/realm-export.json`**
1. Exactly one client per derived portal — no portal missing, no duplicate `clientId`.
2. Client ids **derived** from the accessor (D1), never re-typed.
3. Every portal's **three** redirect URIs present: `<origin>/<portal>/*`, `<origin>` + `portalCallbackPath(portal)`,
   `<origin>` + `portalLegacyCallbackPath(portal)`. **Compare PATHS, not origins** — the export registers
   `localhost:3000` while `apps/web` dev runs on 3100; an origin-exact rule goes red on three untouched clients.
   (This is the reasoning the existing jest gate already records at its "PATHS, NOT ORIGINS" header; follow it, and
   reference it rather than re-deriving it.)
4. **W-3**: no client carries any *other* portal's path segment, anywhere in any URI or in `baseUrl`.
5. **W-1**: no `*` anywhere inside an `/api/auth/callback/` URI.
6. **W-2**: the only `*` permitted is a trailing `<origin>/<own portal>/*`.
7. Every portal client is confidential (`publicClient:false`) with `standardFlowEnabled` and
   `directAccessGrantsEnabled` true — **all four portals, not just student** (G-PORTAL 4/4).
8. The `student` realm role is declared.

**(b) `infra/kc-prod-redirects.mjs`**
9. Its `CLIENTS` map binds **exactly one portal per client**; a multi-portal binding is a **hard failure**.
10. Its client-id key set equals the derived set — no client missing, none extra.
11. A **missing** client is a FAILURE, not a skip (DNC-08 — the original defect was
    `✗ client not found (skipped)` followed by `exit 0`). Assert that the script's not-found branch increments
    `failures` and cannot reach `exit 0`; if you assert this by reading source text, say so and say what shape you
    matched, so a later reader knows how brittle it is.
12. No `*` is written into any `/api/auth/callback/` URI by `callbackPaths` (W-1 at the provisioner).

### AC-2 — the rule is NOT re-typed (D1)

exits 1 naming file, anchor and remedy — never yields an empty set that passes vacuously.

**Self-assessment is mandatory and it is an output, not a formality:** state in the PR body whether the shipped
script re-types any part of the rule. If it does, AC-2 is **failed** — record it, do not narrate around it.

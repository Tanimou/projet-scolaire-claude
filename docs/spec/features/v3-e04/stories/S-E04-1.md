## 0. Read this first

This slice is **one decision plus its mechanical consequences**. It writes no feature a user can see. It changes
what the `audit_log` table *says about who acted*, and it puts the four helpers that ~20 future call sites will need
into a home that is not a feature module.

Three things, in this order, and the order is not negotiable:

1. **T-0 — move the helpers first**, before any other edit. `sanitiseInetOrNull`, `truncateUserAgent`,
   `MAX_USER_AGENT_LENGTH` and the actor-role derivation move out of the `calendar` and `alerts` **feature** modules
   into a new `apps/api/src/shared/audit/`. The originals are **deleted**. **No re-export shim** — a shim is how a
   second copy survives its own removal.
2. **One derivation, one home.** `deriveAuditProvenance(jwt, req)` becomes the single answer to "who acted, and
   through which portal". Today there are **four** answers in production code (§2.2), two of which are inline
   copies carrying no shared identifier, and one of which is wrong for `parent`.
3. **`ADR-036`** writes down why the operator's real IP and User-Agent are **null** rather than plausible-looking —
   the pinned hop count, the refusal of blanket `X-Forwarded-For` trust, and who owns making them real
   (`S-E04-3`).

**The one sentence the whole epic is stated over:** *« une provenance absente, jamais une provenance fausse »* — an
absent provenance, never a false one. Every ruling below falls out of it. If you find yourself about to write a
value that *looks* right rather than one you can prove, write `null` and say why in a docblock.

## 2. The design

### 2.1 The new home

Create **`apps/api/src/shared/audit/`** with exactly these files:

```
apps/api/src/shared/audit/
  provenance.ts        # the derivation + the sanitisers + the types   (the ONLY declaration site)
  index.ts             # re-export barrel for the module's public API
  provenance.spec.ts   # unit cases for the pure functions
```

Do **not** create a Nest module, provider, interceptor or decorator here. `calendar.controller.ts:271-275` already
records the ruling and this slice keeps it: *« Aucun intercepteur partagé n'est construit »*. A pure function that
every call site invokes explicitly is auditable by grep; an interceptor is a place a future author can forget to
apply. A shared interceptor, if it is ever wanted, is `S-E04-7`'s decision with its own gate.

### 2.2 `provenance.ts` — the contract

```ts
/** Longueur maximale stockée dans `AuditLog.userAgent` (colonne `String?`). */
export const MAX_USER_AGENT_LENGTH = 512;

export interface AuditProvenance {
  actorRole: string | null;
  portal: string | null;
  ipAddress: string | null;
  userAgent: string | null;
}

/** The role/portal half only — what the nine existing call sites already consume. */
export type AuditActorProvenance = Pick<AuditProvenance, 'actorRole' | 'portal'>;

export function sanitiseInetOrNull(raw: string | undefined | null): string | null;   // moved verbatim
export function truncateUserAgent(raw: string | undefined | null): string | null;    // moved verbatim

/** Canonical. */
export function deriveAuditProvenance(jwt: KeycloakJwtPayload, _req?: unknown): AuditProvenance;

/** Kept for the nine existing importers; delegates, declares nothing of its own. */
export function deriveAlertActorProvenance(jwt: KeycloakJwtPayload): AuditActorProvenance;
```

**Rules on this file, each of which is an acceptance criterion:**

- **The bodies of `sanitiseInetOrNull` / `truncateUserAgent` / the precedence logic move verbatim.** This slice
  changes *where* they live, not *what they do*. `calendar-seed-holidays.spec.ts:445-452` already pins their
  behaviour; those assertions must still pass **unchanged** apart from the import path.
- **`deriveAlertActorProvenance` must not re-implement anything.** One line: `return { actorRole, portal }` off
  `deriveAuditProvenance(jwt)`. If it contains a second `find(...)` over a role array, AC-1 is violated by the very
  file that is supposed to end the duplication.
- **`ROLE_PRECEDENCE` and `ROLE_PORTAL` stay module-private** (not exported) so no caller can fork a variant map.
  Precedence stays `super_admin > school_admin > teacher > parent`; `ROLE_PORTAL` stays
  `{super_admin: 'admin', school_admin: 'admin', teacher: 'teacher', parent: 'parent'}`. The fallback stays exactly
  as it is today: an unrecognised caller yields `{ actorRole: realmRoles[0] ?? null, portal: null }`, never throws —
  the audit write is best-effort and must not become a failure mode for the operation it records.
- **`packages/contracts`' `REALM_ROLES` (`src/enums/index.ts:6`) is NOT reused here.** It is the *set* of realm
  roles; `ROLE_PRECEDENCE` is an *ordering* that encodes privilege. They coincide today by accident. Reusing the
  contract array would make a future reorder of a display list silently reorder audit precedence. Say this in a
  comment so a later reviewer does not "simplify" it.

### 2.3 `ipAddress` / `userAgent` are `null` in this slice — and the second parameter is deliberately unread

`deriveAuditProvenance` returns `ipAddress: null, userAgent: null` **unconditionally**. It accepts a second
parameter so the signature `tasks.md` specifies is stable for `S-E04-3`, and it **must not read it**. Name it
`_req` (the repo's ESLint sets `argsIgnorePattern: '^_'`, `packages/eslint-config/base.js:87-90`, so this is clean;
`noUnusedParameters` is not set, `packages/tsconfig/base.json`).

Why unread rather than "read `req.ip` for now": `apps/api/src/main.ts:37` is a bare `NestFactory.create` with **0**
occurrences of `trust proxy` repo-wide, so Express `req.ip` is the **socket peer**. For every write site in this
slice the peer is the **web container** (`apps/web/src/lib/api-client.ts:53` forwards only `Accept`,
`Content-Type`, `Authorization`), so `req.ip` is one constant address shared by every actor forever, and undici
sends no `User-Agent`. Reading it would put a *wrong* value in a governance trail that `/admin/audit` renders in
monospace as "where the admin acted from". Null-rather-than-wrong.

The docblock on the function must say all of this in two or three sentences and name `S-E04-3` as the owner, so
nobody reads the null as a bug. **A test asserts the null** (§4.3, T-5): given a `_req` carrying `ip: '203.0.113.7'`
and a `user-agent` header, the function still returns both as `null`. That test is what makes the rule enforceable
rather than aspirational.

### 2.4 The call-site edits, exactly

**Pattern A — the JWT is already on the handler** (sites 1, 2, 3, 4, 7, 8):

```ts

// …
```

For `academic-years.controller.ts`, the literal is inside the private `audit(tx, me, …)` helper. Widen that helper

**Pattern D — `grades.controller.ts:332-336` + `:345`** (copy **C**): replace both the inline `find(...)` and the

Keep its `deriveAlertActorProvenance(jwt)` call as-is (it now resolves to the shared module).

1. **The topology, measured, with the files it was read from.** What this repository can prove:
   - `apps/api/src/main.ts:37` — bare `NestFactory.create`; **0** occurrences of `trust proxy` / `trustProxy` in

   - `infra/nginx/conf.d/pilotage.conf` — one nginx in front of the API (`upstream api_upstream`, `location /api/`

   - `infra/docker-compose.yml:427,450` — in the dev/local stack there is **no** Traefik and nginx runs only under
     the `prod` profile.
   - `apps/web/src/lib/api-client.ts:53` — the server-side seam forwards only `Accept`, `Content-Type`,
     `Authorization`. `apiUrl()` (`:86`) also exists, so a second, browser-direct path to the API is possible in
     production (`NEXT_PUBLIC_API_URL = PUBLIC_BASE_URL`). **Both paths must be named in the ADR**; every write
     site this slice touches is reached over the *server-side* one.
2. **The pinned hop count, and the honest statement of what could not be established.** A number must be pinned
   **per topology** (production and local are different chains), and the ADR must state, in those terms, which
   segment of the chain it could **not** verify from this checkout — the host's Traefik and its own
   `forwardedHeaders` trust configuration live outside this repository. `plan.md` §3's Traefik→nginx→api sentence
   is the deployment picture, not a verified trust boundary. The existing draft pins `N = 2` / `N = 0` and carries
   that caveat; check that the caveat is present and unambiguous, because it is what stops `N` becoming `R-26`'s
   magic number. **Never invent a number.**
3. **The written refusal of blanket `X-Forwarded-For` trust, with the reason.** `app.set('trust proxy', true)`
   makes the audit IP **client-forgeable** — any caller can send `X-Forwarded-For: 1.2.3.4` and choose what the
   governance trail says about them. A forgeable provenance in an audit trail is **strictly worse than blank**,
   because a recorded value is believed. Refused. (`plan.md` §3, option (b).)
4. **The null-rather-than-wrong rule**, stated as a rule other slices inherit: where the pinned hop count cannot
   resolve a trustworthy address, the field is `null` and the UI says « provenance non disponible ».
5. **The non-negotiable consequence:** the API **cannot see** the operator's IP or UA until `apps/web` forwards
   them explicitly. Fixing `trust proxy` alone changes nothing on the server-side path, because the only peer nginx
   ever sees there is the web container. **Name `S-E04-3` as the owner** of the forwarding chain (AC-5).
6. **A named way to re-derive `N` if the topology changes** — otherwise `N` is a magic number, which is `R-26`'s
   shape. Give a concrete procedure: e.g. *"count the proxies between the client and `apps/api` in
   `infra/docker-compose.prod.yml` + `infra/nginx/conf.d/pilotage.conf`; each one must both (a) be operated by us
   or by the host operator, and (b) overwrite or append `X-Forwarded-For` from its own `$remote_addr`. A hop that
   fails either test is not counted. Re-run this whenever a `proxy_set_header X-Forwarded-*` line or a
   `traefik.http.routers.*` label changes."*
7. **This slice sets no `trust proxy` value.** `apps/api/src/main.ts` is **not edited**. The ADR is the decision;
   `S-E04-3` is the implementation. Say so, so a reader does not go looking for the missing line.

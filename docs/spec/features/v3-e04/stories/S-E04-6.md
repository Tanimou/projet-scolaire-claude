## 2. What ships

### 2.1 The seam — `apps/api/src/shared/audit/write-audit.ts` (new)

`shared/audit/` is an existing **pure-function area, no Nest module** (see the docblock at `provenance.ts:28`). Keep
it that way: a plain exported function, re-exported from `shared/audit/index.ts`, declared **once**.

```ts
import type { Prisma } from '@prisma/client';
import type { AuditProvenance } from './provenance';

/**
 * A transaction client, and ONLY a transaction client.
 *
 * `Prisma.TransactionClient` alone is NOT enough — see §2.2. The `?: never`
 * members are the part that does the work.
 */
export type AuditTransactionClient = Prisma.TransactionClient & {
  $transaction?: never;
  $connect?: never;
};

export interface AuditWriteInput {
  /** ALWAYS the CALLER's tenant (`me.tenantId`) — never derived from the target row. */
  tenantId: string;
  actorId: string | null;
  action: string;
  resourceType: string;
  resourceId?: string | null;
  before?: Prisma.InputJsonValue | null;
  after?: Prisma.InputJsonValue | null;
  /**
   * REQUIRED, not optional — AC-3 becomes a compile-time property too. A caller
   * with no request in scope states so by passing
   * `deriveAuditProvenance(jwt, NO_CLIENT_HINTS)`, which is an honest blank
   * written down, not an omission.
   */
  provenance: AuditProvenance;
}

export async function writeAudit(
  tx: AuditTransactionClient,
  input: AuditWriteInput,
): Promise<void>;
```

Body: one `tx.auditLog.create({ data: { … } })`. Nothing else. **No** `try`/`catch`, **no** default provenance,
**no** `process.env`, **no** `ConfigService`, **no** flag, **no** `skip`/`force` parameter, **no** id allow-list
(**G-DNC / DNC-10** — there must be no way to reach the mutation while skipping the write).

`before`/`after` pass through untouched. Do **not** normalise, redact or stringify here; that is a policy this slice
does not own.

### 2.2 The compile-time invariant — and the trap in `plan.md` §5

`plan.md` §5 and `tasks.md` assert that *"the transaction client as the first parameter makes `writeAudit(this.prisma, …)`
a TYPE error"*. **With `Prisma.TransactionClient` alone that claim is false**, and shipping it unexamined would ship a
gate that is green over nothing.

`Prisma.TransactionClient` is `Omit<PrismaClient, ITXClientDenyList>` where `ITXClientDenyList` is
`'$connect' | '$disconnect' | '$on' | '$transaction' | '$use' | '$extends'`. TypeScript is **structural**: a value with
*more* members is assignable to a type requiring *fewer*. `PrismaService extends PrismaClient`, therefore
`writeAudit(this.prisma, …)` **type-checks fine** against a bare `Prisma.TransactionClient` parameter.

The `& { $transaction?: never; $connect?: never }` intersection above closes it:

- a real `tx` **lacks** `$transaction` entirely → an absent optional property is assignable → **compiles**;
- `PrismaService` **has** `$transaction: <overloads>`, which is not assignable to `never | undefined` → **error**.

**This is mandatory and must be falsifiable in the suite.** In `write-audit.spec.ts`:

```ts
// @ts-expect-error — a full PrismaClient must NOT satisfy AuditTransactionClient (S-E04-6 §2.2)
await writeAudit(prismaService, input);
```

`@ts-expect-error` is itself an error when the line compiles cleanly, so `pnpm typecheck` turns red the day the brand
is weakened. That is the evidence; a prose claim is not.

### 2.3 The four families

Every family follows the same shape, and the order matters:

1. resolve `me = await this.users.ensureUser(jwt)`;
2. derive provenance **before** opening the transaction —
   `const provenance = deriveAuditProvenance(jwt, extractAuditClientHints(req));`
   (the `S-E06-6` reason, restated at `subjects.controller.ts:214`: an `inet` cast is sanitised **outside** the
   transaction so a malformed `X-Forwarded-For` can never roll back the write it traces);
3. run every validation / `NotFoundException` / `ConflictException` **before** `$transaction` — a denied request must
   open no transaction and write no row;
4. inside `this.prisma.$transaction(async (tx) => { … })`: the entity mutation, then `await writeAudit(tx, …)`;
5. anything slow, external or best-effort (guardian notification fan-out, BullMQ enqueue) stays **outside and after**
   the transaction.

The **canonical existing exemplar** to copy is `school-structure/subjects.controller.ts:218-260`
(`@Req() req: ClientHintsRequest`, `deriveAuditProvenance(jwt, extractAuditClientHints(req))`, then
`$transaction(async tx => { …mutation…; await tx.auditLog.create(…) })`). This slice replaces its last statement's
*shape* everywhere it introduces one — but **do not** migrate `subjects.controller.ts` itself onto the seam; that is
`S-E04-7`'s sweep and widening the diff into it is out of scope.

#### (a) Role grant / revoke — `identity/users.service.ts` + `identity/users.controller.ts`

`UsersService` today takes primitives. Widen both methods to accept the provenance, so the controller keeps ownership
of the request and the service keeps ownership of the transaction:

```ts
async assignRole(userId: string, roleId: string, grantedById: string, tenantId: string, provenance: AuditProvenance)
async revokeRole(userRoleId: string, tenantId: string, actorId: string, provenance: AuditProvenance)
```

Make `provenance` **non-optional** (the `AuditActorProvenance` docblock at `provenance.ts:59` gives the precedent and
the reason: a forgotten caller is a compile error, not a silent null).

- `assignRole` — the three existing pre-checks stay exactly as they are and stay **outside** the transaction:
  `NotFoundException('User not found')`, `ForbiddenException('Cross-tenant assignment refused')` when
  `user.tenantId !== tenantId`, `NotFoundException('Role not found')`. The **idempotent early return** at :55
  (`existing` and not revoked) also stays outside, and it writes **no** audit row — nothing changed, so nothing is
  audited. State that in a comment; it is a deliberate absence, not an omission.
  Then: `$transaction(async tx => { const created = await tx.userRole.create({…}); await writeAudit(tx, { action: 'role.grant', resourceType: 'user_role', resourceId: created.id, after: { userProfileId, roleId, roleSlug, schoolId: null }, … }); return created; })`.
- `revokeRole` — pre-checks (`NotFoundException`, `ForbiddenException` on
  `ur.userProfile.tenantId !== tenantId`) stay outside. Inside: `tx.userRole.update({ revokedAt })` then
  `writeAudit(tx, { action: 'role.revoke', resourceType: 'user_role', resourceId: userRoleId, before: { revokedAt: null }, after: { revokedAt } })`.
  `revokeRole` currently receives no actor id — add `actorId` (the controller already has `me.id`).
- `users.controller.ts` — add `@Req() req: ClientHintsRequest` to `assignRole` and `revokeRole`, derive provenance,
  pass it down. **Do not change `@RequiresPermission('roles.assign')` on either handler.**

`role.grant` must carry `after.roleSlug` (read from the `role` already fetched at :48) as well as `roleId`: the audit
row must be readable without a join into a table whose row may later be deleted.

#### (b) School mutation — `schools/schools.controller.ts`

Three handlers, all already tenant-guarded. Add `@Req() req: ClientHintsRequest`, derive provenance, wrap:

| Handler | action | resourceType | `before` / `after` |
|---|---|---|---|
| `create` (:115) | `school.create` | `school` | `after`: `{ name, schoolCode, country, timezone, locale }` |
| `update` (:137) | `school.update` | `school` | `before`: the pre-image already fetched at :143 (`{ name, timezone, locale, status }`); `after`: the same keys from `updated` |
| `remove` (:163) | `school.close` | `school` | `before`: `{ status: school.status }`, `after`: `{ status: 'closed' }` |

`remove` is a **soft close**, not a delete (`:176`, `data: { status: 'closed' }`). The action code says `close`
because the code is the structural truth; naming it `school.delete` would be the third kind of lie this epic exists

`POST :id/switch` (:182) is **explicitly not audited** and this is a decision, not an oversight: it mutates

The unique-`schoolCode` `ConflictException` (:119) stays outside the transaction.

#### (c) Enrollment decision — `enrollments/enrollments.controller.ts`

Four mutating handlers. Add `@Req() req: ClientHintsRequest` to each; derive provenance once per handler.

| Handler | action | resourceType | Notes |
|---|---|---|---|
| `create` (:145) | `enrollment.create` | `enrollment` | all five validations (:157-186) stay outside the transaction; wrap only the `enrollment.create` at :188. `after`: `{ studentId, classSectionId, academicYearId, status }` |
| `update` (:220) | `enrollment.status_change` | `enrollment` | `before`: `{ status: enrollment.status, endedAt: enrollment.endedAt }`, `after`: the same keys from `updated` |
| `transfer` (:258) | `enrollment.transfer` | `enrollment` | **converts an array `$transaction` into an interactive one** — see below |
| `remove` (:314) | `enrollment.cancel` | `enrollment` | both branches (hard delete when `pending`, soft `dropped` otherwise). `after.hardDeleted: boolean` distinguishes them; `before`: `{ status: enrollment.status }` |

**`transfer` is the one structural change.** It is currently
`this.prisma.$transaction([ update(…), create(…) ])` — the **array** form, which cannot host a third statement that
needs the `tx` client. Convert to the interactive form and preserve the return value's shape:

```ts
return this.prisma.$transaction(async (tx) => {
  const closed  = await tx.enrollment.update({ where: { id }, data: { status: 'transferred_out', endedAt: new Date(), endReason: body.reason ?? `Transféré vers ${target.name}` } });
  const opened  = await tx.enrollment.create({ data: { tenantId: me.tenantId, studentId: current.studentId, classSectionId: body.toClassSectionId, academicYearId: current.academicYearId, status: 'active' } });
  await writeAudit(tx, {
    tenantId: me.tenantId, actorId: me.id, provenance,
    action: 'enrollment.transfer', resourceType: 'enrollment', resourceId: opened.id,
    before: { enrollmentId: closed.id, classSectionId: current.classSectionId },
    after:  { enrollmentId: opened.id, classSectionId: body.toClassSectionId, reason: body.reason ?? null },
  });
  return [closed, opened];
});
```

Returning `[closed, opened]` keeps the wire response **byte-identical** to the array form's tuple. Assert that in a
test — a silent shape change here breaks `apps/web` and this slice ships no web change to compensate.

`notifyGuardiansOfEnrollment` (:56) **stays outside and after** the transaction, unchanged, including its
`try`/`catch`. It is a multi-query fan-out that already swallows its own errors; moving it inside would lengthen every
enrollment transaction and make a notification failure roll back a legitimate enrollment. Say so in a comment.

### 2.6 `ADR-035`

`docs/adr/` currently holds `001-004, 013-028, 036, 037`. **`ADR-035` is free and is this epic's existing

`docs/adr/ADR-035-audit-in-transaction.md` must state:

- **D1** — an audit row is written **inside** the transaction of the mutation it describes, through the single seam
  `shared/audit/writeAudit`. Consequence, stated plainly: **an audit failure now fails the mutation.** Availability is
  traded for integrity, deliberately. The alternative (best-effort, the current convention at ~22 sites) permits an
  entity that exists with no trace, which the north star's *"append-only audit is non-negotiable"* forbids.
- **D2** — the invariant is **compile-time**, via the branded `AuditTransactionClient`, and §2.2's reason why the bare
  `Prisma.TransactionClient` would not have achieved it. Record the `@ts-expect-error` line as the evidence.
- **D3** — **`PF-96` posture: STATED, NOT CHANGED.** `AuditLog` has **no foreign key to `Tenant`** (`schema.prisma:1233-1252`:
  `tenantId String @map("tenant_id") @db.Uuid`, no `@relation`, one index `@@index([tenantId, createdAt])`). This is
  deliberate for an append-only journal — an FK plus a cascade would make deleting a tenant delete its audit trail,
  and an append-only log must outlive the row it points at. The cost is that tenant scoping here is
  **application-level only**: `writeAudit` writes the **caller's** `me.tenantId` and never a value derived from the
  target row. **No relation is added in this slice.** RLS remains absent repo-wide (measured: 0 occurrences of
  `ENABLE ROW LEVEL SECURITY` / `CREATE POLICY`, `0_baseline/migration.sql` included) — this ADR therefore *narrows*
  `ADR-002` until `ADR-032` / `V3-E01` delivers it.
- **D4** — **`DNC-10`**: there is no off switch, and nothing switchable is in scope. `write-audit.ts` reads no
  `process.env`, no `ConfigService`, no flag, no `NODE_ENV`; the input type has no `skip` member.
- **D5** — the finance clause of `AC-2` is **vacuous today** (§7), armed by `S-E04-7`'s gate.
- **D6** — the ~22 remaining non-transactional sites and the `packages/imports-core` pair are **knowingly left**;
  `S-E04-7` owns the sweep and the ratchet. `S-E04-8` will **amend** this ADR with the chain (the `ADR-024`
  amendment pattern, already used four times in this repo) — it does **not** supersede it.

## 4. Acceptance criteria

**AC-1 (G-AUDIT, direction i — the mutation fails).** For each of the four existing families: with the entity
mutation forced to throw **inside** the transaction, **neither** the entity row **nor** the audit row is persisted.

**AC-2 (G-AUDIT, direction ii — the writer fails).** Inverted, per family: with `writeAudit` forced to throw, the
entity mutation does **not** persist and the request fails. *(A test proving only direction (i) proves nothing about a
writer placed after a commit — `plan.md` §5. Both directions, all four families: **8 tests**, not 4.)*

**AC-3 (provenance).** Every row written by every new call site carries `actorId`, a real `actorRole`, a `portal`, the
caller's `tenantId`, and `ipAddress`/`userAgent` — obtained from the existing `deriveAuditProvenance` in
`shared/audit/provenance.ts` fed by `extractAuditClientHints`. **Do not reinvent either.** A caller with no hints
passes `NO_CLIENT_HINTS` and the row carries `null`/`null`.

## 8. Pre-mortem — what will actually go wrong

1. **The gate turns red backwards (highest probability).** §2.5 is skipped, the nine codes never reach
   `WRITTEN_ACTIONS`, and the REVERSE assertion demands the nine new labels be deleted. Someone deletes them. The
   vocabulary silently loses the slice's whole contribution while every test is green. **Mitigation:** §2.5 is
   mandatory and item 5 is its falsification.
2. **The compile-time invariant is theatre.** A bare `Prisma.TransactionClient` accepts `PrismaService`
   structurally, the ADR claims an invariant that does not exist, and `S-E04-7` builds a ratchet on top of it.
   **Mitigation:** §2.2's brand plus AC-6's `@ts-expect-error`.
3. **A transaction wraps too much.** Validation queries or the guardian fan-out get pulled inside, enrollment
   transactions grow to a dozen round-trips under lock, and a notification outage starts rolling back enrollments.
   **Mitigation:** the five-step order in §2.3, and the enrollment test that asserts the fan-out is outside.
4. **An `inet` cast rolls back a legitimate mutation.** Provenance is derived *inside* the transaction and a malformed
   `X-Forwarded-For` aborts the write it was supposed to trace — the `S-E06-6` failure, re-created. **Mitigation:**
   step 2 of §2.3; `sanitiseInetOrNull` already runs in the extraction seam, outside.
5. **Availability regression, unannounced.** Four privileged paths that previously could not fail on audit now can.
   A DB hiccup on `audit_log` becomes a 500 on role assignment. This is **intended** (`ADR-035` D1) but must be
   written down, not discovered in production.
6. **The `transfer` response shape changes.** The array→interactive conversion returns an object instead of a tuple,
   `apps/web` breaks, and no web change ships in this slice to catch it. **Mitigation:** FR-11 and its test.
7. **`role.grant` audits a role that is later deleted.** `resourceId` points at a `UserRole` with no FK from
   `AuditLog`; the join dies. **Mitigation:** `after.roleSlug` denormalised into the row.
8. **KPI drift read as a regression.** Six new `critical: true` codes raise « Modifications critiques ». **Mitigation:**
   §2.4's note, repeated in `PROGRESS.md`.

## 9. New finding to register (do not fix here)

**`PF-153` (P1, `[auth]`, out of scope — register in `traceability/OPEN.md` and `PROGRESS.md`).**
`identity/users.service.ts` `assignRole` performs **no check that the grantor may confer the role being granted**: any
holder of `roles.assign` can attach **any** `Role` row — including a system role carrying `roles.write`,
`schools.write` or every permission the grantor lacks — to any user in their tenant. `Role` has no `tenantId` at all
(stated in `roles.controller.ts:109`: *"we don't have a tenant_id on Role yet"*), so the candidate set is **global**.
That is textbook privilege escalation and it is the direct violation of the epic's own G-AUTHZ clause *"no permission
granted the grantor lacks"*.

It is **deliberately not fixed in this slice**: the fix is an authorisation change (a subset check, or a
`Role.tenantId` column) with its own blast radius, and folding it into an audit slice would couple two unrelated
corrections in one diff. What this slice does change is that the escalation is now **recorded** — `role.grant` writes
an audit row with the grantor, the role slug and the target. Detection before prevention, stated rather than implied.
Owner: **`V3-E05`** (AuthZ hardening), or `S-E04-7` if it lands first.

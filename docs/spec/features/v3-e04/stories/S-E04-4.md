## 1. What is broken, measured

### 1.1 Three populations, three vocabularies, no agreement

| Population | What it puts in `audit_log.action` / `.resource_type` | Where |

| **The 54 seeded/live rows** | **French display strings** in structural columns: `Création`, `Mise à jour`, `Validation`, `Suppression`, `Export` / `Année scolaire`, `Professeur`, `Inscription`, `Résultats`, `Élève`, `Classe`, `Évaluation`, `Note` | `apps/api/prisma/seed-demo.ts:1060-1120` |

`analytics.service.ts:3314-3325` then matches a **fourth** set that straddles both vocabularies:

- `'Export'` matches the legacy rows *and* nothing else — `export.bulletin.request` does **not** contain `Export`.

### 1.2 ⚠️ The orchestrator's literal inventory undercounts the written set by **34 %** — do not trust it

The run brief lists **27** `action` codes, obtained with `grep -rhoE "action:\s*'[a-z_]+'"`. That grep is

## 2. The design

### 2.1 The new home

Create `packages/contracts/src/audit/` — a **new module**, NOT an append to `src/enums/index.ts`.
Reason (record it in ADR-037): `enums/index.ts` is a flat list of value sets with no labels and no
resolution behaviour; the audit vocabulary is a *code → French label* mapping plus classification
behaviour plus a legacy-alias table. Mixing them is how `PORTALS` came to be read as "the list of portals"
by a login DTO **and** by an audit facet — two different questions, one array (§2.4).

```
packages/contracts/src/audit/
  vocabulary.ts   — the declarations: AUDIT_RESOURCE_TYPES, AUDIT_ACTIONS, AUDIT_PORTALS,
                    AUDIT_CRITICAL_ACTIONS, AUDIT_EXPORT_ACTIONS, AUDIT_LOGIN_ACTIONS,
                    LEGACY_AUDIT_ALIASES
  labels.ts       — the resolvers: classifyAuditAction / classifyAuditResourceType /
                    classifyAuditPortal, and LEGACY_FORMAT_MARKER
  index.ts        — re-export barrel ONLY; it declares nothing of its own
```

Wire-up (both are required — one without the other breaks a consumer):
- `packages/contracts/src/index.ts` — add `export * from './audit';` (after `./enums`).
- `packages/contracts/package.json` — add an `"./audit"` entry to `exports`, **mirroring `./enums` exactly**:
  ```json
  "./audit": { "types": "./src/audit/index.ts", "default": "./dist/audit/index.js" }
  ```

### 2.2 The declaration shape — the label is attached to the code

The French label lives **with** the code, in one object literal per axis. There is no second array of codes
and no separate label map — that separation is what let 7 dead keys survive in `audit-labels.ts`.

```ts
// packages/contracts/src/audit/vocabulary.ts

/** Code → libellé français. The code is the key; there is no second list of codes. */
export const AUDIT_RESOURCE_TYPES = {
  academic_year: 'Année scolaire',
  alert_instance: 'Alerte',
  // … one entry per code the extractor reports (§3.2). See §3.1 for the measured set.
} as const satisfies Record<string, string>;

export type AuditResourceType = keyof typeof AUDIT_RESOURCE_TYPES;

export const AUDIT_ACTIONS = { /* same shape */ } as const satisfies Record<string, string>;
export type AuditAction = keyof typeof AUDIT_ACTIONS;

/**
 * FOUR portals. Separate from `PORTALS` in `enums/index.ts` ON PURPOSE — see §2.4 and ADR-037 D2.
 * Do NOT widen `PORTALS`.
 */
export const AUDIT_PORTALS = {
  admin: 'Admin',
  teacher: 'Professeur',
  parent: 'Parent',
  student: 'Élève',
} as const satisfies Record<string, string>;
```

The three KPI predicate sets are **subsets of `AUDIT_ACTIONS` keys**, typed so a typo is a compile error:

```ts
/**
 * « Modifications critiques » — a write that DESTROYS or OVERWRITES a previously
 * recorded state. Membership rule stated so a future code can be classified without
 * re-litigating; the KPI card's subtitle is « Suppressions et révisions ».
 */
export const AUDIT_CRITICAL_ACTIONS = [
  'role.delete', 'role.update',
  'academic_year.delete', 'academic_year.update',
  'import.rollback', 'import.conflict.resolve',
  'coefficient.upsert',
  'grade.flag', 'grade.unflag',
  'alert.dismiss',
  'guardianship.claim_rejected', 'guardianship.claim_withdrawn',
  'remediation.plan_closed', 'remediation.booking_cancelled',
] as const satisfies readonly AuditAction[];

export const AUDIT_EXPORT_ACTIONS = [
  'export.bulletin.request', 'export.grade_grid.request',
] as const satisfies readonly AuditAction[];

/**
 * EMPTY BY MEASUREMENT, not by omission. Zero call sites in `apps/api/src` or
 * `packages/imports-core/src` write any authentication action: authentication is
 * Keycloak's, and no audit row is written on login today. Declared as an empty set
 * — rather than left as an inline `contains: 'login'` that can only ever count 0 —
 * so the emptiness is a FACT the KPI reads and reports (DNC-09, §2.6), and so the
 * slice that instruments login has exactly one place to add its code.
 */
export const AUDIT_LOGIN_ACTIONS = [] as const satisfies readonly AuditAction[];
```

### 2.3 The legacy alias table — declared, never inlined

```ts
/**
 * The FRENCH DISPLAY STRINGS the 54 pre-V3 rows carry in structural columns.
 * These are NOT canonical vocabulary and MUST NOT be offered as write targets.
 * They exist for exactly two reasons:
 *   1. so a legacy row renders with a real French label + an explicit « format hérité » marker
 *      instead of being relabelled, bucketed or hidden (DNC-08);
 *   2. so the KPI predicates keep MATCHING the 54 real rows and do not silently drop to 0
 *      the day the canonical codes land (DNC-09).
 * The rows themselves are NEVER updated (§0 rule 1).
 */
export const LEGACY_AUDIT_ALIASES = {
  actions: {
    'Création': { label: 'Création', critical: false, export: false },
    'Mise à jour': { label: 'Mise à jour', critical: true,  export: false },
    'Validation': { label: 'Validation', critical: false, export: false },
    'Suppression': { label: 'Suppression', critical: true,  export: false },
    'Export': { label: 'Export', critical: false, export: true },
  },
  resourceTypes: {
    'Année scolaire': 'Année scolaire',
    'Professeur': 'Professeur',
    'Inscription': 'Inscription',
    'Résultats': 'Résultats',
    'Élève': 'Élève',
    'Classe': 'Classe',
    'Évaluation': 'Évaluation',
    'Note': 'Note',
  },
} as const;
```

> **Measured, and it matters:** the seed writes `'Révision'` **nowhere**, and no row contains `'delete'`
> or `'revise'`. The current `criticalChanges` predicate lists four strings of which exactly one can match.
> Do not carry the three dead strings forward — carry the alias table above, which is what the data holds.

### 2.4 Why a separate `AUDIT_PORTALS` and not a widened `PORTALS`

**Do not widen `PORTALS`.** `packages/contracts/src/dto/auth.ts:10` consumes it as
`portal: z.enum(PORTALS)` for **LOGIN**. Adding `'student'` there would silently make `student` a legal
login portal — an authz change, out of scope, and not what AC-3 asks for. Two different questions were
sharing one array; this slice separates them and ADR-037 D2 records why.

**AC-3 is satisfied by the label existing for all four** (facet option + row rendering).
**Record honestly in `PROGRESS.md`:** no writer emits `portal: 'student'` today —
`deriveAuditProvenance` (`apps/api/src/shared/audit/provenance.ts`) maps three realm roles to three
portals. **Do not fabricate a writer** to make the fourth portal "real". The vocabulary is complete;
the emission is a later slice's.

### 2.5 The resolvers — one classification, three consumers

```ts
// packages/contracts/src/audit/labels.ts

export const LEGACY_FORMAT_MARKER = 'format hérité';

export type AuditVocabulary = 'canonical' | 'legacy' | 'unknown';

export interface AuditCodeLabel {
  /** The stored value, VERBATIM. Never rewritten, never normalised. */
  readonly code: string;
  /** French label; for `unknown`, EQUAL to `code` (DNC-08 — nothing is bucketed away). */
  readonly label: string;
  readonly vocabulary: AuditVocabulary;
}

export function classifyAuditAction(code: string): AuditCodeLabel;
export function classifyAuditResourceType(code: string): AuditCodeLabel;
export function classifyAuditPortal(code: string | null): AuditCodeLabel | null;
```

Resolution order, identical for all three:
1. canonical table hit → `{ code, label: <French>, vocabulary: 'canonical' }`
2. legacy alias hit → `{ code, label: <French>, vocabulary: 'legacy' }`
3. otherwise → `{ code, label: code, vocabulary: 'unknown' }`

**Three hard properties of step 3 (DNC-08):**
- `label === code`. Not `'Inconnu'`, not `'Autre'`, not a de-underscored guess. **The raw value is what a
  governance surface must show** when the system cannot classify it.
  > This intentionally **replaces** `humanizeResourceType`'s current de-underscore-and-capitalise fallback
  > (`audit-labels.ts:55-62`). That fallback turns `some_new_code` into `Some new code`, which reads like a
  > label the system authored and is indistinguishable from a canonical one. Under the new contract the
  > **marker** carries the "we don't know this" signal, and the value stays verbatim. This is a deliberate
  > behaviour change; state it in ADR-037 D4 and in `PROGRESS.md`.
- The function **never throws** and is **never wrapped in a `try/catch` by a caller**. An unclassifiable
  code is a normal return, not an error path that can swallow a row.
- An `unknown` code is **never dropped from a facet list**. The facet is built from `distinct` DB values;
  every one of them gets an option.

`classifyAuditPortal(null)` returns `null` (the caller renders nothing — an absent portal is not `unknown`,
it is absent; `AuditTable.tsx:142` already guards on `a.portal &&`).

### 2.6 The KPI predicates — and the card that can only read 0

`apps/api/src/modules/analytics/analytics.service.ts:3310-3331`. Change **only** the predicates and the
`adminLogins` shape. Do not touch the row mapper above, the facets below, or the read path (that is
`S-E04-7`, findings PF-121/122/123 — leave them alone).

```ts
import {
  AUDIT_CRITICAL_ACTIONS, AUDIT_EXPORT_ACTIONS, AUDIT_LOGIN_ACTIONS, LEGACY_AUDIT_ALIASES,
} from '@pilotage/contracts';

// Built from the declaration — canonical codes UNION the legacy aliases flagged for that KPI.
// Both halves are sourced; neither is an inline array.
const criticalActions = [
  ...AUDIT_CRITICAL_ACTIONS,
  ...Object.entries(LEGACY_AUDIT_ALIASES.actions).filter(([, v]) => v.critical).map(([k]) => k),
];
const exportActions = [
  ...AUDIT_EXPORT_ACTIONS,
  ...Object.entries(LEGACY_AUDIT_ALIASES.actions).filter(([, v]) => v.export).map(([k]) => k),
];
```

- `criticalChanges` → `action: { in: criticalActions }`
- `sensitiveExports` → `action: { in: exportActions }` — **replaces** `contains: 'Export'`.
  A substring match over a free-text column is how `conversation.report` would one day be counted as an
  export. The alias `'Export'` is now an exact member, so the 54 rows still count (DNC-09).
- `adminLogins` → **DNC-09.** `AUDIT_LOGIN_ACTIONS` is empty, so the query would be `{ in: [] }`, which is
  a card that can only ever read 0 — the exact thing DNC-09 forbids. **Do not ship that.** Instead:
  - when `AUDIT_LOGIN_ACTIONS.length === 0`, **skip the query entirely** and return `adminLogins: null`;
  - widen the response type to `adminLogins: number | null`;
  - `apps/web/src/app/admin/audit/page.tsx:161-168` renders `value={audit.kpis.adminLogins ?? 'Non instrumenté'}`
    and the card body becomes `Aucun événement de connexion n'est journalisé` instead of `Sessions ouvertes`.
    `KpiCard`'s prop is already `value: number | string` (`packages/ui/src/components/KpiCard.tsx:52`) —
    **no `packages/ui` change is needed, and none is permitted in this slice.**
  - The `portal: 'admin'` filter in that query disappears with the query. **This is the one surviving
    `portal: 'admin'` literal that `audit-provenance-gate.spec.ts` G-2 asserts on** (`apps/api/src/shared/
    quality/audit-provenance-gate.spec.ts:298-314`: *"the only surviving `portal: 'admin'` is a `where:`
    FILTER, and there is exactly one"*). Removing it makes that assertion RED (`toHaveLength(1)` → 0).
    **You must update that case in the same diff**, to `toHaveLength(0)`, with a comment naming S-E04-4 and
    stating that the last filter literal is gone because the KPI it filtered was not instrumented. Do not
    delete the case — invert it, the way `audit-provenance-gate.spec.ts:742` inverted AC-11.

### 3.2 The extractor — the independence is the whole point

**PF-105's lesson: `A ≡ A` proves nothing.** A completeness test driven off a hand-written list is a test
of the list against itself. The extractor must read the **source** and derive the written set independently
of the declaration.

**Use the TypeScript compiler API.** A regex cannot resolve the five shapes in §1.2, and this repo already
does exactly this in two shipped gates: `apps/api/src/shared/quality/open-redirect-gate.spec.ts:4` and
`web-observability-gate.spec.ts:6` both `import * as ts from 'typescript'`. Follow that precedent.

**Algorithm**

1. **Roots** (three writer populations):
   `apps/api/src` (excluding `**/*.spec.ts` and `**/__fixtures__/**`), `packages/imports-core/src`,
   and the single file `apps/api/prisma/seed-demo.ts`.
2. Parse each file with `ts.createSourceFile(…, ts.ScriptTarget.ES2022, true)`.
3. Find every `CallExpression` whose callee text **ends with** `auditLog.create` — this covers
   `this.prisma.auditLog.create`, `prisma.auditLog.create` and `tx.auditLog.create`.
4. In its first argument's `data:` object literal, take the `action` and `resourceType` properties and
   resolve the initializer:
   - `StringLiteral` → collect it.
   - `ConditionalExpression` → collect the string literals in **both** branches (`grade.flag`/`grade.unflag`).
   - `Identifier` / `PropertyAccessExpression` → walk up to the enclosing function declaration, find the
     matching parameter, and resolve **its declared type**:
     - a `UnionType` of `LiteralType`s → collect every member (`remediation.plan_closed | …_reopened`);
     - a `TemplateLiteralType` or the bare keyword `string` → **do not guess**. Record the enclosing
       function's name and fall through to step 5.
5. **Call-site resolution** for every function recorded in step 4: find every `CallExpression` to that
   function within the same file, take the argument in the matching position, and collect its
   `StringLiteral`. This is what recovers `academic_year.update`, the five `guardianship.*`, the two
   `integration`/`import.sync` and the two `remediation.booking_*`.
6. **The seed** additionally writes from array literals (`namedAuditEntries`, `auditActions`,
   `auditResources`). Handle it by collecting `action`/`resourceType` string literals from any object
   literal in `seed-demo.ts` **that is not inside the `legacyFormatFixtureRows` declaration**, and by
   collecting the elements of the two `pick()` source arrays.

**Non-negotiable assertions on the extractor itself** (a broken extractor makes every rule below vacuous):

```ts
it('the extractor is not vacuous', () => {
  expect(WRITTEN_ACTIONS.size).toBeGreaterThanOrEqual(40);
  expect(WRITTEN_RESOURCE_TYPES.size).toBeGreaterThanOrEqual(20);
});

it('THE TRAP — no Prisma sort direction leaked in from an orderBy clause', () => {
  // analytics.service.ts:3355 / :3369 and roles.controller.ts:92 (array form).
  expect(WRITTEN_ACTIONS.has('asc')).toBe(false);
  expect(WRITTEN_ACTIONS.has('desc')).toBe(false);
  expect(WRITTEN_RESOURCE_TYPES.has('asc')).toBe(false);
  expect(WRITTEN_RESOURCE_TYPES.has('desc')).toBe(false);
});

it('the five hard shapes are actually recovered — a regex-only extractor fails this', () => {
  // If any of these is missing, the extractor regressed to the naive grep (§1.2).
  expect(WRITTEN_ACTIONS.has('grade.unflag')).toBe(true);              // ternary
  expect(WRITTEN_ACTIONS.has('remediation.plan_reopened')).toBe(true); // union param
  expect(WRITTEN_ACTIONS.has('academic_year.delete')).toBe(true);      // positional arg
  expect(WRITTEN_ACTIONS.has('guardianship.claim_approved')).toBe(true); // action: string
  expect(WRITTEN_ACTIONS.has('remediation.booking_created')).toBe(true); // template-literal type
  expect(WRITTEN_RESOURCE_TYPES.has('calendar_event')).toBe(true);     // AC-2's named miss
});
```

**Completeness, in BOTH directions, as set equality:**

```ts
it('every written code has a label (forward)', () => {
  expect([...WRITTEN_ACTIONS].filter((c) => !(c in AUDIT_ACTIONS)).sort()).toEqual([]);
});
it('every label corresponds to a written code (reverse) — no dead keys', () => {
  expect(Object.keys(AUDIT_ACTIONS).filter((c) => !WRITTEN_ACTIONS.has(c)).sort()).toEqual([]);
});
```

…and the same pair for `resourceType`. **The reverse direction is what deletes the 7 dead keys and keeps
them deleted.** Report offenders as a **sorted array in the assertion**, never as a boolean — a failing
run must name the codes.

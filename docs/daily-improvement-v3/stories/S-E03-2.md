## 1. The defect, in one paragraph

The parent portal reads "this child's grades" from **two independent projections** that share neither their `where`
clause, their permission, nor their guard. The one that backs `/parent/grades` carries a **private fourth copy** of
the student ABAC whose teacher branch is the verbatim `PF-288` fail-open that `S-E05-16` closed at the service
(`grades.controller.ts:466`: *"teachers can read any student in their school (Phase 4 simplification)"* → `return`).
A fifth site is worse — `lessons.controller.ts:367` checks **only** `roles.includes('parent')`, so every other
holder of `lessons.read`, i.e. teacher and school_admin, reads an arbitrary student's lessons with no check at all.
And when either read **fails**, the page does not say so: `safe()` returns `null`, `?? []` turns it into an empty
array, and the parent is shown the positive assertion **"Aucune note publiée"** — a school-wide claim manufactured
out of a 403.

4. **`PF-05` reproduces on today's seed by a mechanism the brief did not name.** `parent@pilotage.local` holds


## 3. Acceptance criteria

### AC-1 (G-AUTHZ, Tier A) — delete the private ABAC in `grades.controller.ts`

`assertCanReadStudent` (`:449`) is **deleted**. Both call sites — `students/:studentId/stats` (`:368`) and
`students/:studentId/grades` (`:384`) — resolve through `StudentAccessService.canAccessStudent`. The teacher branch
becomes bounded to taught students.

- Wiring: `GradesModule` gains `StudentsModule` in `imports:`. **Not** a local `providers:` copy — `ADR-071 §D1`.
  Cycle-freedom verified: `StudentsModule` is a sink.
- The pre-existing `student.findUnique` + `tenantId` check stays; it produces `404`, the ABAC produces `403`, and
  the ordering must not change (a `403` where a `404` was tells an attacker the id exists).
- `ensureForUser` must appear nowhere on the refusal path (`PF-265` / `ADR-051 §D1`).
- **RED-BEFORE, evidenced by execution.** A teacher with zero `TeachingAssignment` for the student is granted
  today. Run the spec against pre-diff code, record the failure count, restore.

### AC-2 (G-AUTHZ, Tier A) — `lessons.controller.ts` resolves through the same service

The `studentId` branch (`:365`) resolves through `StudentAccessService`, so a non-parent holder of `lessons.read`
can no longer read an arbitrary student's lessons.

- **The decision is hoisted ABOVE `this.scope.run(...)`** — `ADR-071 §D2`. The service reads on the **owner**
  connection; calling it inside the scope holds two connections for the whole interactive transaction
  (`calendar.controller.ts:273-275` states this in production) and makes a 403 abort a transaction it never needed.
- The `tx.enrollment.findMany` that follows stays **inside** the scope. It is data, not authorisation.
- `LessonsModule` gains `StudentsModule` in `imports:`.
- RED-BEFORE required, same protocol as `AC-1`.

### AC-3 (RATCHET — mandatory: this closes a CLASS)

`apps/api/src/shared/quality/student-authorisation-gate.spec.ts`. **The rule is stated over authorisation
resolution, never over `guardianship` queries** — `ADR-071 §D4` explains why the obvious rule flags eight innocents
and leaves only the three exits `R-30` forbids.

Rule: a function that, in one body, (a) reads `realm_access.roles`, (b) issues a `guardianship` read binding
`guardian: { userProfileId: … }` to the **caller's own** id, and (c) throws `ForbiddenException`, must live in the
file that **declares `canAccessStudent`**.

Required, each non-negotiable:

- inventory **derived by walk**, never a hand-typed path list;
- home recognised **by construction** — the declaring file, asserted **exactly one**;
- fixtures use a **synthetic** model name, never `guardianship` spelled out (`body-metatype-gate.spec.ts:761`);
- **anti-vacuity floor per walked root**, measured then asserted below the measurement;
- **negative control**: a fan-out fixture and an admin-listing fixture that must **PASS**;
- **no `SKIP_*` / `ALLOW_*` / `NODE_ENV`** (`DNC-10`);
- allowlist **derived**, asserted to contain **exactly** `attendance.controller.ts`, with its reason inline
  (*bounded teacher branch via `teacherOfStudentWhere`, `S-E05-5`; ordering documented at `:610-621`; conversion
  deferred, `PF-266`*).

**The brief's TS6059 warning is stale.** `apps/api/tsconfig.build.json` already sets `rootDir` and excludes
`**/*.spec.ts`; `keycloak-client-identity-gate.spec.ts:11` already imports `apps/web/src/lib/`. **No tsconfig edit.**

### AC-4 (G-TRUTH — the `PF-05` core) — a failed read is not an empty fact

`apps/web/src/app/parent/grades/page.tsx` stops rendering a failed read as `EmptyState "Aucune note publiée"`.

- **Reuse, do not invent** (`ADR-071 §D5`): `ApiResult<T>` (`api-client.ts:151`), `apiResultFromError`
  (`api-client.ts:197`), `ErrorState` (`@pilotage/ui`, `role="alert"`, already used by four `/student` pages).
- **Do not write a 61st `safe()`.** There are 60 copies with **two** different semantics — `/parent/grades:39`
  catches only `ApiError`; `/parent/dashboard:248` catches everything and guards `isNextNavigationSignal`. The
  divergence is `PF-336`; adopt the shared shape at **these two reads only** (`GUARDRAILS §5`).
- Failure on the **grades** read → `ErrorState` *"Nous n'avons pas pu charger les notes"* + retry.
- Failure on the **child-list** read (`:105`) → `ErrorState`, **not** `"Aucun enfant rattaché"`. Telling a parent
  their children are unlinked because a server 500'd is worse than the grades case.
- The `NEXT_REDIRECT` escape must survive: `api()` calls `redirect()` on 401 and `apiResultFromError` re-throws it
  **first**. A hand-rolled catch would print `NEXT_REDIRECT;replace;/parent/login` into the UI (`PF-174`).

### AC-4b (G-TRUTH) — the empty state names the child

`"Aucune note publiée"` → `"Aucune note publiée pour <Prénom Nom>"`, name taken from the already-loaded `children`
array, **no extra fetch**. A sentence with no subject is read as a claim about the school. This is `PF-335`'s fix
and the cheapest honest change in the slice.

### AC-5 (G-TRUTH) — the two projections agree, and the axes are executable

A test asserts A and B return the **same count** for the Jade Brun fixture, and names the divergence axes in a way
that goes red when one projection changes and the other does not.

**Derive, never re-type.** Two hand-kept lists is the drift that produced a 503 on four portals. Both `where`
clauses are built by one leaf module — `apps/api/src/modules/grades/published-grades.where.ts`, in the
`teaching-wall.where.ts` shape (`import type { Prisma }` and nothing else, no Nest, no service import, no module
edge, no CJS cycle). `ADR-071 §D3`:

- every optional dimension is an **explicit parameter with an explicit branch** — **never** `...(x ? { x } : {})`,
  Prisma strips `undefined` and the query **widens** (`ADR-065 §D5`). Grep the diff for that shape.
- `tenantId` and `studentId` **non-optional in the type**;
- the year dimension keeps A's `[]`-on-no-active-enrolment semantics (`analytics.service.ts:926`) as a **named**
  argument — it is a decision (`PF-329`), not a default;
- `isAbsent` and the zero-value rule are **parameters**, not constants.

**Adopting the builder in one call site and not the other is worse than adopting it in neither.**

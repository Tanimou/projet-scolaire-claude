## 1. The defect, in one paragraph

The audit (`02_Internal_Platform_Audit.md` §7, App. B.7) observed **one seeded child** simultaneously described as
*"actively enrolled in 2nde A"* by the parent dashboard and the child-detail page, and as *"no active enrolment"* /
*"no linked child"* by the children list, the « Ma famille » settings tab and the claim panel. Nothing was broken:
**each surface asks a different question and every answer is locally correct.** The server filters on
`Enrollment.status`; two client surfaces then re-filter the already-filtered result on a *different column*,
`AcademicYear.status`; the child-detail page falls back to `enrollments[0]` on a payload that carries **no status
filter at all**; and the dashboard picks `enrollments[0]` in server return order. Four derivations, one fact.
This is `DNC-01` (a KPI diverging from its ledger) reached not by a bad query but by **the absence of a canonical
one** — precisely what `ADR-041 §D4` forbids: *"Portals import the predicate; they never re-derive it."*

## 2. Measured state — verified this run (2026-08-25), do not re-derive

Prisma lives at **`apps/api/prisma/schema.prisma`**, not `packages/database`.

### The schema facts the divergence hangs on

| Fact | Citation |
|---|---|
| `Enrollment` has `tenantId`, `studentId`, `classSectionId`, `academicYearId`, `status` (default `active`). **No `schoolId`.** | `apps/api/prisma/schema.prisma:652` |
| The unique index forbids two active enrolments **per academic year** — so a pupil pre-enrolled into next year while the current row is still `active` legally has **two** active enrolments | `schema.prisma:669-670` |
| `AcademicYear.status` and `Enrollment.status` are **independent columns** | `schema.prisma:319`, `:652` |

### The four parent surfaces and the four different derivations

| # | Surface | File | Derivation it applies | Verdict on a child whose active enrolment sits in a non-`active` year |
|---|---|---|---|---|
| **P1** | Parent dashboard | `apps/web/src/app/parent/dashboard/page.tsx:267-270` | `student.enrollments[0]?.classSection`, falling back to the analytics field | **"2nde A"** |
| **P2** | Child detail | `apps/web/src/app/parent/children/[id]/page.tsx:184-185` | `enrollments.find(e => e.status === 'active') ?? enrollments[0]` | **"Inscription active"** |
| **P3** | Children list | `apps/web/src/app/parent/children/page.tsx:186` | `enrollments.find(e => e.academicYear.status === 'active')` | **"Aucune inscription active"** |
| **P4** | « Ma famille » | `apps/web/src/app/parent/settings/page.tsx:377` | identical to P3 | **"Pas d'inscription active"** |

The payloads those four read are themselves filtered three different ways:

| # | Server projection | `where` on `enrollments` | Citation |
|---|---|---|---|
| **B1** | `AnalyticsService.parentDashboard` | `{ status: 'active' }`, `orderBy: { enrolledAt: 'desc' }`, `take: 1` | `apps/api/src/modules/analytics/analytics.service.ts:889-915` |
| **B3** | `GET /students` (list) | `{ status: 'active' }` — **all** rows, no `take`, no `orderBy` | `apps/api/src/modules/students/students.controller.ts:224-225` |
| **B4** | `GET /students/:id` | **NO status filter whatsoever**, `orderBy: { enrolledAt: 'desc' }` | `apps/api/src/modules/students/students.controller.ts:272-278` |

**So P2's fallback is not a defensive nicety — it is the bug.** `B4` returns `transferred_out` / `graduated` /
`dropped` rows, `find(status==='active')` yields `undefined`, and `?? enrollments[0]` then renders a
**graduated** enrolment behind `StatusBadge label="Inscription active" tone="success"`
(`children/[id]/page.tsx:343`).

## 3. The ruling this slice implements

`ADR-041 §D2` already decided `PF-12`, and the row is quoted here so nobody re-opens it:

> **Class roster** | **Effective-dated as of today**, not "current" as a mutable attribute | *Removes the `PF-12`
> self-contradiction between child and enrollment views*

`ADR-041 §D4`: *"Definitions live in one module, not in each query. A single registry in `packages/contracts`,
each entry carrying id, definition, scope label and the predicate. Portals import the predicate; they never
re-derive it."*

**Therefore the canonical definition of an actively-enrolled child is, verbatim, what `ADR-072` must record:**

> A child is **actively enrolled** when they hold an `Enrollment` whose `status` is `active` **and** whose
> `academicYear` is the tenant's canonical active year as resolved by
> `resolveActiveAcademicYear` (`packages/contracts/src/academic-year/`, `ADR-070`). Where more than one such row
> exists, the canonical one is chosen by a **single total order stated once in the contract module** — never by
> the caller. Where none exists, the answer is **"not actively enrolled"**, and it is **never** softened by
> falling back to an arbitrary row.

Two things follow that must be stated in the ADR rather than discovered later:

1. **This changes what some surfaces display.** A child whose only enrolment is `graduated` currently reads
   "Inscription active" on the detail page; after this slice it reads honestly. `ADR-041 §D3` anticipated
   exactly this: *"Some numbers will change in the UI on the day this lands. That is the point."*
2. **`ADR-070`'s residual `PF-328` is inherited, not solved.** With no "at most one active year" DB invariant,
   the canonical year is chosen *deterministically*, not *correctly*. The enrolment contract inherits that
   limitation verbatim and **must say so in its own docblock** rather than appearing to be stronger than the
   resolver it is built on.

## 4. Acceptance criteria

### AC-1 (G-TRUTH) — one contract module, mirroring `ADR-070`'s shape

Create `packages/contracts/src/enrollment/` mirroring `packages/contracts/src/academic-year/` exactly
(`index.ts` re-exporting one implementation file; re-export from `packages/contracts/src/index.ts`).

It exports, at minimum:

- the **Prisma predicate** for "actively enrolled", parameterised by tenant and canonical academic year — so
  server queries import it instead of spelling `{ status: 'active' }` inline;
- the **total order** used to choose among several candidate rows, stated **once**;
- the **selection function** over an already-fetched array (`selectActiveEnrollment(rows, ctx)`), which is what
  the four web surfaces consume;
- a **scope label** per `ADR-041 §D3`, so the surface can say what it is showing.

The module's docblock must carry the `PF-328` inheritance from §3.2 and the `confirmed: false` posture
`ADR-041` requires of every unratified definition.

### AC-2 (G-TRUTH) — the server answers the question instead of shipping the ingredients

The parent-facing payloads carry an **explicit canonical field** (e.g. `activeEnrollment`, plus its scope
label) derived server-side through AC-1. The client must never have to choose.

**`B4` (`GET /students/:id`) keeps returning the full unfiltered enrolment history** — the detail page's
history section is a legitimate consumer and truncating it would be a regression. What changes is that the
history stops doubling as the *activity* answer: the canonical field is separate and explicit.

### AC-3 (G-TRUTH / G-PORTAL) — the four derivations are deleted, not merely aligned

`dashboard/page.tsx:267-270`, `children/[id]/page.tsx:184-185`, `children/page.tsx:186` and
`settings/page.tsx:377` all consume the AC-2 field (or AC-1's selection function). **The literal
re-derivations are removed from the source**, because a duplicated-but-currently-agreeing predicate is the
state this finding is about.

`children/page.tsx:109-124` — the children-list KPI counters use the same predicate — must be converted in
the same pass or the counter and the badges will disagree with each other, which is `PF-12` reproduced at a
smaller scale inside the fix.

### AC-4 (RATCHET — mandatory, this closes a CLASS)

A one-way gate in the `apps/api/src/shared/quality/` family (the `academic-year-resolution-gate.spec.ts` /
`student-authz-locality-gate.spec.ts` shape) making a second re-derivation **inexpressible**:

- **Parse, never grep** — `require('typescript')`, per `notification-tenant-scope-gate.spec.ts:35-41`.
- Walk roots **must include `apps/web/src`**, since three of the four offending sites live there. Note
  `apps/web` has no unit runner (`project_web_has_no_unit_test_runner`) — the gate **reads** those files as
  source text/AST from the API test tree, it does not import them, so no `rootDir`/TS6059 problem arises.
- Flag, outside the declaring module: an `enrollments`-shaped array indexed at `[0]` used as an activity
  claim; a `.find()`/`.filter()` whose predicate tests `status === 'active'` or
  `academicYear.status === 'active'` over enrolments; and a Prisma `enrollment` read whose `where` spells
  `status: 'active'` literally instead of importing AC-1's predicate.
- **Per-root vacuity floor** and `MANUAL_ALLOWLIST` shipped **empty and asserted empty**, as its siblings do.
- Use the shared `scripts/lib/walk-read.js` seam (`walk-read-gate.spec.ts`), not a private walker.

**A negative control is required**: a fixture proving the gate actually fires on a re-derivation, so a green
verdict is not vacuous.

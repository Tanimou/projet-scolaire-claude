## 1. The defect, measured on the worktree, 2026-08-28

### 1.1 The line

`apps/web/src/lib/api-client.ts:124`:

```ts

  return (await res.json()) as T;
```

## 4. Acceptance criteria

Each AC needs **executed** evidence. Where behaviour changes, red-before / green-after.

### AC-1 — ONE canonical page envelope, declared ONCE

**File** `packages/contracts/src/pagination/page-envelope.ts`, sibling of `page-window.ts`, exported through the
existing `packages/contracts/src/pagination/index.ts` (which the root barrel already re-exports —
`packages/contracts/src/index.ts:14`).

It must deliver **two faces of one contract, in one file**:

**(a) The wire parser** — a zod factory over an item schema:

```ts
export function pageEnvelope<T extends z.ZodTypeAny>(item: T) { … }
```
returning an object schema with `data: z.array(item)` and `total: z.number().int().nonnegative()`.

**(b) The server-facing TS type**, carrying the brand:

```ts
export interface PageEnvelope<T> { readonly data: readonly T[]; readonly total: ResultTotal }
```

`ResultTotal` is **imported from `./page-window`**, not redeclared. This is what keeps `total: data.length` from
compiling in a controller (`ADR-080 §D2`, mechanism inherited from `ADR-079 §D3`).

**Why two faces and not one.** A brand cannot survive `JSON.parse` — `page-window.ts` already says so in prose
(*"la marque ne survit pas au fil"*). The wire parser therefore yields a plain `number`; the brand lives
server-side, between the read and the payload, which is where the error is written. Declaring both in one file is
what stops them being two lists. **A compile-time bridge assertion must sit in the module** proving the parsed
wire type and the unbranded projection of `PageEnvelope<T>` are mutually assignable, so a later edit to one face
that forgets the other **fails to compile**.

**It must be EXTENSIBLE.** Three of the four real envelopes carry extra keys (`kpis`+`filters`;
`limit`+`offset`; `limit`+`offset`+`totals`+`coverage`). An envelope that cannot express those is an envelope
nobody adopts. `pageEnvelope(item).extend({ … })` must be the documented way, and §AC-2 governs what `.extend()`
must not silently undo.

**Purity, same bar as `page-window.ts`:** no `new Date(`, no `Date.now(`, no `process.env`, no Nest import, no
Prisma import. Testable in a bare node process, and tested there.

### AC-2 — ⚠ THE OBVIOUS WAY TO BREAK A WORKING PAGE

**This is the single highest-risk line in the slice, and it is stated first so it is designed around rather than
discovered.**

**A zod object STRIPS unknown keys by default.** Parsing the audit payload through a bare `{ data, total }`
object would **delete `kpis` and `filters` at runtime** while every type stays green — turning a slice that
exists to *prevent* a silent shape disagreement into the thing that *causes* one, on the exact page whose four
KPI cards are the reason `AuditResponse` has extra keys at all.

**Requirements:**

1. The frame **passes through or is explicitly extended — it never strips.** Choose deliberately and say which in
   the module docblock.
2. `.extend()` must be verified to **preserve** the non-stripping behaviour. Do not assume it; assert it. A zod
   `.extend()` that reset the unknown-key policy would reintroduce the hazard through the exact door AC-1 opens
   for extensibility.
3. **A test that FAILS if the parse drops a key the server sent.** Structure it as a genuine red-before /
   green-after:
   - **red-before**: parse an audit-shaped payload through a *bare* `z.object({ data, total })` and assert the
     result **does not** contain `kpis` — this is the executed demonstration that the hazard is real, not a
     hypothesis;
   - **green-after**: parse the same payload through `pageEnvelope(...)` and through
     `pageEnvelope(...).extend({ … })`, and assert **key-set equality** with the input, including a key the
     schema does not know about.
4. Key-set equality is asserted over the **whole envelope**, not over a listed set of names. A test that lists
   the keys it expects is a third hand-maintained list and would be this slice repeating its own defect.

### AC-3 — The client stops asserting

**A new, additive parsing entry point** in `apps/web/src/lib/api-client.ts` — e.g.
`apiEnvelope(schema, path, init)` — that fetches through the existing machinery and then **parses** the body
against the caller's schema instead of casting it. **`api()`'s signature does not change** for the other ~201
call sites.

Convert the **four named readers** (§1.2 rows 1–4). Their call sites, verified:

- `apps/web/src/app/admin/audit/page.tsx:261` (inside `safe(...)`)
- `apps/web/src/app/admin/exports/page.tsx:258`
- `apps/web/src/app/admin/students/page.tsx:158`
- `apps/web/src/app/admin/assignments/page.tsx:74`

**Parse failure behaviour must be decided and DOCUMENTED, and it must be all three of these:**

- **Named** — a dedicated error class (e.g. `ApiEnvelopeError`) with a stable `name`, never a bare `throw` and
  never a generic `Error`.
- **Diagnosable** — the message names **the request path and the zod issue paths** (`total`, `kpis.criticalChanges`)
  so a reader learns *which key disagreed*. It must **not** include response *values*: this platform handles
  children's data (GUARDRAILS §1), and a shape error is not a licence to log a payload.
- **Never a silent fallback.** No `?? []`, no `catch { return empty }`. A page that cannot trust its data must say
  so; an envelope quietly replaced by an empty one is DNC-08 (*"a zero rendered without having read"*).

**And it must not render as an unexplained 500.** Each of the four pages already owns an error surface — the audit
page routes through `safe(...)` to an `EmptyState`. Route the failure into **the page's existing** error path.
Inventing a new error UI is out of scope; leaving a page with no path at all is not acceptable either. State per
page, in the story's implementation notes, which existing path was used.

**⚠ PF-133 — `api-client.ts` is a SERVER module** (it imports `next/headers` and `@/auth`). A `'use client'` file
must never import a **value** from it. Verified for this slice: all four converted call sites are server
components. The schemas live in `packages/contracts` (isomorphic), so client components such as
`admin/teaching-assignments/AssignmentsManager.tsx` (`'use client'`) continue to import **types only**, which
erase. **Do not move a schema value import into a `'use client'` file.**

### AC-4 — The server side is annotated, so drift fails to COMPILE on the API too

A contract only the client checks is still one list kept by hand.

- `teaching-assignments.controller.ts:140` `async list(…)` gains a **declared return type** derived from the
  canonical envelope. The declared shape is the one the handler already returns at `:272-298` — `data`, `total`,
  `limit`, `offset`, `totals`, `coverage`. **Nothing about the returned value changes.**
- `analytics.service.ts:191` `AuditListResult` stops being an independent transcription and is **re-expressed on
  top of the canonical envelope type**, keeping `kpis` and `filters` as its extension. Its existing annotation at
  `:3788` stays. This is a **re-homing**, not an addition (§1.3).

The success test for AC-4 is negative and must be executed: **reintroduce run 94's exact defect** — rename the
server's `totals` key to `summary` — and show the API side now **fails to compile**, where in run 94 it did not.
If that experiment is only described and not run, AC-4 is not met.

### AC-5 — A ONE-WAY RATCHET, because this is a CLASS claim

**File** `apps/api/src/shared/quality/page-envelope-boundary-gate.spec.ts`.

It lives under `apps/api` because **`apps/web` has no unit-test runner at all** (only Playwright) — the house
rule for every cross-cutting gate. It **walks files from disk**; it does **not import** anything from `apps/web`,
which is what keeps it clear of the `rootDir`/TS6059 trap.

**Rules** (each frozen on the **POST-diff** tree — measure after the change, never before):

- **R1 — new hand-written envelope declarations: TOLERANCE ZERO.** A named `interface`/`type` in `apps/web/src`
  whose body carries both `data: X[]` and `total: number`. After the four conversions this is **0**. Any new one
  reddens.
- **R2 — envelopes read through a bare `api<…>` cast: DECREASING CEILING.** Inline `api<{ … data … total … }>`
  occurrences. Measured pre-diff **6**; expected post-diff **6** (this slice converts named declarations, not
  inline ones). Frozen at the number the script measures on the post-diff tree. **The class can only shrink.**
  These six are `PF-428` — **counted, never allowlisted**, the convention of
  `class-roster-size-derivation-gate.spec.ts:33-44`.
- **R3 — the canonical envelope has exactly one home.** Path equality on
  `packages/contracts/src/pagination/page-envelope.ts` — not a glob, not an exemption list — the construction
  `page-window-derivation-gate.spec.ts` uses for its R4.

**Anti-vacuity floors are mandatory.** A walker that finds nothing must go **RED**, not green. Minimum:
`filesScanned >= 300` (measured: 382), `apiCallSitesFound >= 190` (measured: 211). Freeze floors below the
measurement with a stated margin, never at it.

**A falsifiability test is mandatory.** Run the walker against an in-memory synthetic source containing a
reintroduced defect (a fresh `interface Foo { data: Bar[]; total: number }`, and a fresh inline
`api<{ data: X[]; total: number }>`) and assert it **reports both**. A ratchet nobody has watched turn red is a
ratchet nobody knows is wired up.

**The measuring script is embedded in the ratchet itself** — same construction as
`page-window-derivation-gate.spec.ts`, same reason: so the frozen number and the thing that produces it can never
drift apart (`project_paired_lists_drift`). Reproduce it verbatim in §5.6 of this story; do not paraphrase it.

**The four inclusion decisions are CODE, not prose** (the lesson of `ADR-080 §6.3`, where a prose census produced
three different denominators): (1) root = `apps/web/src` only; (2) `*.spec.*`, `*.test.*`, `*.d.ts`, `__fixtures__`
excluded; (3) the unit is one `api<…>(` call expression; (4) "envelope" = the type text carries both a `data:`
key and a `total:` key. **State each one in the file.**

## 6. Gates

**G-TRUTH** — *triggered.* This is a read-projection / response-shape seam. The same fixture must yield the same
values on every surface that shows it. The slice's whole point is that a shape disagreement becomes an **error**
instead of an em-dash. Evidence: the AC-2 key-preservation spec and the AC-4 rename experiment.

**G-PORTAL** — *triggered, and the check has been run.* Measured across `apps/web/src/app/{teacher,parent,student}`:
**97 `api<…>` call sites, and not one of them reads a `data`+`total` envelope.** Teacher and parent read
bare-list shapes (`api<{ data: Lesson[] }>`, `api<{ data: PortalCalendarEvent[] }>`) or single objects. **The
envelope class is admin-only.** The four converted readers are `/admin/audit`, `/admin/exports`,
`/admin/students`, `/admin/assignments`. **No teacher, parent or student surface reads these shapes**, and none
changes. The bare-list class is real but different, and is recorded as **PF-429** rather than fixed.

**G-DNC** — *triggered, DNC-01 especially.* `ResultTotal` is imported from `page-window.ts`, not redeclared, so
`total: data.length` continues to fail to compile on the server. **Never let a length wear a total's label**, and
never let the new parser be the place where one starts to.

**G-AUTHZ** — **NOT triggered, by design.** No guard, no `@RequiresPermission`, no DTO permission, no session
handling is touched. `api()`'s 401→redirect path is unchanged. **This slice produces no authz evidence and claims
none.**

**G-TENANT** — **NOT triggered, by design.** No `where` clause, no `tenantId` predicate, no query is touched. The
API sends exactly what it sends today. **This slice produces no tenancy evidence and claims none.**

**G-MIGRATION** — **NOT triggered.** No schema change, so no `scripts/restore-drill-baseline.json` entry is owed.

## 9. Pre-mortem — assume this shipped and broke production

1. **`/admin/audit` renders four empty KPI cards.** Cause: the envelope stripped `kpis`. → AC-2, plus the
   whole-envelope key-set equality assertion.

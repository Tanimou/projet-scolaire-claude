## 1. The defect, in one paragraph

`academic_year` is resolved **nine times, by hand, in seven files**, and the nine resolutions disagree on **four
axes**. One of them is not tenant-keyed. Four of them are not deterministic. Three different things happen when no
active year exists. One of them assumes *many* active years while eight assume *one*. On the measured data both
tenants' `active` year **ended in the past** — one by seven weeks, one by more than two years — and no code path
notices. Every downstream count that is "scoped to the active year" therefore inherits whichever of the nine
resolutions its caller happened to use, which is one measured mechanism of PF-04 (one dataset, incompatible counts
across portals) and PF-36 (teacher count variance 43/46/48, 25/26).

## 4. What to build — A. the canonical resolver

### 4.1 Where it lives, and why that is not a new architectural decision

**`packages/contracts/src/academic-year/`**, re-exported from `packages/contracts/src/index.ts`.

This was the load-bearing decision of the slice and ADR-070 must record it with the alternative that was rejected:

- **Constraint.** `apps/worker/tsconfig.json` sets `"rootDir": "./src"`. A worker file cannot import from
  `apps/api/**` without TS6059. The resolver must therefore live in a workspace package.
- **Rejected: a new `packages/academic-year` package** mirroring `@pilotage/imports-core`. It is the obvious
  answer and it is the expensive one: `infra/docker/Dockerfile.api` and `Dockerfile.worker` list every workspace
  package **by name**, twice each (a `COPY packages/<x>/package.json` line and a `RUN pnpm --filter <x> build`
  line). This repository has already been broken in production by exactly that class of omission (the
  "imports-core Dockerfile" gotcha). It would also need two `package.json` dependency edits, a lockfile change, an
  eslint config, and **two `moduleNameMapper` entries** (§4.5) — six plumbing edits, on the prod deploy path, for
  one slice.
- **Chosen: `@pilotage/contracts`.** It is already a dependency of `apps/api`, `apps/worker` **and** `apps/web`;
  it is already built in all three Dockerfiles; and it is already mapped to **source** in both jest configs. Its
  charter is not "Zod DTOs only" — `packages/contracts/src/` already contains `observability/`, `release/` and
  `security/`, none of which are DTOs. Adding `academic-year/` is a **new module in an existing home**, not a new
  home. Plumbing cost: **one line** in `src/index.ts`.
- **Hard constraint that follows.** `@pilotage/contracts` must gain **no new dependency**, and in particular must
  **not** import `@prisma/client` — `apps/web` consumes this package and a Prisma import would land in the browser
  bundle. The resolver therefore takes a **structural reader port** (§4.2), which is independently the right shape:
  framework-free, injectable, trivially testable.

### 4.2 The port

Declare the narrowest structural type the resolver needs. No `@prisma/client` import, no NestJS import.

```ts
/** The single Prisma capability this module consumes. Structural on purpose (§4.1). */
export interface AcademicYearReader {
  findMany(args: {
    where: { tenantId: string; schoolId?: string; status?: 'active' };
    orderBy: ReadonlyArray<{ startDate?: 'desc'; id?: 'desc' }>;
    select: { id: true; schoolId: true; name: true; startDate: true; endDate: true; status: true };
    take?: number;
  }): Promise<Array<{
    id: string; schoolId: string; name: string;
    startDate: Date; endDate: Date; status: string;
  }>>;
}
```

Call sites pass `this.prisma.academicYear` (or `prisma.academicYear` in the worker generator, which receives the
client through `GenerateArgs`). If Prisma's generated delegate resists assignment to this signature — its
`findMany` is generic over `select` and the overloads may not unify — the fallback is **one** narrowly-commented
`as unknown as AcademicYearReader` **at each adapter point**, never inside the resolver, and ADR-070 records that
the port was structural-with-adapter rather than structural-clean. Do **not** solve it by adding `@prisma/client`
to `contracts`.

> **Why `findMany` and not `findFirst`:** the resolver needs both the singular and the plural answer (site 7 is a
> `findMany`), and it needs to be able to *report* multiplicity (`activeCount`, §4.4) rather than have Postgres
> silently pick. One reader method serves both. `take` is used only by the fallback path.

### 4.3 The contract

```ts
export type AcademicYearAbsencePolicy =
  /** No `active` year for this scope → resolve to null. Eight of the nine sites. */
  | 'nullWhenNoActiveYear'
  /** No `active` year → fall back to the most recent year of ANY status. Site 2 only. */
  | 'mostRecentOfAnyStatus';

export interface ResolveActiveAcademicYearOptions {
  /** REQUIRED. Never optional, never inferred, never defaulted. ADR-002. */
  tenantId: string;
  /** Optional — sites 1, 8, 9 scope by tenant only when no school is given. */
  schoolId?: string;
  /** REQUIRED and INJECTED. The resolver never calls `new Date()`. */
  referenceDate: Date;
  /** REQUIRED. No default — the caller states what absence means for it. */
  onAbsent: AcademicYearAbsencePolicy;
}

export interface ResolvedAcademicYear {
  id: string;
  schoolId: string;
  name: string;
  startDate: Date;
  endDate: Date;
  status: string;
  /** true when the row came from the ANY-status fallback, not from `status = 'active'`. */
  viaFallback: boolean;
  /** startDate <= referenceDate <= endDate. */
  containsReferenceDate: boolean;
  /** endDate < referenceDate. PF-15's signal — exposed, never hidden. */
  isStale: boolean;
  /** Whole days from endDate to referenceDate when stale; 0 otherwise. */
  staleByDays: number;
  /** How many `active` rows the scope actually held. > 1 means the tie-break decided. */
  activeCount: number;
}

export async function resolveActiveAcademicYear(
  reader: AcademicYearReader,
  options: ResolveActiveAcademicYearOptions,
): Promise<ResolvedAcademicYear | null>;

/** Site 7's shape: every active year of a scope, in the same total order. */
export async function listActiveAcademicYears(
  reader: AcademicYearReader,
  options: { tenantId: string; schoolId?: string; referenceDate: Date },
): Promise<ResolvedAcademicYear[]>;
```

### 4.4 Required properties — all of them, no exceptions

1. **Always tenant-keyed.** `tenantId` is a required parameter of both functions and appears in **every** `where`
   the module builds. There is no code path that issues an academic-year query without it. This is the property
   that closes site 6.
2. **Totally ordered, therefore deterministic.** `orderBy: [{ startDate: 'desc' }, { id: 'desc' }]`. The code
   comment must say, in as many words: *`startDate desc` alone is **not** a total order — two active years sharing
   a `startDate` leave Postgres free to return either row, and two portals reading the same tenant can then
   legitimately disagree. The `id` tie-break is what makes the answer a function of the data rather than of the
   plan.*
3. **Explicit, caller-chosen fallback.** `onAbsent` is required and has no default. **State the honest count in
   the ADR:** the brief describes *three* absence meanings in the tree; two of them (`empty result`, `null`) are
   the **same resolver behaviour** — return `null` — differing only in what the caller does next. The resolver
   therefore models **two** absence policies and the third difference stays, unchanged, in the callers. Modelling
   a third identical member would be ceremony.
4. **Semantics preserved per site.** This slice removes divergence in **how** the year is resolved. It does not
   change **what** any endpoint returns for the current data. Every unavoidable behaviour change is disclosed in
   §5 and repeated in the PR body.
5. **Staleness exposed, not hidden.** `isStale` / `staleByDays` / `containsReferenceDate` / `activeCount` are
   computed on every resolution. A resolver that silently returns a two-year-old year has not closed PF-15.
   `containsReferenceDate` is *reported*, not *selected on*, in this slice — see §5, disclosure (c).
6. **Clock injected.** `referenceDate` is required; the module contains no `new Date()`, no `Date.now()`. The gate
   suite forbids nondeterministic clocks in specs, and the staleness branch is untestable otherwise.
7. **Framework-free.** No `@nestjs/*`, no `@prisma/client`, no logger. Pure function + port.

### 4.5 The jest landmine — do not skip this

`apps/api/jest.config.js` and `apps/worker/jest.config.js` both map `@pilotage/contracts` **to source**, because
`scripts/test-ratchet.js` spawns jest with `cwd: appDir` and turbo's `test → dependsOn ["^build"]` therefore never
runs; a spec importing a symbol added to `contracts` in the same commit would otherwise read `undefined` from a
`dist/` built before it. Those mappers **already exist and already cover the new module** (`'^@pilotage/contracts$'`
and `'^@pilotage/contracts/(.*)$'`). No jest config change is needed — **verify this is still true** before
assuming it, and if the module is placed anywhere else, add the mapper to **both** configs.

`packages/contracts` still has to be **built** for the running API/worker to see the new export
(`pnpm --filter @pilotage/contracts build`). That is an existing landing prerequisite, already performed by all
three Dockerfiles; it is also a precondition of the §6 probe.

### Behaviour changes that could not be avoided — disclose all three in the PR body

- **(a) Determinism on sites 2, 3, 4, 5.** They currently have **no** `orderBy`. With more than one active year
  per school the row returned is whatever the plan yields; after the change it is the newest `startDate`, ties
  broken by the greater `id`. On the measured data every school has **at most one** active year, so the observable
  result is **identical today**. The change is a strict improvement in a state that does not currently exist.
- **(b) Site 6 gains `tenantId`.** If any row has `academic_year.tenant_id` disagreeing with its school's
  `tenant_id`, site 6 would go from returning that row to returning `null`. **This must be measured, not assumed
  — it is an explicit item of the §7 probe.** If the probe finds such rows, STOP and report: that is a data
  defect, and silently changing four portals' behaviour on top of it is not acceptable.
- **(c) Nothing selects on `containsReferenceDate` in this slice.** The signal is computed and reported; no call
  site opts into "prefer the year containing today", because doing so would change what every admin dashboard
  returns **on data where both tenants' active year is in the past** — i.e. it would blank the product. Selecting
  on containment is the follow-up that needs PF-328's invariant and a data decision first.

**Who consumes `isStale` in this slice.** Two low-frequency sites only: `alerts.service.ts` (site 1) and
`alerts-evaluator.service.ts` (site 8) emit **one** structured `logger.warn` when the resolved year is stale,
naming `tenantId`, `academicYearId`, `name` and `staleByDays`. Deliberately **not** `SchoolContextService`: it runs
on essentially every authenticated request and a per-request warn is log spam, not observability. **No endpoint
response shape changes anywhere.**

## 6. What to build — C. the one-way ratchet

New spec: **`apps/api/src/shared/quality/academic-year-resolution-gate.spec.ts`**, in the house style of
`apps/api/src/shared/quality/enum-route-input-gate.spec.ts` — **read that file first**; it is the most recent and
the most explicit about every rule below.

**The rule, in one line.** *No Prisma query on the `academicYear` model may filter on `status: 'active'` outside
the canonical resolver module.*

Non-negotiable house rules, each learned the hard way in this repository:

1. **Derive the inventory by SCANNING.** Walk `apps/api/src`, `apps/worker/src` and `packages/*/src` and find
   `…academicYear.<method>({ … })` call sites in the source. **Never** hand-write a twin list of file paths —
   paired hand-maintained lists have already produced a silent drift and a 4-portal 503 in this repo
   (`memory: project_paired_lists_drift`). Use `scripts/lib/walk-read.js` (`mapWalkedFiles`, `warnSkipped`,
   `maxVanishedFor`) exactly as `enum-route-input-gate.spec.ts` does — the walk-then-read race is real under
   parallel jest and that module is the only sanctioned tolerance for it.
2. **The resolver's home is recognised BY CONSTRUCTION, never by name.** The legitimate site is *the file that
   declares `export … function resolveActiveAcademicYear`* (and its sibling `listActiveAcademicYears`), found by
   the same scan. **No allowlist.** If someone moves the module, the scan follows it; if someone deletes the
   declaration, the scan finds zero legitimate homes and the anti-vacuity floor (4) turns the gate RED.
3. **Anti-vacuity floors.** A refactor that renames or moves a directory must turn the gate **red**, never
   silently green-because-it-found-nothing. Assert at minimum:
   - files walked: `apps/api/src ≥ 240`, `apps/worker/src ≥ 60`, `packages/*/src ≥ 80` (measured today: 279 / 78 /
     110 — leave the headroom, these grow);
   - accounting identity: `classified.size + skipped.length === walkedFiles.length`;
   - `skipped.length <= walkRead.maxVanishedFor(walkedFiles.length)`;
   - **recognition floor**: the scan found `≥ 15` `academicYear.*` call sites in total (measured: 21 files carry
     at least one). Zero violations found over zero recognised sites proves nothing;
   - **exactly one** legitimate resolver home was found (not zero, not two).
4. **Negative control.** Prove the rule goes **RED** on a synthetic violating snippet — a fixture using a
   **synthetic** model/identifier that appears nowhere in the product (see `enum-route-input-gate.spec.ts`'s
   `FixtureStatus` and PF-295: a real name written into a fixture becomes the next reviewer's false grep hit).
   Feed the classifier the model name as a **parameter** so the fixture can use a synthetic one. **And a positive
   control**: the resolver's own module, fed through the same classifier, must be accepted — a matcher that is
   always-red satisfies every red case and proves nothing (run 45 / TOOL-13).
5. **No environment escape hatch.** No `SKIP_*`, no `ALLOW_*`, no `NODE_ENV` branch (DNC-10). If a `MANUAL_ALLOWLIST`
   constant exists at all it must be named, asserted **empty**, and ship empty.
6. **Name the site in the failure message**, never a count: `file:line — academicYear.<method> filters status
   'active' outside the canonical resolver`.

**Known residual, write it in the file (mirror `enum-route-input-gate.spec.ts`'s R-1 note):** `scripts/ci-gate.sh`
runs the full `test-ratchet.js api` suite only when the diff touches `GATE_MACHINERY`
(`^(scripts/|\.github/|infra/|apps/api/src/shared/quality/)`). This file is inside that prefix so it runs on **this**
PR; a future PR touching only services would take the `--skip src/shared/quality/` branch and would not execute this
ratchet. That is a real residual, recorded as such — not a hole this file can close alone.

## 7. What to build — D/E. tests, probe, ADR, docs

### D. Tests — red before, green after

Unit specs live in `apps/api/src/shared/academic-year/resolve-academic-year.spec.ts` (`packages/contracts` has no
jest runner; `apps/api` does, and already maps the package to source — §4.5). Two fakes:

- an **args-recording reader** that captures every `where`/`orderBy` it is handed, and
- an **in-memory reader** that filters and sorts *honestly* over a seeded row set.

Minimum cases:

1. **DETERMINISM** — seed **two active years for one school** (the state that does not exist in prod, which is why
   it must be seeded) and resolve twice; assert the same `id` both times **and** that it is the one the documented
   total order selects. Add the hard case: two active years with the **same `startDate`**, differing `id` — assert
   the `id` tie-break decides. `activeCount === 2`.
2. **TENANT SCOPING** — a year belonging to tenant B is never returned when resolving for tenant A, **even when its
   `schoolId` is passed**. This is the regression test for `school-context.service.ts:32`. Assert it twice: on the
   in-memory reader (behaviour) and on the args-recording reader (**every** captured `where` contains `tenantId`,
   for both exported functions, on every policy branch, including the fallback query).
3. **STALENESS** — a year whose `endDate` precedes `referenceDate` comes back with `isStale === true`,
   `containsReferenceDate === false` and a correct `staleByDays`; a year containing `referenceDate` comes back
   `isStale === false`. Use the real measured rows (`2023–2024` ending 2024-07-05 against a 2026-08-25 reference)
   so the test speaks about the actual defect. Boundary: `endDate === referenceDate` is **not** stale.
4. **FALLBACK MODES** — `'nullWhenNoActiveYear'` returns `null` when no active year exists;
   `'mostRecentOfAnyStatus'` returns the most recent row of any status with `viaFallback === true`; and when an
   active year **does** exist both policies return the same row with `viaFallback === false`.
5. **NO CLOCK** — a static assertion that the module source contains no `new Date(` / `Date.now(`.
6. **`listActiveAcademicYears`** returns every active row of the scope, in the total order, tenant-keyed.

**Red-before is mandatory and must be evidenced**, not asserted: run case 2 against the pre-slice
`school-context.service.ts` behaviour (a reader whose `where` omits `tenantId`) and show it failing, then green.

Three existing specs mock the old shape and **will** break — budget for them, they are part of the diff:
`apps/api/src/modules/analytics/analytics.service.spec.ts:475`,
`apps/api/src/modules/analytics/school-performance-drilldown.service.spec.ts:111` and `:194`. Update the mocks to
the new reader shape; **do not** weaken an assertion to make one pass.

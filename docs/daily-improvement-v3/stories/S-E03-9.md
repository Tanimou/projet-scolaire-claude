## 1. The defect, in one paragraph

A page window — "how many rows, starting where" — is parsed **nine different ways in nine files**. Eight of the nine
are hand-rolled `parseInt`/`Math.min` expressions; the ninth (`packages/contracts/src/dto/conversation.ts`) is a Zod
schema that is **already correct** and is the only one that is. The nine disagree on five defaults (20 / 50 / 100 /
200), four caps (100 / 200 / 500 / none), and — the part nobody wrote down — **three incompatible answers to bad
input**. Four of them clamp only from above, so `?limit=-5` reaches Prisma as `take: -5`, and a negative `take` in
Prisma means *take from the end, in reverse*: a caller-reachable, undocumented change to **which rows come back**.
Two of them pass a negative `offset` straight through, where Prisma raises at runtime — a 500 where a 400 belongs.
Meanwhile `GET /teaching-assignments` has no window at all: it is an unbounded `findMany` with four nested includes,
and the admin page that consumes it derives **four KPIs and one whole-set coverage claim** from the array it gets
back. Bounding that endpoint without moving those figures to the server would manufacture, for the third time in
this epic, the exact defect the routine already closed twice: a displayed count that is the length of a bounded list.

## 4. Acceptance criteria

### AC-1 — ONE canonical page-window resolver, in ONE place

> **⚠ THE PATH BELOW IS SUPERSEDED — corrected by the land pass of run 94, 2026-08-27, and left standing
> rather than rewritten because this file records what was PLANNED.** The module shipped at
> **`packages/contracts/src/pagination/page-window.ts`**, exported from `packages/contracts/src/index.ts`.
> `ADR-080 §D1` decides it explicitly, and the delivered path is the RIGHT one: the sibling pure-derivation
> contracts are `src/calendar/` (`ADR-078 §D1`), `src/school-time/` and `src/roster/` (`ADR-079`) — one
> directory per domain, not a flat `dto/`. What is stale is this story's sentence, not the implementation.
> The *argument* below is unaffected: it weighs `packages/contracts` against `apps/api/src/shared`, and that
> half was decided exactly as written.

**Home (as planned): `packages/contracts/src/dto/page-window.ts`, exported from `packages/contracts/src/dto/index.ts`.**

Justified in `ADR-080` and here, against the two candidate homes the repo already uses:

1. **It is a generalisation of an existing contracts sibling, not a new home.** The only *already-correct*
   implementation of this contract in the tree is `packages/contracts/src/dto/conversation.ts:105-108`. Moving the
   canon anywhere else would leave the correct implementation orphaned in contracts and the canon somewhere it
   cannot reach. `dto/common.ts` already hosts the cross-cutting primitives (`UuidSchema`, `PageInfoSchema`,
   `PaginatedResponse`, `ProblemDetailsSchema`) — a page window is that kind of primitive. A **new file** rather
   than an append to `common.ts` because the module carries a docblock long enough to bury `common.ts`'s other
   exports; `dto/` is already a one-concern-per-file directory (11 files).
2. **AC-1 demands zero Nest and zero Prisma dependency.** `packages/contracts` has exactly one runtime dependency,
   `zod`. `apps/api/src/shared/` is a NestJS tree; the walk-read and tenant-scope gates live there because they are
   *checks on the API*, not shared vocabulary.
3. **Both sides need it.** `apps/web` builds the query strings. A cap that lives only in `apps/api` cannot be read
   by the caller that must respect it.
4. **No new dependency edge.** `teaching-assignments.controller.ts:16` already imports from `@pilotage/contracts`.

**The contract:**

```ts
export interface PageWindowBounds { readonly default: number; readonly max: number }

/** Zod schema factory — the ONE definition. Everything else is built on it. */
export const pageWindowSchema = (bounds: PageWindowBounds) => z.object({
  limit:  z.coerce.number().int().min(1).max(bounds.max).default(bounds.default),
  offset: z.coerce.number().int().min(0).default(0),
});

/** Pure resolver: raw query -> Prisma `{ take, skip }`. Throws PageWindowError on invalid input. */
export function resolvePageWindow(raw: unknown, bounds: PageWindowBounds): { take: number; skip: number }

/** The typed failure. Carries the field messages; it is NOT a Nest exception. */
export class PageWindowError extends Error { readonly issues: ReadonlyArray<{ path: string; message: string }> }
```

Requirements, all testable without a database:

- `resolvePageWindow` is implemented **on top of** `pageWindowSchema`. There must be exactly **one** parse
  expression in the module. A second, parallel implementation is a fail.
- Clamps **below as well as above**: `limit < 1` → `PageWindowError`, **never** coerced.
- `limit = 0` → `PageWindowError` (→ HTTP 400), **never** the default.
- `offset < 0` → `PageWindowError`, never passed to Prisma.
- Non-integer, non-numeric, and `Infinity`/`NaN` inputs → `PageWindowError`. `'1e3'` must resolve to **1000** or
  400 — never silently to `1`. State which you chose in the ADR. (`z.coerce.number()` gives 1000; that is a
  deliberate, disclosed behaviour change and it is the only one in §5.4's table that is not a rejection.)
- `bounds.default` and `bounds.max` come from the **caller**. There is **no** default default and **no** default
  max in the module. 50/200/500 are product choices; ONE PARSER is the contract, not one number.
- Pure: no Nest import, no Prisma import, no `process.env`. It must be constructible in a bare `node` REPL.
- Deterministic error messages, in French, matching the house tone of the existing Zod DTO messages.

### AC-5 — the truth half (NOT optional)

> **RECONCILED (implementation).** This block was originally drafted here as
> `summary: { total, distinctTeachers, distinctClasses, assignedSubjectIds }`, while `ADR-080 §D4` ruled the same

> architecture decision, and its `subjectsWithoutTeacher` scalar is also the safer derivation (see below). The id
> list the coverage panel needs moved to `coverage.subjectIdsWithTeacher`, where it belongs by scope.

Use `prisma.teachingAssignment.groupBy({ by: ['teacherProfileId'], where, _count: true })` (or
`findMany({ where, distinct, select })` **with a `take`** — see AC-6(b): a bare `findMany` here would *add* to the
frozen census). `groupBy` is preferred precisely because it is an aggregate and does not enter the census at all.

`subjectsWithoutTeacher` is **computed server-side in one read** (`subject.count({ where: { tenantId, schoolId,
teachingAssignments: { none: where } } })`), not differenced in the browser. `ADR-080 §D4` is explicit about why:

card therefore reads `totals.subjectsWithoutTeacher` and performs no client-side set difference at all.

### AC-6 — a one-way ratchet

New file `apps/api/src/shared/quality/page-window-derivation-gate.spec.ts`, shaped after the gates already
there (`class-roster-size-derivation-gate.spec.ts` is the closest sibling: a long docblock naming each rule, a
structural detector, a decreasing cap, and a falsifiability control).

**(a) No NEW hand-rolled parse outside the canonical module.** Detector derived from the *idioms*, never from the
nine paths:

- **R1** — a `parseInt(` whose argument identifier matches `/limit|offset|page|per_?page|take|skip/i`, in any file
  under `apps/api/src` or `apps/web/src` other than the canonical module. **Zero tolerance** — the slice converts
  every measured one.
- **R2** — a `Math.min(` / `Math.max(` expression in the same statement as an identifier matching
  `/\b(take|skip|limit|offset)\b/`. **Decreasing cap**, not zero tolerance: measure the residue after conversion
  and freeze it. A cap counts residuals; it never allowlists them.
- **R3** — a `new DefaultValuePipe(` in the same `@Query(` decorator as `'limit'` or `'offset'`. Zero tolerance.
- **R4** — a `z.coerce.number()` bound to a key named `limit`/`offset` in `packages/contracts` outside
  `page-window.ts`. Zero tolerance — this is what stops the ninth shape being re-created in its own home.

The canonical module itself is excluded **by path equality on one file**, not by a glob and not by an allowlist.

**(b) The census freeze.** Count `findMany` call sites in `apps/api/src` (excluding `*.spec.ts`) that carry no
`take:` inside their own brace-matched argument object, and assert `count <= FROZEN`.

**Measure it yourself.** This story measured **156 without `take`, of 213 sites, over 174 files** on the tree it
was written against (§2.6, script in §5.6). Freeze at **the number you measure on your POST-diff tree**, and record
your PRE-diff number in the docblock as provenance. Expected post-diff: **155** — this slice bounds exactly one
site, and every new aggregate is a `groupBy`/`count`, which does not enter the census. **If your post-diff number
is 156 or higher, one of your new aggregates is a bare `findMany` — fix the aggregate, do not raise the freeze.**

This is a *strengthening* of the brief, which said "freeze at the number on the tree you start from". Freezing at
the start number leaves one unit of slack the diff has already spent; freezing post-diff makes the ratchet bite
immediately. Say so in the ADR.

**(c) Anti-vacuity floor.** The census assertion is worthless if the walker returns zero. Assert:
`filesScanned >= 150` **and** `totalFindManySites >= 200` **and** `sitesWithTake >= 40`. A detector that finds
nothing must go **red**, not green.

**(d) Falsifiability control.** For each of R1–R4, feed the detector a crafted violating string in-memory and
assert it is flagged; feed it the canonical-module source and assert it is not. Then assert the real-corpus scan
touched at least one *known* file. **Every one of these must be able to fail.** Note `PF-407`: `process.env.TZ`
reassignment is inert inside a jest worker. You have no reason to reach for it here — but the general lesson is
the point: a control that cannot go red is not a control.
